# 开发说明

更新日期：2026-11-23。本文记录技术栈、目录结构、实现入口、必须保留的行为约束、构建与验证方法、已知问题与待办。

## 项目概况

| 项目 | 当前状态与依据 |
| --- | --- |
| 用途 | 在 VS Code 中完成 Android 无线调试的二维码 / 配对码配对、设备发现、无线连接、历史配对管理与诊断。 |
| 当前版本 | `0.1.0`（`package.json`）。移植自仓库 `ADB-connect-tool` v1.3.7.0。 |
| 技术与交付 | TypeScript + VS Code Extension API（CommonJS，编译到 `out/`）；Webview 前端为原生 HTML/CSS/JS；二维码生成内置 `qrcode-generator` 1.4.4（MIT，见 `src/vendor/` 与 `THIRD-PARTY-NOTICES.md`），运行时不依赖 `node_modules`；adb 通过 `child_process.spawn` 调用 `PATH` 中的 `adb.exe`。交付形态为 VSIX。 |
| 项目目录 | Tinderbox 仓库根目录下的 `ADB-WIFI-VSCode-Extension/`（已登记在仓库根 `README.md`）。 |
| 平台 | 按 Windows 10/11 实现与验证；其它平台未验证。 |

## 实现入口

| 文件 | 当前职责 |
| --- | --- |
| `src/extension.ts` | `activate` / 命令注册（含 `adbWifi.selectAdbPath` 文件选择器）/ 状态栏 / WebviewView 注册 / 配置监听；`adbWifi.diagnose` 打开诊断文本。 |
| `src/sidebar.ts` | 两个 `WebviewViewProvider`：设备视图输出富卡片与文字操作按钮，配对视图输出三个入口按钮；CSP nonce、消息转发。 |
| `src/service.ts` | 状态机与全部业务行为。对外只暴露 `start/refreshNow/generateQr/pairWithCode/connectTo/connectGroup/disconnectGroup/unpairGroup/restartServer/diagnose/redetect/setOptions`。 |
| `src/adb/adbClient.ts` | 按配置端口注入 `-P`、解析 / 校验 adb 路径（配置 / `ADB` 环境变量 / Android SDK / PATH）、子进程环境、stdout/stderr 收集、超时 kill、配对码 stdin、版本解析。 |
| `src/adb/parse.ts` | `adb devices -l`、`adb mdns services`、`track-services`、`list-known-hosts` 的解析；按硬件序列号 / 地址合并设备。 |
| `src/adb/knownHosts.ts` | 与 C# 版同结构的 protobuf wire-format 解析；按 GUID 原子删除，保留其它记录原字节。 |
| `src/panel.ts` + `media/main.js` | `postMessage` 协议：扩展→页面 `state/toast/focus/visibility`；页面→扩展 `ready/refresh/redetect/generate-qr/pair-code/connect/connect-device/disconnect-device/unpair-device/copy/restart-server/diagnose/open-settings`。 |

## 主面板 UI 结构

- **侧边栏**：单个 WebviewView「控制台」，用 flex 纵向分三块：ADB（可折叠）、设备（不可折叠，`flex:1` 撑满剩余高度，列表内部滚动）、配对与 IP 连接（可折叠，内部三个互斥折叠模块）。ADB 与配对区域默认展开但可折叠；设备列表始终占据剩余高度。配对 / IP 地址复用主面板的分段输入与自动带入逻辑。二维码只在真正可见时自动生成：侧边栏视图可见、配对区展开且「二维码配对」模块展开；任一条件不满足就暂停，重新可见后按需生成。
- **主面板**（`src/panel.ts` + `media/`）采用左右分栏（与桌面原工具一致）：左侧「设备」列表；右侧两个同级操作 TitleBar（「配对新设备」「用 IP 连接」）各自带内容卡片，同一时间只展开一个，另一个 TitleBar 收在下方；切换用 `grid-template-rows` 过渡做上下挤压动画；右侧内容区设最小高度，避免配对被切换成内容较少的「用 IP 连接」时页面高度突然变矮；底部状态栏显示 ADB / 服务地址 / mDNS / 配对记录。

- **左侧「设备」**：按「已连接」「已配对 · 未连接」「其他设备」分组；每台设备提供连接 / 断开 / 解除配对 / 复制标识，展开可查看连接详情。设备列表同时包含当前连接与 ADB 配对记录；列表只在内容指纹变化时重建，并保留已展开的详情，避免自动刷新导致详情收起。连接详情会去掉 mDNS 后缀、合并重复信息，状态显示为「已连接 / 未连接 / 已配对 / 未授权」。
- **右侧「配对新设备」**：默认二维码（推荐）；仅当面板可见且停留在二维码页时自动生成（切到配对码、切到「用 IP 连接」或面板不可见时暂停），无需手动点击。二维码区域在可见时始终自动展示：隐藏时只暂停生成、不取消已有会话；重新可见时若上一个二维码未过期就继续展示，已过期则重新生成，过期后也持续自动续期。剩余有效期合并在「重新生成」按钮内显示，按钮固定宽度，倒计时数字变化不会引起抖动。配对码区恢复 IPv4 四段 + 端口输入（可切 IPv6），已发现的配对地址会自动带入；也支持 chip 一键填入、粘贴完整地址自动拆分。
- **右侧「用 IP 连接」TitleBar**：与「配对新设备」同级、样式统一，展开后内容直接跟在 TitleBar 下方；IPv4 分段 + 端口输入，已发现地址自动带入，并提供「使用 …」快捷项。
- **底部状态栏**：始终显示 ADB 路径 / 版本、ADB 服务地址、mDNS 与配对记录状态，不再占用主面板的操作区域。
- **响应式**：宽度不足时左右分栏自动改为上下排列（设备在上、配对与连接在下）。
- **两处二维码的可见性**：侧边栏「二维码配对」模块与主面板「配对新设备 → 二维码」共享同一二维码会话；任意一处可见就继续自动生成 / 续期，只有两处都不可见时才暂停自动生成。隐藏不取消已有二维码，重新可见时未过期就继续展示，已过期则重新生成。
- **刷新与闪烁**：历史预览只在第一次快照发送，后续刷新直接等待完整快照，避免已连接设备在「已配对 · 未连接」与「已连接」之间闪烁；二维码过期后服务端自动清理，不再维持 1 秒刷新。

界面样式全部使用 `--vscode-*` 变量以适配亮 / 暗主题，不使用内联样式（符合 Webview CSP）。主面板标题标识直接引用项目根目录 `icon.png`，由 `src/panel.ts` 转换为 Webview URI。活动栏容器与编辑器面板标签共用 `media/activitybar.svg`，图标按 VS Code 要求绘制为居中 24×24 单色 SVG；手机屏幕上半部为 Wi-Fi，下半部为 Android 机器人头像（[View Container 图标规范](https://code.visualstudio.com/api/references/contribution-points#contributesviewscontainers)）。`docs/assets/界面预览-*.png` 为用模拟状态渲染的界面示意，不是真实 VS Code 截图。前端仍然只通过 `postMessage` 与 `src/panel.ts` 通信，消息类型保持不变（`ready / refresh / redetect / generate-qr / pair-code / connect / connect-device / disconnect-device / unpair-device / copy / restart-server / diagnose / open-settings`）；`visibility` 由扩展发往前端，用于二维码按需生成。

## 必须保留的硬约束（继承自原工具）

1. **不建立连接历史。** 运行期设备地址 / 名称缓存仅内存；设备品牌 / 型号 / 厂商作为设备资料保存到 VS Code `globalState`（键 `adbWifi.deviceProfiles`），用于断开后的设备列表展示，不含连接地址。QR 服务名 / 密码只存在内存；唯一 ADB 文件写入是用户确认后的解除配对。
2. **ADB 可配置。** `adbWifi.adbPath` 留空时优先读取 `ADB` 环境变量，其次 `ANDROID_HOME` / `ANDROID_SDK_ROOT` 的 `platform-tools`，最后从 `PATH` 查找；也允许配置可执行文件或所在目录。显示实际路径与版本；找不到时提供「重新检测」。`adbWifi.serverPort` 默认 5038（避开 ADB 默认 5037 冲突）。
3. **配对与连接分区呈现。** 配对码明文输入；二维码与配对码在同一配对区切换。
4. **历史先显示、失败保留。** 先读 `adb_known_hosts.pb`，失败回退 `mdns list-known-hosts --proto-text`；两者都失败时保留本次已读取历史并报告，不得清空。
5. **按硬件身份合并设备。** 使用 `getprop ro.serialno`；不得仅按型号合并；状态必须区分已配对 / 未连接 / 已连接 / 查询失败，不使用「在线」代替连接状态。
6. **端口变化可恢复。** 优先用当前 mDNS 地址；旧地址只试一次，失败后作废并继续发现；历史设备连接 5 轮重试。
7. **ADB 服务端口可配置。** 全部命令与 mDNS 监听按 `adbWifi.serverPort` 注入 `-P`，默认 5038；子进程删除会覆盖服务地址的环境变量并设置 `ADB_USB=0`、`ADB_EMU=0`；不得修改系统环境变量。
8. **解除配对安全。** 用户确认后重新检查设备未连接；只删除目标 GUID；写临时文件 + fsync + 确认原文件未变后原子替换；确认框默认不执行。
9. **不添加后台自动连接。** 原 1.3.7.0 源码没有后台 `adb connect`；本扩展仅在配对成功后做 4 次 × 900 ms 连接确认。

## 刷新与超时策略

后台定时器每 1 秒检查一次，实际刷新由「下次允许刷新时间」控制：

| 场景 | 下次刷新 |
| --- | --- |
| 正常 | 当前时间 + `adbWifi.refreshInterval`（默认 2000 ms） |
| 二维码激活 | 约 1 秒（每个 tick） |
| `devices -l` 失败 / mDNS 失败 / `mdns check` 异常 | +8000 ms |
| 断开 / 解除配对之后 | +5000 ms |
| 手动刷新、生成二维码、重启服务后 | 立即 |

主要命令超时：`devices -l` 6000、`mdns services` 3000、`mdns check` 2500、`list-known-hosts` 3000、`pair` 20000、`connect` 12000（会话缓存地址 4000）、`disconnect` 6000、`kill-server` 6000、`start-server` 8000、设备身份 `getprop`（序列号 / 品牌 / 型号 / 厂商）2500。

## 配置项

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `adbWifi.adbPath` | 空 | adb 文件或目录；空时按 `ADB` 环境变量 → `ANDROID_HOME` / `ANDROID_SDK_ROOT` 的 `platform-tools` → `PATH` 顺序解析。 |
| `adbWifi.serverPort` | 5038 | ADB 服务端口。 |
| `adbWifi.refreshInterval` | 2000 | 正常刷新间隔（毫秒）。 |

## 构建、测试与验证

以下命令在项目根目录执行，需要 Node.js 22+。

```powershell
npm install
npm run compile        # tsc -p .  → out/
npm run watch          # 开发时增量编译
node --test out/test/parse.test.js   # 单元测试
```

- 在受限环境中 `node --test` 无法启动子进程时（`spawn EPERM`），可直接执行 `node out/test/parse.test.js`，测试在单进程内运行。
- F5 调试：`.vscode/launch.json` 使用 `extensionHost`，参数为 `--extensionDevelopmentPath=${workspaceFolder}`，预启动任务为 `npm: compile`。
- 打包：`npm run package`，会先执行 `vscode:prepublish`（编译），再用 `vsce package --no-dependencies --readme-path README.extension.md --baseContentUrl https://github.com/allnan/tinderbox/blob/main/ADB-WIFI-VSCode-Extension/ --baseImagesUrl https://raw.githubusercontent.com/allnan/tinderbox/main/ADB-WIFI-VSCode-Extension/ --out dist/` 输出 VSIX 到 `dist/`；`@vscode/vsce` 已列入 devDependencies。`--no-dependencies` 表示本扩展无运行时 npm 依赖、不探测 `node_modules`；`--readme-path` 指定打包进 VSIX 的扩展介绍页，与仓库 `README.md` 分开维护；`--baseContentUrl` 让扩展介绍页的相对链接指向仓库内本项目目录（vsce 3.x 不会自动使用 `repository.directory`）。安装 `code --install-extension .\dist\adb-wifi-wireless-0.1.0.vsix --force`。
- **每次修改后的安装（用户明确要求）**：本项目任一文件修改后，必须先运行 `npm run package`，成功后运行 `npm run install:vsix`，将最新 VSIX 安装或更新到当前 VS Code。源码、图标 / 资源、扩展清单和文档修改均适用；打包或安装失败时必须说明失败环节与实际原因，不得报告为已安装。
- VSIX 自包含（二维码库在 `out/vendor`），运行时不读取 `node_modules`。
- 构建产物只写入 `dist/`，不留在项目根目录或仓库根目录；`dist/` 已同时被 `.gitignore` 与 `.vscodeignore` 排除。
- 若运行环境禁止 `npm` / `vsce` 启动子进程，请在普通终端执行打包。

- **扩展激活与面板渲染未在真实 VS Code 中验证**：CSP、主题变量、Webview 中文与布局需要实机检查。

- **解除配对会写真实 ADB 配对文件**：测试前应备份 `%USERPROFILE%\.android\adb_known_hosts.pb`；自动化测试只用合成 protobuf 数据。
- **诊断中的 ADB 进程信息**仅含 PID + 映像名，不含完整路径（原工具含完整路径）。
- **局域网前缀**不判断默认网关，只取恰好一个 /24 网卡地址；推断错误时不会阻止手动输入。
- **Marketplace 发布待重新尝试**：用户已确认 Publisher ID `tinderbox`；Marketplace 拒绝名称 `adb-wifi-connect`，提示该名称已存在。当前选定名称为 `adb-wifi-wireless`，扩展 ID 为 `tinderbox.adb-wifi-wireless`；新名称是否可发布待再次验证。真实 VS Code 激活与手机联调仍待验证。
