# ADB 无线调试：开发说明

更新日期：2026-11-10。本文记录当前设计约束、源码入口、验证方式和待验证事项，供后续开发使用。

## 项目概况

| 项目 | 当前状态与依据 |
| --- | --- |
| 用途 | 简化 Android 系统无线调试的二维码与配对码配对、历史配对和日常设备连接管理。 |
| 当前版本 | `1.3.7.0`，见 [Program.cs](../src/Program.cs) 中的程序集版本。 |
| 技术与交付 | C#、WPF、.NET Framework 4.8；[构建脚本](../build.ps1)生成单个 `dist/ADB-Wireless.exe`，嵌入 QRCoder 1.8.1 及许可证，运行时调用 PATH 中的 ADB。 |
| 项目目录 | 仓库根目录下的 `ADB-connect-tool/`。 |

## 已确认的设计约束

- **单文件、依靠 ADB 自身数据。** 运行期设备地址与名称等缓存必须仅保留在内存；不得为本工具建立持久历史、地址、别名或配置文件及注册表项，也不得内置 ADB。仅在用户确认解除配对时，允许在 ADB 自身数据目录通过临时副本原子更新配对文件，且操作后必须清理该临时副本。源码构建所需缓存位于开发目录 `.build/`。
- **使用 PATH 中的 ADB。** 必须显示调用位置与版本，找不到时提供重新检测，不提供更换 ADB 的入口。
- **配对与连接分别提供。** 两者必须在同一页面内分区呈现，二维码与六位配对码必须在同一配对区原位切换。六位配对码必须直接显示，便于核对。
- **历史设备能主动发起连接。** 重开工具后必须显示 ADB 已配对设备，并提供连接、重连、解除配对、状态查看。按钮文案使用“连接”。
- **设备在一个列表中管理。** 同一手机的多个 ADB 连接必须按设备身份合并，不得仅按型号合并；详情保留每条连接标识，连接和断开在对应设备行内操作。状态必须区分已配对、未连接、已连接和查询失败，不得用“在线”代替连接状态。
- **减少输入和保持输入。** IPv4 分段填写，端口独立；IPv6 使用一个地址框。自动发现与网段提示必须默认工作，后台刷新不得覆盖正在编辑的地址；切换到 IPv6 后再返回时，必须恢复原 IPv4 输入。
- **与其他 ADB 软件共存。** 本工具必须使用独立端口 `5038`，重启服务时必须保留其他端口的服务与连接。
- **日常窗口布局必须协调。** 列宽、表头与内容必须对齐，状态文字必须完整，配对和连接模块必须视觉平级。当前版本四列居中，窄窗口的操作按钮上下排列。

### 维护时必须保留的行为

1. **历史先显示。** 优先只读 `.android/adb_known_hosts.pb`，按 GUID 去重；读取失败时回退到 ADB 历史命令。mDNS 超时或 ADB 查询失败必须保留本次已知历史，并报告失败；确认空记录时才清除已移除的设备。
2. **端口变化能恢复。** 连接时优先使用当前发现的地址。本次运行取得的地址仅缓存在内存；旧地址失败后必须使其失效并继续查找新端口，避免反复尝试旧端口或在刷新时丢失重连入口。
3. **独立服务覆盖全部调用。** 普通命令和后台 mDNS 监听统一使用 `-P 5038`；子进程清除会覆盖目标服务的环境变量，并禁用 USB、模拟器扫描。这些设置必须仅影响子进程，不得修改系统环境变量。当前实现保留隐式本地主机，原因见 `Adb.CreateStartInfo` 注释。
4. **配对历史与手机授权分别处理。** 解除配对必须在用户确认后重新检查设备仍未连接，只从 ADB 自己的历史文件移除所选 GUID，并保留其他记录。手机端仍可能保留电脑授权，必须在交互中说明处理范围；界面确认默认焦点必须为“取消”。

## 开发、构建与验证

以下命令必须在项目根目录执行。构建使用 .NET Framework 的 C# 编译器，首次构建会从 NuGet 下载并校验 [QRCoder 1.8.1](https://www.nuget.org/packages/QRCoder/1.8.1)。二维码库和 MIT 许可证必须按现有脚本嵌入可执行文件。

在本项目目录运行：

```powershell
./build.ps1
./tests/run-history-regression.ps1
```

构建验证输出为 `dist/ADB-Wireless.exe`；回归检查基线为 **162 项断言**，并核验现有 ADB 配对文件在验证前后的哈希一致。`.build/` 和 `dist/` 已由项目忽略规则排除。测试夹具使用虚构设备、示例 SDK 路径和文档示例网段地址。

仅检查布局时可运行 `./tests/run-history-regression.ps1 -LayoutOnly`。布局产物位于 `.build/history-regression/`。

实机隔离验证入口为：

```powershell
./tests/verify-server-isolation.ps1 -Executable dist/ADB-Wireless.exe
```

该脚本要求已有 5037 服务、5038 空闲，会启动 5038 并在发现设备时尝试连接和断开，结束时清理自己创建的服务。上述回归基线不包含实机隔离、扫码、配对码和解除配对操作；涉及这些功能的修改必须分别记录实机验证结果。

### 修改与交付要求

- 修改连接、历史、服务隔离或设备列表后，必须执行适用的回归检查，覆盖重开软件、断开后再连接、端口变化和发现失败时的行为。
- 界面修改必须检查窄、默认、宽窗口下的列对齐、按钮和完整状态文字，不得只依据编译成功判断界面符合要求。
- 历史与连接的离线回归必须使用测试配对文件和 FakeAdb；对真实配对文件的只读核验必须保持其内容不变。
- 仅在任务包含实机验证且满足脚本前置条件时，才可以运行会启停服务或连接、断开手机的实机脚本。
- 正式交付必须为单个 `dist/ADB-Wireless.exe`。文件被占用时必须如实说明，不得将其他名称的产物表述为该路径已更新。

## 待验证事项

- **mDNS 发现异常：待验证。** 发现为空或超时而直接连接成功的现象仍需复现定位。5038 隔离已实现；具体异常必须结合网络、手机广播和后台状态调查。
- **离线设备名称：当前能力有明确边界。** 纯配对历史提供 GUID；当前实现从广播补型号、设备名和序列号，本次运行已读到的名称可暂存。完全不可发现且无缓存时，列表只能使用可取得的标识。当前名称取值见 `DeviceCatalog.DisplayName` 和 `Adb.BuildKnownHosts`。
- **名称优先级优化：尚无已确认方案。** 当前按已有实现展示可取得的型号或标识；后续调整必须先明确需求与验证方式。

**AI 后续建议：** 用户要求继续处理发现问题时，先分别复现冷启动、断开后连接、手机重开无线调试三种过程；核对 5038 的服务进程、当前广播和实际连接结果，再确定修改。用户提出新功能时，先确认它是否涉及运行期数据持久化或服务隔离边界。
