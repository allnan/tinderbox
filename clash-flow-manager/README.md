# Clash Flow Manager

Windows 本机桌面工具：读取多个服务商的原始订阅，合并节点并标记来源，生成可导入 Clash Verge 的 Mihomo profile；提供策略组编辑和按时段查看流量记录。

## 当前阶段

截至 2026-11-23，本轮移除了本地线路验证，只保留 Mihomo 真实验证；订阅来源页的按钮文案改为“添加订阅”。策略组顺序弹窗铺满窗口可用高度，各列 item 从上到下紧凑排列。单来源刷新可并行执行，当前来源卡片显示独立阶段与停止操作；Clash Verge 触发批量刷新时，概览和每个来源卡片分别显示进度。流量分析的连接状态每秒更新，统计数据可手动刷新，站点明细支持右键复制网站链接。流量趋势使用 Recharts 绘制并列上传/下载柱，悬停单根柱显示对应日期、方向和流量值，提示框随柱即时更新、不飞入，点击图表不留黑色焦点框；趋势标题和统计卡片使用 SVG 图标。Windows 启动采用单实例锁，重复启动唤起现有窗口；托盘图标双击打开主界面。最近一次 `npm run typecheck`、`npm run build` 已通过；当前订阅进度调整仍需完成构建与替换验证。

## 当前功能

- 订阅来源页窗口底部固定显示可折叠的“合并订阅 / 节点分组”面板，收起时显示节点数和分组数；展开后按订阅厂商查看自动线路分组及节点数，命名风格通过独立弹窗调整。命名拼凑支持拖动中的实时让位动画，松手后保存顺序；订阅卡片布局和节点命名格式保持独立。
- 社区规则目录的每张规则卡片提供“详情”入口，可查看用途说明、来源网址和远端规则内容；查看未添加的规则只读取预览，不会勾选或保存。
- 策略组的规则集目录增加与社区规则目录一致的来源筛选，支持 blackmatrix7、ACL4SSR、MetaCubeX、Loyalsoldier 和 Sukka，并可按规则集标题和本地规则内容搜索，并与用途分类筛选组合。
- 管理多个原始 HTTP/HTTPS 订阅地址，设置服务商名称、节点前缀和地区提示；订阅卡片可独立折叠，收起时保留节点数、更新时间和套餐摘要；可拖动订阅卡片调整并保存来源顺序，策略方案中的自动地区线路按此顺序排列；单来源刷新遵循设置中的代理开关，来自不同来源的手动刷新可并行执行；批量更新可分别选择直连或代理，代理不可连接时禁用代理刷新按钮；手动刷新显示来源、处理阶段和进度，并提供“停止刷新”，中止时保留本次刷新前的数据。Clash Verge 触发批量刷新时，概览和来源卡片显示等待、当前阶段及完成进度。设置页集中管理订阅下载代理（可独立选择订阅刷新走代理或直连）、自动更新和 Mihomo 采集连接；来源编辑项有修改后才可点击“保存”。
- 刷新成功时解析服务商套餐信息：支持 `Subscription-Userinfo` 流量与到期响应头、资料标题/官网响应头，以及订阅正文中的常见剩余流量、重置日期和套餐到期公告；可识别字段显示在对应订阅卡片的套餐信息区域。
- 在本机解析支持的 Clash YAML、Base64 Clash YAML 与常见分享链接；每个订阅可分别切换服务商前缀、国旗、国家/地区和原始节点名，字段以紧凑按钮显示在订阅卡片底部。界面随应用内置 Mozilla Twemoji COLR 字体显示彩色国旗，生成名称和导出 profile 保留 Unicode 国旗字符。原始节点名已经包含相同地区时，生成名称会自动省略重复地区标签；保存格式后会直接更新本地节点和 profile。展开订阅卡片后依次显示套餐信息、订阅设置和默认折叠的“节点信息”；节点信息可切换国家/地区和“🌐 未纳入的节点”，并在同一列表对照生成节点名与订阅原名。节点数为 0 的分类不可选。地区未识别的有效代理节点仍可通过“全部可用节点”动态范围进入策略组，但不会出现在按国家/地区生成的线路中；服务商将剩余流量、到期时间或官网等信息写入有效代理节点名称时，该节点也归入“🌐 未纳入的节点”；独立解析出的套餐摘要仍显示在订阅卡片上方，不计入节点数。
- 管理多份本机策略方案；侧栏“策略方案”负责整套方案的选择、创建、置顶、启用、重命名和删除；置顶方案排在列表前面，同一组内保持原有顺序，在线模板选择与预览也在方案列表流程中完成。打开或创建方案后进入单独的可视化编辑工作区，离开到其他模块时草稿保留，侧栏底部的编辑状态可直接返回；方案列表不与策略组卡片混排；旧的策略组子页面和此前的试用可视化入口已移除。工作区用折叠卡片展示策略组；新建和设置策略组时均可直接输入或按分类选择 Emoji 作为名称前缀，创建后卡片默认折叠。用户可拖动组卡调整顺序；卡片展开后只显示组内成员，成员卡始终两列等宽，最后一项不跨列铺满。策略编辑工作区采用左右两栏：左侧列出可折叠策略组并在展开后直接查看组内成员；右侧候选通过“内置项”“策略组”“自动地区线路”三个标签切换；“内置项”只列全部可用节点及 DIRECT、REJECT、REJECT-DROP、PASS、PASS-RULE 五种内置出站，“策略组”只列用户创建的策略组，“自动地区线路”单独列自动生成组，避免重复；自动地区线路候选按订阅厂商分组，每个厂商下排列该订阅生成的全部节点线路，线路卡保留拖入策略组和打开线路设置的操作；默认显示“内置项”，六项按“全部可用节点”、DIRECT、REJECT、REJECT-DROP、PASS、PASS-RULE的顺序排列，不提供单节点候选。节点数量与组/线路成员数量分开显示，分别标为“个节点”和“个成员”；自动地区线路名称显示国旗，台湾、香港使用中国国旗。组设置、线路规则和规则集管理分别使用弹窗，单条规则与规则集分开管理；策略组引用会阻止自引用、重复加入和循环引用。地区与来源自动线路按订阅来源及识别地区动态生成，并作为本方案左侧的自动策略组卡片显示；成员随订阅刷新自动增删，切换方式和测速参数按组保存在当前方案。右侧候选中的自动组只出现在“自动地区线路”标签，不重复列入“策略组”标签。策略组基本设置集中在设置弹窗；设置页不重复列出分流明细，只提供单条网站/IP/应用规则和规则集两个管理入口，分别打开各自管理页；页面下方直接提供关键词输入框；规则集管理页始终显示全部可用规则集，当前组已引用项默认勾选，取消勾选可移除，重新勾选可将项目排到末尾。目录搜索可匹配规则集标题与本地规则内容，并可与来源及用途分类组合；标题命中高亮标题，内容命中展示对应规则行。关键词输入框一次检查当前组的自定义规则和已引用规则集的本地内容，并分别显示命中项。底部唯一按钮在有待应用变化时显示“应用并返回设置”，一次应用变化并返回，最后仍须点击“保存方案”提交。规则集按 AI、搜索开发、社交通信、影音音乐、游戏平台、云服务支付、国内服务、网络广告等用途分类浏览；MRS、未完整同步或本地缺失的规则集会标明检查范围。测速网址和间隔通过下拉预设选择，并保留方案中已有的自定义设置。线路规则仍按方案顺序交给 Mihomo。规则集维护继续位于独立的规则集库页面。模板库提供 ACL4SSR、Subconverter 和社区模板，可导入 Clash YAML 或 ACL4SSR/Subconverter INI，也可输入自定义模板地址。订阅卡片内提供默认折叠的节点信息，通过分组选择器查看全部节点或地区线路；“🌐 未纳入的节点”包括未识别地区线路和名称带订阅信息的有效代理节点，套餐摘要独立留在订阅卡片顶部；未识别地区的有效节点仍可通过“全部可用节点”动态范围进入策略组。侧栏“应用”分区中的规则集库支持从 HTTP/HTTPS 地址下载并预览，或通过表单逐条维护网站、IP 与进程规则；规则集显示可读来源文件名，缺少配置的 ACL4SSR 编号显示为“模板规则集 N”。
- 规则集库从列表打开应用内的新增或编辑弹窗。保存成功后，列表立即显示结果。新增时可从“社区规则目录”选用、填写网址下载，或手动创建；目录浏览时只显示目录，选用规则后再进入读取预览表单。目录按 AI、搜索与开发、社交与通信、影音与音乐、游戏平台、云服务与支付、国内服务、网络与广告分组，提供 blackmatrix7、ACL4SSR、MetaCubeX、Loyalsoldier 和 Sukka 五个社区来源的 87 条精选预置；本机已保存但未列入预置的这些来源规则也会按来源和用途显示，并标记为已添加。公开项目没有统一的实际使用量统计；目录以常见服务范围及项目关注度作参考，不将 GitHub Star 描述为真实用户数，也不把所有来源统一标成“开源”。在线来源的内容类型与文本/YAML/MRS 格式会在读取时自动识别，MRS 类型从文件头读取。每个规则集可填写用途说明；策略组选择器和已分配规则会展示用途、有效规则数和内容类型。在线文本/YAML 规则可分别维护远端规则、本地追加和本地屏蔽；拉取更新只替换远端列表，追加项与屏蔽项继续保留。更新间隔可选每 6 小时、12 小时、每天、每 2 天、每周或不自动更新；没有本地调整时，Mihomo 按在线间隔获取来源；启用本地调整后生成合并快照。在线规则集在列表显示上次同步时间，可逐个或批量检查远端变化并同步；批量操作只处理带有效 HTTP/HTTPS 地址的在线规则集。MRS 是二进制格式，支持在线引用与更新，但不支持逐条查看、追加或屏蔽。
- 社区规则目录和策略组规则集共用同一套用途分类，含“其他用途”兜底；未指定或不属于分类表的社区条目归入“其他用途”。目录提供两排筛选：上排按来源、下排按分类；两项筛选可组合使用，也可继续叠加搜索。
- 社区规则目录支持勾选多项批量添加；“全选当前结果”只选择当前来源、分类和搜索条件匹配的可添加规则。批量操作逐项读取并保存，显示进度与失败原因；失败项保留选择状态，可再次重试，已存在的规则集会标记并跳过。
- 全部下拉选择器使用统一的应用内菜单样式；菜单按选项宽度展开，内容未超出可视高度时不显示滚动条，超出时使用无箭头的细滚动条。菜单支持分组、禁用选项、键盘方向键、Home/End、输入首字母查找和 Escape 关闭，不再显示 Windows 原生灰色选中菜单。拖动界面时不会选中静态文字；输入框、代码和规则内容仍可选择。
- 对需要包含全部可用节点的策略组，可将右侧“内置项”中的“全部可用节点”拖入组内启用；组内先显示为一个动态范围项，展开节点明细后才列出单节点；后续订阅刷新会自动同步新增和移除的节点，不会额外创建“全部节点”策略组。点击组名与摘要区域可折叠或展开。
- 启动回环地址 profile 服务，供 Clash Verge 添加统一配置；设置页可选择刷新配置时是否同步已启用订阅，再返回最新 profile。
- 在“设置”页配置 Mihomo 控制器和流量历史采集开关；“流量分析”页采集总上传/下载和活跃连接流量，支持今天、近 7 天、近 30 天或自定义日期，查看每日趋势及站点、节点、服务商、策略组、命中规则分类，并提供“站点 × 服务商 × 节点 × 策略组 × 命中规则”组合明细。连接状态时间每秒更新；“刷新数据”按钮重新读取当前日期范围内的统计，站点及组合明细中的站点可右键复制链接。“未命中”页记录落到 `MATCH` 兜底的连接，可刷新和导出 CSV，供后续判断。控制器断开时显示连接提示，不把 0 B 当作正常采集结果。
- “流量分析”提供清空本机流量统计和未命中历史的操作，执行前需要连续确认两次；“设置”页可导出包含订阅、节点、策略方案、规则集、应用设置和流量历史的 JSON 备份，并从备份恢复。
- “导入配置”页可自定义 Clash Verge 中显示的配置名称，并通过下拉框选择一份订阅提供套餐流量信息。顶部流程导航区分待导入、待更新和已拉取；profile 内容或元数据更新后显示“待更新”，收到新请求后恢复为“已拉取”。该状态只证明配置地址被读取，不能确认 Clash Verge 已选中或启用该配置。
- 侧栏“应用”中的“线路验证”通过 Mihomo 混合端口发送真实请求，并从新增活跃连接读取实际命中规则、策略组、代理链和最终节点。
- 使用 Tauri 桌面界面，不依赖 Electron；发布方式为单个便携 `.exe`，应用数据写入 exe 同级 `userdata/`。

手动选择策略组的成员卡片在鼠标悬停时显示图钉；点击图钉可将该节点或嵌套策略组设为默认项，再点当前图钉可取消默认并恢复 Mihomo 的组内首项行为。默认成员通过 Mihomo `default-selected` 输出。自动地区线路仍在“设置”中选择默认节点；自动测速、故障切换和负载均衡按 Mihomo 的自动选择逻辑运行。

## 快速开始

展开策略组后，可拖动组内成员卡片左侧手柄调整已添加成员的顺序；顺序会保存到方案草稿，并用于生成配置。

- 顶部流程导航只出现在四个主模块：订阅来源 → 策略方案 → 导入配置 → 流量分析。节点信息默认折叠并显示在所属订阅卡片内；策略方案列表保留独立布局，打开或创建方案后进入单独的可视化策略编辑工作区；规则集库和“线路验证”位于侧栏“应用”分区。添加原始订阅并刷新节点后，在“策略方案”页创建或选择方案，再在编辑工作区顶部新建策略组；展开左侧组卡查看成员，在右侧“内置项”“策略组”或“自动地区线路”标签页中，将候选成员拖入目标组；“内置项”包含五种内置出站和“全部可用节点”动态范围，不单独添加节点。组设置和规则管理通过弹窗打开。方案切换、启用及维护均在方案列表完成。再到独立的“导入配置”页面复制 profile 地址到 Clash Verge，最后回到流量页查看 Mihomo 记录。需要确认 Mihomo 当前实际线路时，打开“线路验证”，输入目标地址并执行真实验证。Clash Verge/Mihomo 负责实际转发代理流量；本程序负责管理订阅、生成 profile 和采集统计，启用采集时需保持程序运行（关闭窗口后可留在托盘）。

策略组规则支持单条和批量添加；批量输入每行一条，按所选的网站及子域名、精确域名、域名关键词、IPv4/IPv6 网段、进程名或程序路径类型逐行校验，重复项跳过，无效行保留并说明原因。已添加规则卡片显示对应的中文类型名。

进入策略方案编辑页后，点击右上角“规则顺序”。左右两栏分别显示同一批策略组，卡片按列从上到下排列。左栏拖动只改变方案中的组显示顺序；右栏拖动只改变流量规则检查组的顺序，两边互不带动。鼠标悬停组名时，两边同名组会同时高亮；如果对应卡片滚出另一侧视口，列表会滚到该组。点击“应用顺序”会把两侧改动写入当前方案草稿，再点击右上角“保存方案”提交。组内规则顺序保持不变；命中对应规则时才会进入该策略组。所有规则均未命中时，仍按方案页黄色“未命中规则时”的 `MATCH` 去向处理，该兜底不在排序弹窗中显示。

从项目构建 Windows 可执行文件：

```powershell
npm install
npm run build
```

构建产物为 `release/ClashFlowManager.exe`。开发阶段在项目目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/replace-test-exe.ps1`，将它覆盖到桌面下的 `clash-flow-manager/ClashFlowManager.exe`；脚本校验 SHA-256 并保留同目录数据。具体约束见[开发说明](./docs/开发说明.md#临时测试包投放)。

将 exe 放到可写目录后运行。启动后在“订阅来源”添加服务商原始链接，完成策略设置后进入“导入配置”页面，把完整 profile 地址添加到 Clash Verge。运行条件、代理设置、策略导入范围及流量统计边界见[使用说明](./docs/使用说明.md)。

## 使用边界

- 应用必须保持运行（窗口关闭后会留在系统托盘），才能继续提供本机 profile 和采集流量；自动更新开启时也需保持运行。从托盘退出后这些任务停止。
- 总流量来自 Mihomo 累计计数的定时采样；站点、节点和策略分类来自每秒活跃连接采样，短于采样间隔的连接可能没有分类明细。程序启动前的流量不会补算。
- 订阅地址、节点凭据、控制器密钥及流量日志保存在本机 `userdata/`，其中 JSON 文件未加密。不要公开该目录。
- 便携 exe 需要 Windows WebView2 Runtime；exe 应放在当前用户有写权限的位置，以便旁边创建 `userdata/`。
