# 使用说明

## 1. 放置并启动

运行 `release/ClashFlowManager.exe`。程序不安装到系统目录，数据放在 exe 同级的 `userdata/`。请将 exe 放在当前用户可写的文件夹中。Windows 需要有 WebView2 Runtime。

关闭主窗口时，程序会隐藏到系统托盘并继续工作。关闭规则集弹窗会回到规则集列表。需要完全退出时，在托盘图标菜单中选择“退出程序”。程序退出后，本机 profile 服务、自动更新和流量采集都会停止；下次启动会继续使用已经保存的数据。

窗口顶部使用与应用界面配色一致的自绘标题栏；拖动标题栏空白处可移动窗口，右侧按钮用于最小化、最大化/还原和关闭到托盘。

## 2. 添加并合并原始订阅

1. 打开“订阅来源”，选择“添加来源”。应用顶部会持续显示“订阅来源 → 策略方案 → 导入配置 → 流量分析”四步入口，可直接跳转。
2. 填写服务商显示名称、节点前缀和原始订阅链接。原始链接会在来源卡片中明文显示，并独占一行；链接过长时会自动换行并扩展输入框。地区提示用于节点名未标出地区时补充标签。
3. “保存并刷新节点”会由本机读取订阅并生成带标签的节点。每张来源卡片都有独立的“刷新订阅”按钮，只刷新该服务商；该按钮遵循设置页“走代理刷新订阅”开关。概览栏提供“更新节点（直连）”和“更新节点（代理）”，分别强制直连或使用设置中的代理批量刷新所有启用来源；代理连接检测通过后才可点击代理按钮。编辑名称、前缀、地区提示、原始链接、启用状态或节点名称格式后，“保存”才会启用；保存名称格式或地区提示会即时重命名本地节点并更新 profile，不需要重新下载订阅。已暂停来源仍可单独手动刷新，暂停只影响自动刷新和批量刷新。
4. 订阅卡片左侧的拖拽手柄可调整来源顺序，松开后自动保存。策略方案左侧“自动策略组”中的线路会按订阅顺序排列；同一订阅下先显示“全部节点”，再按节点订阅内容中地区首次出现的顺序显示地区线路。
5. 节点名称格式位于订阅卡片底部原有的节点格式示例位置，以一排紧凑按钮切换服务商前缀、国旗、国家/地区和原始节点名称。原始节点名已经包含相同国家/地区时，名称会自动省略重复地区标签。“节点信息”默认折叠；展开后使用分组选择器切换全部节点、国家/地区或“🌐 未纳入的节点”，线路在同一个列表显示。未纳入节点只供查看，不进入策略组线路，订阅更新后随节点变化。若服务商把剩余流量、到期时间、官网等信息写在有效代理节点的名称中，该节点仍列在“未纳入的节点”中。
6. 在“节点信息”中选择线路分组，可对照生成节点名与订阅原名。

每张订阅来源卡片都可以独立收起。标题信息区会醒目显示“上次更新 · 2 小时前”这类相对时长；将鼠标停在时间上可查看具体日期和时间。尚未刷新过的来源会显示“尚未更新”。点击服务商标题信息区或“展开/收起”按钮都能切换，首次点击即可展开；启用开关和刷新按钮仍各自执行原操作。收起后仍显示服务商名称、启用状态、节点数、最近更新时间、套餐信息和刷新错误；重新展开后按“套餐信息 → 订阅设置 → 节点信息”的顺序显示，订阅设置使用独立分区。节点信息区域默认折叠；展开后默认查看全部节点，地区信息为空或值为“未识别”的代理节点归入“未纳入的节点”；节点数为 0 的分类不可选。未纳入节点只供查看，不进入策略组线路；选择线路分组后，组内节点按名称自然排序，编号按数字顺序显示，并同时列出生成后的节点名和订阅原名。

订阅来源、策略方案、策略组和规则集的删除按钮支持快捷操作：普通点击显示确认框；按住 Shift 点击直接执行删除并跳过确认框。此操作只跳过确认框，不会解除当前启用方案或规则集引用等业务限制。

刷新成功后，程序优先读取 `Subscription-Userinfo` 中的上传、下载、总量和到期时间，也会读取资料标题/官网响应头，以及订阅内容里常见的“剩余流量”“下次重置”“套餐到期”“官方发布页”公告。识别到的套餐字段显示在对应订阅卡片顶部的套餐信息区域；服务商没有返回或文案无法识别的字段不会显示。有已用流量和有效总量时，“已用 / 总量”显示为用量进度条，条上保留两个数值。服务商若另外提供名称包含这些信息的有效代理节点，该节点仍计入节点总数并列在“未纳入的节点”中；套餐摘要与节点列表分别显示。流量计数是服务商数据，不等同于本程序采集的 Mihomo 流量统计。

当前订阅响应支持 Clash YAML 的 `proxies` 列表、Base64 编码的 Clash YAML、以及常见 Base64 分享链接。分享链接解析支持 VMess、SS、SSR、Trojan、VLESS、Hysteria2/Hy2、TUIC 与 SOCKS。HTTP(S) 网页链接不会当成节点分享链接；HTTP 代理节点请使用 Clash YAML。服务商如果返回“客户端不支持”“请更换代理软件”等说明内容，应用会显示兼容性错误，不会将这些文字保存为节点。若订阅格式仍无法识别，错误会显示响应类型、字节数和正文类别，不会显示订阅正文或令牌；请据此在服务商后台选择 Clash Verge、Clash Meta 或 Mihomo 兼容格式。

订阅由本机进程下载，并发送 Clash Verge 格式的客户端标识，以便服务商按客户端类型返回对应订阅内容。在侧栏打开“设置”，进入“订阅刷新”卡片，可选择 HTTP、HTTPS、SOCKS5、SOCKS5H 或直连，并分别填写 IP 地址和端口；IP 地址留空时保存为 `127.0.0.1`。默认代理地址为 `http://127.0.0.1:7897`。“走代理刷新订阅”控制来源卡片单独刷新和自动订阅刷新是否使用该代理；关闭时直连。概览栏的批量刷新按钮可单次指定直连或代理，代理按钮会在检测到配置的代理服务器端口可连接时启用。代理配置仍用于模板下载和在线规则预览。程序不会把原始订阅地址提交给策略模板网站。

## 3. 导入 Clash Verge 配置

完成来源和策略设置后，打开单独的“导入配置”页面。页面会显示完整本机 profile 地址，例如 `http://127.0.0.1:39127/profile/<随机令牌>.yaml`；地址会完整换行显示。复制后，在 Clash Verge 添加远程配置并粘贴；刷新配置、确认节点和策略组出现后，再在 Clash Verge 选中该配置。该服务仅绑定 `127.0.0.1`，需要 Clash Flow Manager 保持运行。

在此页可设置 Clash Verge 中显示的配置名称并保存，也可从“在 Clash Verge 显示订阅流量”下拉框选择一份订阅；最多选择一份。选中的订阅套餐信息会显示在此页，并通过订阅响应头提供给 Clash Verge。选择“不显示”后不再提供订阅流量信息。

顶部“导入配置”步骤会区分三种状态：从未拉取时显示“待导入”；已有拉取记录且配置内容或元数据更新后显示“待更新”；新配置地址再次被请求后显示“已拉取”和最近请求时间。该状态表示有客户端读取过配置地址，不能确认配置是否已在 Clash Verge 中选中或启用。Mihomo 控制器状态也不包含 Clash Verge 当前选择的 profile 信息。

生成配置使用“设置”页左侧“流量采集连接”卡片中的混合端口、控制器地址和密钥。控制器密钥在设置页明文显示，便于核对。导入后，确认 Clash Verge 正在运行 Mihomo，并能通过该控制器地址访问 `/version` 与 `/connections`。如果 Clash Verge 当前端口不同，请在侧栏打开“设置”，调整并保存后重新加载 profile。

“设置”页右侧“订阅刷新”卡片中的“自动更新订阅”开关控制定时刷新。开启时，程序启动 12 秒后刷新已启用的来源，后续按设定间隔刷新，间隔范围为 15 到 1440 分钟；网络连接错误会在单次下载内短暂重试，自动刷新仍报错时会在 15 秒后再自动同步一次。旧配置默认保持开启。关闭后不会在启动或定时器到期时自动刷新，订阅来源页面概览栏的“更新节点”和来源卡片操作仍可手动刷新。节点刷新失败时会保留上次成功的节点，并在来源卡片显示具体的连接错误或超时类别。若错误提示返回网页内容，请检查服务商链接是否为原始订阅地址，以及服务商登录或订阅状态。

## 4. 配置策略方案与策略组

展开策略组后，组内成员卡片左侧的拖拽手柄用于调整已添加成员顺序；松开卡片后，新顺序会保存在方案草稿中，并用于生成配置。

侧栏“策略方案”只管理整套方案。方案列表支持置顶、创建、编辑、启用、重命名和删除；置顶方案排在列表前面，同一组内保持原有顺序；打开或创建方案后，会进入独立的“方案编辑”工作区。策略组卡片不会混进方案列表，工作区内也没有单独的“策略组 / 分流规则”页签。

方案编辑器以 Clash Verge 代理组视图呈现策略组之间的线路关系。卡片默认折叠；点击组名与摘要区域可折叠或展开，拖拽柄、折叠箭头、设置和删除按钮各自执行独立操作。点击“新建策略组”后，只需在弹窗填写组名；新卡片默认没有成员。需要手动切换组包含全部节点时，将右侧“全部节点”栏中的“全部可用节点”拖入该组一次，后续订阅刷新会自动同步新增和移除的节点。

策略组的规则集目录按“全部来源”、blackmatrix7、ACL4SSR、MetaCubeX、Loyalsoldier 和 Sukka筛选规则集。来源筛选与用途分类可以组合；搜索同时匹配规则集标题和本地可读规则文本，不搜索说明。

- 展开组卡后直接管理线路成员，不会在卡片里铺开切换方式或规则表单。“全部可用节点”在组内显示为一个动态范围项；点击“查看节点明细”才显示单节点列表。左侧拖柄用于调整策略组顺序；点击“设置”打开当前组的设置弹窗，可改名、选择手动选择/自动测速/故障切换/负载均衡，并用下拉菜单选择测速网址和间隔。设置页提供“网站 / IP / 应用规则”和“规则集”两个管理入口，分别打开自己的管理弹窗；页面下方直接提供关键词输入框，不需要跳转页面。规则集目录始终显示全部可用规则集，当前组已引用项默认勾选；取消勾选可移除，重新勾选可将项目排到末尾。目录搜索匹配规则集标题或本地可读规则文本，可与来源和用途分类组合；标题命中会高亮标题，内容命中展示最多三条规则并标明所属规则集。策略组设置页的关键词输入框同时搜索当前组的自定义规则条件和已引用规则集本地内容，并分别显示命中项；MRS、尚未完整同步或本地库缺失的规则集会提示结果覆盖不完整。规则集来源和内容仍在独立的规则集库页面维护。
- 编辑工作区采用左右两栏：左侧列出可折叠策略组，展开后直接查看组内引用和节点范围；右侧通过“内置项”“策略组”“自动地区线路”三个标签切换，默认打开“内置项”；“内置项”包含全部可用节点和内置出站，“策略组”只显示用户创建的策略组，“自动地区线路”只显示自动生成组，自动组不会在两个候选分类中重复出现。内置项共 6 项，按“全部可用节点”、DIRECT（直连）、REJECT（拦截）、REJECT-DROP（静默拦截）、PASS（跳过规则分支）、PASS-RULE（在子规则内跳过当前规则）的顺序排列；COMPATIBLE 是 Mihomo 在策略组筛选无节点时出现的自动回退，等效 DIRECT，不单独列为候选。
- 将右侧“策略组”或“自动地区线路”标签里的候选，或“全部可用节点”，拖到左侧目标组即可引用。拖入“全部可用节点”后，该组会包含当前所有解析成功的节点，并在订阅刷新后自动纳入新增节点、移除已消失节点。组内先显示一个范围项，打开“查看节点明细”后才显示节点，不会创建额外的“全部节点”策略组。自动地区线路按订阅来源 ID 与已识别地区聚合，并作为左侧独立的自动策略组卡片加入方案；展开卡片可查看当前成员，成员会随订阅刷新自动增加、移除或换入新节点。自动组可单独设置手动选择、自动测速、故障切换或负载均衡，并设置测速网址与间隔；设置保存在当前策略方案。右侧候选中，自动组只在“自动地区线路”标签显示，不会重复列入“策略组”标签。地区未识别的有效节点仍包含在“全部可用节点”范围和来源级全部节点线路中。已有方案里的单节点成员会继续保留并可移除，界面不再提供新增单节点的入口。组内成员右侧的“×”可移除成员；普通点击会要求确认，按住 Shift 点击直接移除。
- 候选策略组会阻止自引用、重复加入和循环引用；策略组名称、切换方式、测速设置与分流入口在组设置弹窗中维护，单条规则和规则集由两个独立入口分别打开管理弹窗。
- 网站/IP/应用规则弹窗支持单条和批量添加；批量模式下选择一种规则类型，并在文本框中每行输入一项，空行会忽略，已存在或本次重复项会跳过，无效行会保留并显示行号与原因。规则集弹窗只管理规则集，不在同一页里切换类型。选择规则类型后示例和说明会对应切换：网站及子域名、单个域名、域名关键词、IPv4/IPv6 网段、应用进程名或完整程序路径；已添加规则卡片显示对应的中文类型名。规则集页按用途分类浏览并支持多选添加；已分配项目显示在对应弹窗内，规则行可拖动调整同类型条目的本组匹配顺序。勾选变化后，点击弹窗底部唯一的“应用并返回设置”按钮即可应用到当前方案草稿并返回；无待应用变化时按钮显示“返回设置”。规则集来源与维护仍由独立的“规则集库”页面管理。
- 在侧栏“规则集库”选择“新增规则集”并进入“社区规则”后，上排按维护来源筛选，下排按用途分类筛选；分类与策略组规则集一致，包括用于未分类条目的“其他用途”。来源、分类可以组合，也可以再使用搜索框缩小结果。每张目录卡片的“详情”按钮可查看用途说明、来源网址和远端规则；未保存的条目会读取远端内容，查看不会勾选或保存规则集。
- 社区目录卡片左侧的勾选按钮可选择多项；“全选当前结果”按当前来源、分类和搜索结果选择可添加项，选择状态会在切换筛选时保留。点击“批量添加”后，程序逐条读取并保存，显示当前进度、成功、跳过和失败原因；已添加或同名的规则集会跳过，失败项继续勾选，可重新批量添加。
- 规则集库顶部的“全部检查更新”会检查所有在线规则集的远端内容；“同步更新全部”会拉取并应用所有在线规则集的内容，同时保留每个规则集的本地追加与屏蔽项。手动规则集不参与这两项批量操作；操作期间会显示完成进度，单个失败不会阻止其余规则集继续处理。
- 策略组不能包含自身，也不能通过多层引用形成循环；界面会阻止这类成员加入。组名在设置弹窗中修改后，会同步更新引用该组的规则和其他组线路。
- 卡片底部的“未命中规则时”控制最后一条 MATCH 规则的去向，默认是 DIRECT。没有 MATCH 规则时，选择目标会创建一条 MATCH 规则。无策略组的空白方案仍以 DIRECT 作为生成配置的兜底去向。
- 修改方案组名时，指向该组的分流规则和其他组中的同名线路引用会同步更新。删除策略组会同时删除目标为该组的规则及其他组里对该组的引用；普通点击会确认，按住 Shift 点击直接删除。
- 顶部“保存方案”写入方案库但不会启用其他方案；“放弃修改”回退到已保存内容；编辑中离开到其他模块时，草稿保留在本机内存；侧栏底部显示“编辑状态”和方案名称，点击即可回到同一份草稿。从其他模块点侧栏或顶部流程里的“策略方案”也会直接返回正在编辑的方案。“返回方案列表”在编辑器内存在未保存修改时会确认；选择“取消”留在编辑器。保存当前正在使用的方案会原位更新该方案，并同步更新当前 profile；保存其他方案不会改变当前启用方案。要让未启用方案作用于 Clash Verge，需在方案列表单独启用，再刷新 Clash Verge 中的 profile。

创建空白方案时不自动启用。在线模板依旧从策略方案列表的模板入口选择和预览；读入后会保存为新方案并进入同一套可视化编辑器。四步导航固定在主窗口顶部；方案编辑的返回、放弃、保存和新建策略组操作也在顶部栏。运行状态统一显示在左下角侧栏。

Clash YAML 导入主要读取 `proxy-groups`、`rules` 和 `rule-providers`。节点名会按订阅来源重新标记；组内显式引用的原节点名会尝试映射到当前订阅节点。ACL4SSR/Subconverter INI 导入读取常见的 `custom_proxy_group`、`ruleset` 与 `rule` 行；ACL4SSR 本地版相对规则路径会映射到 ACL4SSR GitHub 规则文件。不同模板的语法和自定义扩展并不完全一致，导入后请在编辑器核对策略组、线路与规则，再到 Clash Verge 确认 profile 加载结果。

应用生成 Mihomo profile，不会直接修改 Clash Verge 中正在运行的配置。启用方案后，回到 Clash Verge 刷新该远程配置，再选择对应策略组。切换查看或保存方案不会影响 Clash Verge，直到单独执行“启用方案”。
手动选择策略组展开后，将鼠标悬停在组内节点或嵌套策略组卡片上，点击出现的图钉即可设为默认成员；当前默认成员的图钉会保持显示。再次点击该图钉会取消默认，恢复 Mihomo 的组内首项行为。自动地区线路可在“设置”中选择默认节点。订阅刷新后，如果默认节点暂时不在当前成员中，Mihomo 会退回组内首项；节点恢复后，该默认名称仍可再次匹配。自动测速、故障切换和负载均衡由 Mihomo 自动决定当前成员，不使用此默认值。

## 5. 查看流量

“流量分析”可直接切换今天、近 7 天、近 30 天，也可选择“自定义”输入起止日期。页面展示总上传、总下载、总流量、日均流量和每日趋势。默认的“组合明细”把站点、服务商、节点、策略组、命中规则以及上传、下载、合计放在同一行；其他标签可分别按站点、节点、服务商、策略组或命中规则汇总。点击“清空统计”会删除本机全部日期的流量统计和未命中记录，程序会连续要求确认两次；清空后当前页面数据会立即刷新。

连接状态显示“无法连接”时，页面不会以 0 B 假装采集正常。点击侧栏“设置”，核对 Mihomo 是否已运行，以及左侧“流量采集连接”中的 external-controller 地址、端口和密钥是否一致；点击“测试连接”确认。历史记录仍可查询，但断开期间不会新增流量。流量历史采集开关也在这张卡片里；关闭后会暂停新增记录，已有记录保留。

总计来自 Mihomo `/connections` 返回的累计计数，程序每秒采集一次并记录增量。组合明细来自同一响应中的活跃连接快照，按站点、来源、节点、策略组和规则聚合；域名不可见时按 IP 或“未知站点”归类。短时连接可能在两次快照之间结束，因此分类明细会少于总计，页面上方总量与组合明细的合计可能不同。程序刚启动或恢复采集后的首个连接快照用于建立基线；程序退出或控制器断开期间不会新增记录，程序运行前的流量也不在本机历史中。

“未命中”页记录 Mihomo 判定到 `MATCH` 兜底规则的活跃连接，这表示流量落到了规则列表的最终兜底项。列表按当前日期范围筛选，可手动刷新，并导出 CSV 收集判断。记录包含发现时间、站点、目标和来源 IP/端口、网络、应用及路径、入站、兜底去向和代理链；数据仅写入本机 `userdata/unmatched-YYYY-MM-DD.jsonl`。此功能受“启用流量历史采集”开关控制，按秒读取连接快照，因此短于采样间隔的连接可能没有被记录。

## 6. 验证链接去向

在侧栏“应用”打开“线路验证”，可切换两种方式：

- **本地验证**：选择一份本机已保存的策略方案，选择 `https://` 或 `http://` 协议，再输入域名、IP 地址和可选路径。若输入的地址自带 HTTP/HTTPS 协议，则按地址中的协议推演，并忽略协议选择框。程序按方案中规则的先后顺序匹配 URL 域名和端口，并读取本机保存的规则集内容，显示命中规则、目标去向、策略组方式和组内配置成员。进程名或路径条件按 Clash Flow Manager 当前运行进程匹配。此方式读取本机方案数据，不连接 Mihomo，也不向目标网站发请求。它显示策略组及其候选成员；自动选择组当前实际选中的节点由 Mihomo 状态决定。
- **Mihomo 真实验证**：选择 `https://` 或 `http://` 协议，再输入域名、IP 地址和可选路径。若输入的地址自带 HTTP/HTTPS 协议，则按地址中的协议发起真实验证，并忽略协议选择框。程序通过设置中已保存的 Mihomo 混合端口发出带 `Range: bytes=0-0` 的 GET 请求，同时读取 Mihomo `/connections` 中新出现的活动连接，并显示实际命中规则、策略组、代理链、最终节点、HTTP 状态码和请求耗时。请求由 Clash Flow Manager 进程发起；若配置了按进程名分流，结果反映本程序的进程名。

本地验证遇到前置规则需要 DNS 结果、GeoIP/GeoSite 数据、未下载或 MRS 规则集、正则表达式或本地暂不支持的条件时，会停止推演并标注无法判断，不会把后续规则显示为确定命中。Mihomo 真实验证不会跟随 HTTP 重定向，也不会读取响应正文。若活动连接在接口捕获前已经结束，页面会显示“未捕获连接”，可再次尝试。若请求失败，请核对 Mihomo 是否运行、控制器地址/密钥和混合端口是否与当前配置一致。

每天的流量日志写入 `userdata/traffic-YYYY-MM-DD.jsonl`。清空统计会永久删除所有 `traffic-*.jsonl` 和 `unmatched-*.jsonl` 历史文件。

## 7. 本地数据与隐私

`userdata/` 主要包含：

- `sources.json`、`nodes.json`：订阅地址、节点名称和代理凭据。
- `policy.json`、`policy-library.json`、`rule-set-library.json`、`settings.json`：当前使用策略、多份本机方案、共享规则集库、代理地址、控制器设置与密钥。
- `generated-profile.yaml`：给 Clash Verge 使用的合并配置。
- `profile-token.txt`：本机 profile 服务路径令牌。
- `traffic-YYYY-MM-DD.jsonl`：每日流量增量记录。
- `unmatched-YYYY-MM-DD.jsonl`：每日日志，记录落到 `MATCH` 兜底的连接；可从流量分析页导出 CSV。

本地 JSON/YAML/JSONL 文件没有加密；备份或迁移时按敏感网络资料处理。换位置时应将 exe 和整个 `userdata/` 一起移动。

在“设置 → 数据位置与备份恢复”中可导出完整 JSON 备份，或选择备份文件恢复。备份包含订阅地址与节点凭据、策略方案、规则集、应用设置和所有流量历史；备份文件未加密，须妥善保管。恢复会覆盖上述本机数据，程序会显示两次确认；本机 profile 服务端口和随机访问令牌保留当前运行值。
