# 开发说明

## 技术与入口

- 桌面容器：Tauri 2 / Rust，配置位于 `src-tauri/tauri.conf.json`；不使用 Electron。
- Windows 启动必须在创建应用状态、后台任务和托盘之前取得命名 Mutex `Local\Tinderbox.ClashFlowManager.SingleInstance`；同一用户会话的后续启动必须唤起标题为“Clash 订阅与流量管理”的既有窗口并立即退出。Mutex 句柄必须保留到应用退出，避免并发启动两套后台采集、订阅刷新和 profile 服务。托盘图标双击和菜单“打开主界面”必须共用唤起逻辑，确保主窗口可见、恢复并取得焦点。
- 前端：React 19、TypeScript、Rollup、Recharts 3；入口是 `src/main.tsx`，界面在 `src/App.tsx`，策略可视化工作区在 `src/PolicyVisualWorkspace.tsx`，统一下拉组件在 `src/components/DropdownSelect.tsx`，样式在 `src/styles.css`，在线策略模板目录在 `src/core/presetCatalog.ts`，IPC 类型和调用在 `src/core/bridge.ts`。每日流量趋势使用 Recharts `BarChart` 和 `Tooltip`，Tooltip 按单根柱显示对应日期、上传/下载方向与流量值；悬停位置即时更新，不播放位移动画，点击图表不显示焦点黑框。
- 应用图标唯一基准为项目根目录 `icon.png`。前端标题栏与侧栏品牌标识直接显示 `dist/icon.png`；`prepare-dist.mjs` 必须把根目录图标复制到该路径。运行 `npm run generate:icons` 可从根目录图标生成 `src-tauri/icons/` 的平台资源。Windows 可执行文件和托盘共用 `src-tauri/icons/icon.ico`；`src-tauri/build.rs` 监视该 ICO，修改后重新构建会更新 exe 图标与托盘图像。
- Rust 模块：`conversion.rs` 解析订阅并标记节点；`presets.rs` 读取 Clash YAML/ACL4SSR INI 的策略；`policy.rs` 生成 Mihomo YAML；`server.rs` 在 loopback 提供 profile；`traffic.rs` 采集并按单一维度、组合明细及日趋势汇总，按 `/connections.chains` 首项记录最终出站（节点）、末项记录入口策略组，也将 `rule` 为 `MATCH` 的连接按 ID 去重后写入逐日未命中日志；旧流量记录按旧字段顺序在读取时纠正映射，不改写原始历史文件；`route_check.rs` 经 Mihomo 混合端口发起链接请求，并通过 `/connections` 的新活动连接读取实际命中规则与代理链；`paths.rs` 将运行数据定位到 exe 同级目录；`single_instance.rs` 在 Windows 进程启动前取得命名 Mutex 并处理重复启动。`state.rs` 迁移并维护本机策略库。
- 国旗显示使用随应用打包的 Mozilla Twemoji COLR 字体 `src/assets/fonts/TwemojiMozilla.ttf`。`@font-face` 仅为区域指示符字符声明该字体，界面中的旗帜序列会组合成彩色国旗；其他文本和 Emoji 继续使用系统/应用字体。前端构建必须将字体复制到 `dist/assets/fonts/`。原始 Unicode 旗帜字符继续用于线路名和导出的 Mihomo 配置。字体项目代码按 Apache-2.0 许可，Twemoji 图案按 CC-BY-4.0 许可；来源：https://github.com/mozilla/twemoji-colr 。

## 已确认的实现约束

- 自动地区线路命名使用全局设置 `AppSettings.auto_group_name_parts`，不属于单个订阅来源，也不改变订阅卡片或节点名称。订阅来源页窗口底部必须固定可折叠面板，默认收起并显示“合并订阅 / 节点分组”、节点数和分组数；展开后仅显示当前自动线路分组及节点数，并按订阅厂商分区。命名风格必须通过独立弹窗调整。命名模板由订阅厂商、地区/全部节点标识和一个分隔符组成；前端可拖动调整厂商与线路标识顺序、替换分隔符，后端必须校验必需元素和唯一性。拖动命名元素时必须显示跟随指针的拖动项，并在悬停目标变化时通过 FLIP 位移动画让其他元素实时挤压换位；拖入候选分隔符时，预览项必须出现在命名项之间的有效插入位，不能沿用原分隔符位置；仅在释放指针后提交顺序，取消拖动时恢复原顺序。当前仅命名拼凑应用该交互，其他拖动排序区保持现有行为，待用户确认效果后再决定是否扩展。旧版 `settings.json` 缺少字段时使用“订阅厂商 · 地区/全部节点”。保存后必须按自动线路稳定 ID 同步重命名所有已保存方案中的成员和规则目标，并重建 profile。

- 策略组内置出站、策略组和地区线路成员按 `PolicyGroup.group_names` 顺序生成 `proxy-groups[].proxies`；成员卡片必须提供独立拖拽手柄，仅在当前组内重排该数组，并保留其他策略组设置、成员与节点范围。自动地区与来源线路必须按当前节点动态生成，设置键分别使用 `auto:provider:{sourceId}` 和 `auto:country:{sourceId}\0{country}`；旧方案缺少设置字段时默认 select。订阅刷新只重建线路成员，不覆盖各线路已保存的切换方式、测速网址和间隔。若某条地区线暂时没有节点，组内同名旧引用必须从生成的 `proxies` 中跳过；线路恢复后同名引用自动恢复。托盘必须从 exe 嵌入的 Windows 应用图标加载图像，与侧栏和 exe 使用同一图标资源。

- 右侧“自动地区线路”候选普通拖入策略组时，必须作为 Mihomo 自动策略组成员加入；按住 Shift 拖入时，必须保存为单个动态节点范围成员。范围引用使用内部前缀 `__clash_flow_manager_dynamic_node_range_v1__:` 保存自动组 ID 和显示名；组内界面只显示一张带浅琥珀色边框的卡片，可参与组内排序和移除，但不得作为默认成员。生成 `proxy-groups[].proxies` 时按引用所在顺序展开当前自动组的全部节点；节点来自当前订阅解析结果，因此订阅刷新后自动增删。自动组暂时不可用时保留范围引用，恢复后重新展开。

- 新建和编辑用户策略组时，名称输入区必须提供可直接输入的 Emoji 框和分类选择器；Emoji 输入框最多保留一个完整 Emoji，粘贴多个时只保留第一个。Emoji 框的输入区与下拉按钮必须在外框内保留内边距，两个内部区域和外框的圆角必须完整显示，不得被固定高度裁切；新建弹窗中 Emoji 框必须与策略组名称输入框等高。选择器必须提供 16 类、约 900 个去重后的常用 Emoji，覆盖常用、代理网络、地区国旗、AI 科技、办公学习、财务支付、社交通讯、影音媒体、游戏运动、旅行交通、天气自然、动物、食物饮料、活动爱好、生活物品和状态符号。必须显示总量及当前分类数量；分类按钮必须显示各自数量，Emoji 网格在选项过多时独立滚动。弹层必须通过 portal 挂到 `document.body`，按触发按钮定位并在窗口滚动、缩放时更新位置，不得被设置弹窗或滚动区裁切；下拉箭头必须用 CSS 绘制并居中的实心三角形。选择或输入的 Emoji 作为组名的前缀，写入现有 `PolicyGroup.name`，不得另建与组名不同步的 Emoji 字段。编辑已有名称时必须拆出开头的 Emoji，保留其余名称；清除 Emoji 后只保存文字名称。名称唯一性校验必须使用 Emoji 与文字组成的完整名称；重命名必须继续同步规则目标和其他组中的引用。

- `sources.json` 数组顺序是订阅来源顺序。订阅页拖拽卡片后，后端必须校验传入 ID 是当前来源的完整且无重复排列，再保存新顺序并重建 profile。前端自动策略组和 `proxy-groups` 中自动来源/地区组必须按订阅顺序生成；每个来源先列来源级“全部节点”，地区组按订阅节点中地区首次出现的顺序排列。来源内节点名称可继续按自然顺序显示，地区组顺序不得按地区名称重排。

- 同一订阅卡片的套餐信息必须位于标题正下方，展开和收起时使用同一布局、位置和尺寸。折叠仅控制套餐信息下方的详情区域。
- 所有运行时文件必须写入可执行文件同级 `userdata/`，不依赖 Windows AppData 路径。
- profile HTTP 服务仅绑定 `127.0.0.1`，使用 `userdata/profile-token.txt` 的随机令牌路径；preferred port 为 39127，启动时尝试其后的 23 个端口。
- Mihomo 控制器地址、密钥和混合端口来自 `settings.json`；默认端口为 9090 和 7890。控制器密钥写入本机配置文件，JSON/YAML/JSONL 数据未加密。
- `AppSettings.use_subscription_proxy` 控制单来源手动刷新和自动订阅刷新是否使用 `subscription_proxy`；缺少该字段的旧版 `settings.json` 按 `true` 迁移以保留既有行为。订阅来源概览中的批量刷新可单次强制直连或代理，不改写此设置。代理按钮可用性按已配置代理服务器的 TCP 连接探测决定，代理配置关闭或端口不可连接时禁用。关闭设置开关时仅单来源和自动刷新直连，模板下载和在线规则预览仍使用已配置代理；流量控制器请求强制直连以访问本机 Mihomo。
- `AppSettings.sync_subscriptions_on_profile_refresh` 控制 Clash Verge 请求本机 profile 时是否先同步所有已启用订阅；缺少该字段的旧版 `settings.json` 默认 `true`，保持原行为。关闭时跳过订阅刷新 worker，直接返回当前已生成的 profile；此开关独立于定时自动更新和订阅下载代理设置。
- 订阅下载使用 Clash Verge 官方文档示例格式的 `User-Agent: clash-verge/v2.4.0`，使按客户端标识分发订阅内容的服务商返回 Mihomo/Clash 兼容格式。
- 每个订阅来源单独保存节点名称格式：服务商前缀、国旗、国家/地区和原始节点名均由按钮切换；四个紧凑按钮仅显示字段名，位于订阅卡片底部原有的节点格式示例位置。原始节点名已识别为相同国家/地区时，必须省略重复国家/地区标签。旧版来源数据缺少格式字段时，各字段默认启用，以保持现有名称样式。应用启动时必须按当前格式重标已有缓存节点；名称变化时保存节点并重建 profile。保存格式或相关来源字段后，也必须重建该来源的本地节点名称、地区标记和 profile，同时保留现有节点 ID。
- `AppSettings.auto_update_enabled` 控制自动刷新订阅。缺少该字段的旧版 `settings.json` 按 `true` 迁移，保留原有自动更新行为；关闭时后台调度器不执行启动刷新和定时刷新，手动刷新命令不受影响。启用时 `update_minutes` 必须在 15 到 1440 分钟内。
- 订阅刷新命令分为批量刷新和按来源 ID 单独刷新。单来源刷新只替换对应来源的节点，保留其余来源节点；无论来源是否启用都允许用户手动刷新。不同来源的单独刷新必须允许并行下载；写入阶段由 `AppState.source_sync_lock` 串行化，并基于最新来源与节点状态合并，只替换目标来源的节点。批量刷新在此锁内完成读取、下载和写入，防止并发写入覆盖节点池。
- 每个订阅刷新任务必须使用独立 task ID、取消标记和进度记录。单来源刷新只禁用正在刷新的来源卡片，并显示连接、读取、解析与保存阶段；不同来源卡片的单独刷新入口必须保持可操作。批量刷新和 Clash Verge profile 刷新必须在概览显示总进度，并在每个启用来源卡片显示等待、当前阶段和完成状态。用户点击“停止刷新”时必须只取消对应任务的网络请求；批量停止后必须丢弃该轮暂存结果，完整保留刷新开始前的订阅来源和节点数据。定时自动刷新和 Clash Verge profile 刷新必须使用独立进度任务；停止 Clash Verge 触发的刷新时，profile 刷新请求必须收到同步失败结果。
- 订阅成功响应的 `Subscription-Userinfo`、`Profile-Title`、`Profile-Web-Page-Url` 响应头及正文公告会被解析成 `Source.subscription_info`；无法识别的公告字段保持缺省，不能影响节点解析。旧版来源数据缺少该字段时按空值读取，刷新失败时保留上次成功解析的信息。
- 来源卡片可按 ID 独立折叠；未记录状态时默认收起，首次点击“展开”必须立即展开；标题信息区和折叠按钮共用同一正确初始化的切换状态，启用开关和刷新按钮保持独立。刷新按钮固定宽度，空闲态与“刷新中”状态切换不得改变相邻操作的位置。标题信息区突出显示上次订阅更新时间距今的相对时长，悬停可查看具体时间；尚未刷新时显示“尚未更新”。展开后按“套餐信息 → 订阅设置 → 节点信息”的顺序显示；节点区默认折叠，可查看全部节点、国家/地区和“🌐 未纳入的节点”，并在同一列表对照生成节点名与订阅原名。节点数为 0 的分类必须禁用，防止选中后只显示空列表。未识别地区和名称带订阅公告的有效代理节点可以归入“未纳入”查看分组，但不得因此从来源级全部节点线路、动态全部节点范围或生成的 profile 中排除。套餐信息单独显示在订阅卡片顶部，不计入节点数或移入节点分组；订阅设置区域使用独立边框；线路列表不得再增加逐组折叠层级。收起状态仍展示来源名称、节点数、更新时间、套餐信息和错误信息。编辑态与折叠态均使用应用级状态，切换页面后保持；“保存”仅在来源的可编辑字段发生变化时启用，单来源刷新入口在卡片标题栏保持可用。
- 订阅解析先尝试 Clash YAML 和明确识别的分享链接，再尝试 Base64 内容；YAML 节点必须具备非空名称、已知 Mihomo 协议类型、服务器地址和有效端口。服务商客户端下载/协议说明不能作为节点保存，刷新失败保留旧节点时也必须剔除已识别的说明类假节点。普通 HTTP(S) 网页地址不能作为分享链接解析。
- 无法识别的响应必须提供不含响应正文和订阅令牌的诊断信息，包括粗粒度 Content-Type、响应字节数和正文类型；客户端/协议说明必须提示用户在服务商后台选择 Mihomo/Clash 兼容订阅格式。
- 下载代理在界面拆分为协议、IP 地址和端口，保存时仍写入兼容旧版的代理 URL；空 IP 必须规范化为 `127.0.0.1`，直连保存为 `direct`。
- 流量按 1 秒间隔轮询 `/connections`。累计计数用于全局上传/下载；连接记录从活跃连接增量归类，`UsageRecord.group` 保存策略链首项，汇总提供按站点、节点、来源、策略组、规则及其组合明细的视图。分类采样不代表服务商账单，分类和全局累计的口径可能不同。
- 流量分析页必须独立于完整应用快照，每秒读取一次轻量连接状态，使界面显示的采样时间每秒更新。页面“刷新数据”按钮必须重查当前日期范围的汇总及未命中记录。组合明细和站点汇总的站点名称必须提供自定义右键菜单“复制网站链接”；采集记录仅保存主机名时，复制值使用 `https://` 加主机名。
- 流量分析的每日趋势图必须使用 Recharts `BarChart` 和统一纵轴，以并列柱分别显示每日下载与上传，不得将两项数据上下堆叠；Tooltip 必须按单根柱响应悬停，并显示该日期、上传/下载方向与对应流量值，位置须随当前柱即时更新且不得出现从图表角落飞入的位移动画。该展示图不接收鼠标焦点，图表及其内部元素不得出现点击焦点黑框。图表标题和总量卡片使用语义清楚的内联 SVG 图标。
- “线路验证”只提供 Mihomo 真实验证。页面必须使用协议下拉框选择 `http://` 或 `https://`，地址输入框供输入主机和可选路径；若地址自带 HTTP/HTTPS 协议，必须按地址中的协议构造请求并忽略下拉框选择，不能重复拼接。
- Mihomo 真实验证必须使用已保存设置中的 `mixedPort` 发起实际 HTTP 请求，并在发起前记录 `/connections` 基线 ID，只将新增且主机/端口匹配的连接作为验证结果；页面展示其 `rule`、`rulePayload`、`chains` 与最终节点。控制器轮询必须直连本机，目标请求必须显式使用 Mihomo 混合代理并关闭自动重定向。请求带 `Range: bytes=0-0`，客户端不得读取响应正文；未捕获到活动连接时必须明确标记无法确认，不得推算或伪造路线。进程规则命中的是 Clash Flow Manager 进程。
- 本机方案保存在 `policy-library.json`，`activeId` 指向当前启用方案；`policy.json` 仍保存当前 profile 使用的策略。线上模板导入只返回解析结果，保存或启用前不得改变当前策略。
- 在线策略模板目录与本机已保存方案分开展示；目录包括 ACL4SSR、Subconverter 和社区模板。选中模板只填入名称与地址，点击读取后由本机下载；页面预览区须完整列出解析策略组和规则，并允许查看规则集与保留的原始模板正文。预览内容必须限制在预览容器宽度内，原文长行在容器内折行，不得扩展页面宽度。目录清单随软件发布，模板正文按选定链接获取；自定义地址仍可直接输入。ACL4SSR 本地版的 `rules/ACL4SSR/Clash/` 相对规则路径转换为 ACL4SSR 仓库中的绝对规则 URL。
- 规则集库使用应用内的 `<dialog>` 打开新增和编辑表单。弹窗必须与列表分开显示，打开时将焦点限制在弹窗内，保留列表状态。关闭按钮和 Esc 关闭弹窗，写入期间须保留表单直到返回结果。

## 构建与验证

在项目目录执行：

```powershell
npm install
npm run typecheck
npm run build
```

`npm run build` 会生成 React 静态资源，随后调用 Tauri 构建并复制单文件至 `release/ClashFlowManager.exe`。构建输出目录 `dist/`、`.build/`、`src-tauri/target/`、`release/` 和 `userdata/` 均为本地产物或运行数据，不应提交。

验证规则集弹窗时，分别从规则集库打开新增和编辑，确认新增显示表单且编辑加载已有内容。关闭弹窗后，列表必须保留当前状态。保存新增或编辑后，列表必须随即显示写入结果。检查策略组规则集管理页时，确认目录始终显示完整可用规则集，当前组已引用项默认勾选，未引用项可供添加；目录搜索覆盖全部本地规则集库，可与来源和用途分类组合；同时匹配规则集名称和本地规则文本，不匹配说明，也不发起网络请求。在策略组设置页直接输入关键词，确认同一次搜索覆盖当前组自定义规则和已引用规则集，只显示各自命中项；MRS、未同步及本地缺失项必须提示结果覆盖不完整。规则集有改动时，点击弹窗底部唯一按钮一次即可应用至方案草稿并返回；无改动时该按钮直接返回。检查在线规则时，用条目数相同但规则不同的源文件验证更新提示，再同步并核对本地追加和屏蔽仍然有效。

验证策略组的单条规则输入提示时，逐一切换七种规则类型，确认 placeholder 与说明分别使用正确示例：域名后缀、精确域名、域名关键词、IPv4 CIDR、IPv6 CIDR、进程名和完整 Windows 程序路径；切换类型后输入框已有内容应保留，先前的校验错误应清除。

验证策略组规则批量添加时，切换“批量”模式并粘贴多行规则，确认所选类型应用到每个非空行、空行被忽略、有效规则一次写入并保持输入顺序；重复规则必须跳过并计数，无效规则必须显示原始行号和原因且保留在输入框中供修改；切换规则类型后必须按新类型重新校验，不得丢失待处理内容。

验证已添加的单条规则列表时，确认这七种规则类型均显示与规则类型选择器一致的中文名称；规则配置中的 `kind` 值保持 Mihomo 原始类型标识。

验证策略组候选时，确认“内置项”“策略组”“自动地区线路”三个标签可切换，默认选中“内置项”；其中 6 项按动态“全部可用节点”、DIRECT、REJECT、REJECT-DROP、PASS、PASS-RULE的顺序显示；五种内置出站均可拖入组内、显示为成员，并在生成配置的 `proxy-groups[].proxies` 中保留原名；动态项拖入后设置 `include-all: true`；COMPATIBLE 不作为独立候选。

验证策略组规则集目录的来源筛选时，确认“全部来源”、blackmatrix7、ACL4SSR、MetaCubeX、Loyalsoldier 和 Sukka 六项可选；来源按规则集 URL 识别，来源筛选可与用途分类及规则集标题、内容搜索组合，筛选和搜索不改变当前勾选及待应用顺序。

验证组内成员排序时，将组内内置出站、策略组或地区线路卡片通过左侧拖拽手柄移到另一张卡片上；检查同组 `PolicyGroup.group_names` 顺序更新，生成配置的 `proxy-groups[].proxies` 顺序同步，并确认其他组设置、成员和节点范围保持原值。

验证自动地区线路的两种拖入方式：普通拖入后，组内出现可配置切换方式的地区策略组成员，Mihomo 配置保留该自动组名称；按住 Shift 拖入后，组内只出现一张琥珀色“动态节点范围”卡片，显示当前节点数，可拖动排序和移除。检查生成配置在卡片所在顺序展开该线路全部当前节点，而不是自动组名称；模拟订阅节点增删后，卡片保持一个成员，生成节点清单随之更新。临时缺失的自动组不得丢弃已保存范围引用，恢复后继续展开；本地线路验证的成员数量和预览应解析同一动态节点范围。

验证策略组名称 Emoji：打开选择器后核对显示总量及当前分类数量，切换 16 类并确认分类按钮上的数量与可选项一致；大分类的 Emoji 网格必须能独立滚动；设置弹窗上下滚动时弹层必须跟随触发按钮且不被裁切；下拉箭头必须是居中的实心三角形；连续输入或粘贴多个 Emoji 时输入框必须只保留一个。新建组时直接输入 Emoji 与分类选择器选取 Emoji 均应作为组名前缀显示；编辑已有 Emoji 组名时 Emoji 与文字须分开显示，改名或清除 Emoji 后完整组名唯一性校验生效。完成编辑后检查左侧组卡名称、Mihomo `proxy-groups[].name`、指向该组的规则目标和其他策略组引用同步更新。

验证自动策略组区域时，点击“自动策略组”标题可整体收起和展开，展开时操作文字为“收起”，折叠时为“展开”；折叠后标题、说明和数量仍可见。切换到其他工作区再返回时，折叠状态按方案保留，单个自动组的折叠状态仍独立。检查嵌套策略组成员卡片的成员卡片第一行显示加粗名称和浅灰蓝类别标签，第二行直接显示浅色摘要文字，不添加左边线或额外缩进；摘要或名称过长时以省略号显示并可悬停查看全文。

验证自动线路面板时，确认默认收起并显示“合并订阅 / 节点分组”、总节点数和分组数；展开后只显示按订阅厂商分区的自动线路及节点数，命名风格通过单独弹窗打开。检查面板不改变订阅卡片布局。验证命名拼凑时，拖动厂商或线路元素跨过另一项，确认拖动项跟随指针，其他元素在悬停期间实时平滑挤压换位；松开后顺序保存，取消拖动后回到原顺序；拖动待选分隔符到命名拼凑区的名称间隙，确认占位项出现在指针对应的间隙并推动相邻元素让位，松开后生效。当前版本只在命名拼凑使用实时让位动画，其他排序区不变。打开策略方案，检查自动策略组按订阅顺序分区、每个来源的地区组按订阅中地区首次出现的顺序展示；刷新或重启后检查顺序保留，生成 profile 中自动线路的顺序与界面一致。

验证社区规则目录详情时，确认未保存的条目会读取规则预览并显示加载与错误状态，打开和关闭详情不改变目录筛选、搜索和勾选状态，查看不会写入规则集库；已保存的同来源网址应显示其本地远端快照、追加和屏蔽内容。验证批量添加时，确认全选只作用于当前筛选结果、筛选切换后既有勾选仍保留、已有规则集不能重复选择；批量处理期间须显示进度，单项读取或保存失败不应中断其他项，失败原因和重试选择须保留，结束后列表内容须刷新。

验证“线路验证”时，使用 HTTP 与 HTTPS 链接分别确认请求经过已配置的混合端口；对照 Mihomo 活动连接中的规则、策略链和最终节点。Mihomo `/connections` 的 `chains` 从实际出站节点向外层组排列，界面须反转后显示，最内层节点标为“最终节点”，最外层策略目标标为“策略组”。确认 `DIRECT`/`REJECT`、HTTP 错误状态仍能显示已捕获的路由；快速结束而未被 `/connections` 捕获的连接必须显示无法确认，不得显示推算线路。确认重定向不会跟随，且客户端不读取响应正文。随后在方案编辑页打开“规则顺序”，确认弹窗铺满窗口上下可用高度，左右栏按列从上到下显示相同策略组卡片、组号对应，卡片保持紧凑并沿列表高度纵向分布；拖动左栏只改变 `PolicyConfig.groups` 显示顺序且不改变右栏，拖动右栏只改变 `ruleGroupOrder` 和生成规则顺序且不改变左栏；鼠标悬停策略组卡片时确认两侧同 ID 组同步高亮；对应卡片滚出另一侧视口时，另一侧自动滚动到卡片位置；卡片间隙不触发高亮。未修改旧方案时右栏按当前生成规则中各组最早被指向的位置排列。拖动多个右栏策略组后，确认右栏顺序实时预览，指向各组的单条规则与规则集规则按右栏顺序输出、组内顺序保留；排序弹窗不显示固定的 `MATCH` 卡片，所有规则未命中时仍由方案页底部黄色选项控制 `MATCH` 去向。

验证默认成员时，检查手动选择策略组的节点和嵌套策略组卡片在悬停或键盘聚焦时出现图钉；点击后只有该卡片显示固定图钉，并在生成的 `proxy-groups[].default-selected` 写入对应 Mihomo 成员名；再次点击当前固定图钉后移除该字段。检查暂时缺失的默认成员仍保留设置并可从提示中取消；检查自动地区线路的默认节点随方案保存并输出同名字段。对于 `url-test`、`fallback` 和 `load-balance`，不得输出 `default-selected`。默认目标暂时不属于组内成员时，Mihomo 按文档回退到首项；订阅刷新后重新出现同名节点时，该配置仍可命中。

- 仅替换 exe；不得清空或删除目标目录中的其他文件，尤其保留 exe 同级 `userdata/`。该目录是临时测试位置，不是正式发布目录。

## 已知限制

- 截至 2026-11-22，本机 profile 刷新曾出现偶发 HTTP 502；代码将刷新 worker 错误映射为 502，等待超过 18 秒映射为 504。该次 502 的具体触发原因未确认，当前没有复现结论。

- 支持订阅响应格式及导入范围见[使用说明](./使用说明.md)。当前 INI 导入器覆盖常见 `custom_proxy_group`、`ruleset` 和 `rule` 行，未实现 Subconverter 的所有选项或远端模板运行时。
- 节点地区标签来自节点名称中的有限关键词识别，或来源配置的默认地区提示；无法识别的地区会标为用户提示或“未识别”。
- 分类流量依赖活跃连接采样，短连接可能缺少分类；采集从本程序运行后开始，无法补取启动前历史。
- ACL4SSR/Subconverter 仍按已实现的常见 INI 行解析，并非完整执行远端转换器。在线目录提供的策略模板可随上游变更；特定服务商模板需核对节点命名匹配条件和规则目标。
- 数据目录旁需要有写权限；把 exe 放到受限系统目录可能导致启动或保存失败。

## 配置命名、流量历史与备份

- `AppSettings.profile_name` 与 `profile_traffic_source_id` 分别保存远程 profile 名称和唯一流量信息来源；配置名称与流量来源均只在“导入配置”页设置。删除所选来源时必须同步清空该设置。
- 本机 profile 服务收到有效 profile 路径的 GET 请求时，必须更新时间戳文件 `profile-last-requested-at.txt`。`sync_subscriptions_on_profile_refresh` 开启时，向订阅刷新 worker 发出请求，并等待所有已启用来源同步及 `generated-profile.yaml` 重建完成后再读取并返回 YAML；worker 返回错误时必须返回 502，等待超过 18 秒必须返回 504。多个尚未完成的请求必须合并为一次同步，且同步过程中到达的请求使用本轮结果。此 profile 触发的同步不受自动更新开关控制。该设置关闭时跳过 worker，直接返回当前生成的 YAML。profile 内容或元数据发生变化时必须更新 `profile-last-generated-at.txt`，不得清空上次请求时间。通过 `AppSnapshot.profileLastRequestedAt` 和 `profileNeedsUpdate` 提供给前端，供流程导航显示待导入、待更新或已拉取。旧版将请求时间写为 0 的标记必须迁移为待更新提示。该状态只表示 profile 地址被请求，不能证明 Clash Verge 已导入、选中或启用。
- `AppState::regenerate_profile` 必须同步写入 `generated-profile.yaml` 和 `profile-metadata.json`。`server.rs` 每次响应读取元数据，输出不带 `.yaml` 后缀的 UTF-8 `Content-Disposition` 文件名；只有选中订阅存在足够的套餐数据时才输出 `Subscription-Userinfo`。
- `traffic::clear_history` 只删除数据目录顶层匹配 `traffic-*.jsonl` 与 `unmatched-*.jsonl` 的文件，不得递归删除或影响其他用户数据；界面必须在调用命令前连续执行两次破坏性确认。
- `backup.rs` 的版本化 JSON 包含设置、订阅、节点、当前策略、全部策略方案、规则集库及全部流量 JSONL 历史。恢复必须验证格式/版本、来源与节点 ID、流量文件名和配置名称；必须保留当前运行 profile 端口，不导入/覆盖运行令牌。提交写盘前必须生成 profile 并完成数据序列化；文件写入或清理失败时必须尝试回滚已修改文件。恢复完成后再更新内存状态。
- 导出备份必须先打开系统保存对话框，由用户选择保存位置；默认文件名使用 `ClashFlowManager-完整备份-YYYY-MM-DD-HHmmss.json`。恢复必须由用户选择文件并连续确认两次。备份含订阅 URL、节点凭据和 Mihomo 密钥，界面与使用说明必须提示文件未加密。
- 代码改动后的最小检查为 `npm run typecheck`、`cargo check --offline` 与 `npm run build`；交付测试 exe 时还须执行前述 `scripts/replace-test-exe.ps1` 并核对 SHA-256。手动清空和备份往返需要在 Windows 应用界面验证；未执行时不得报告为已验证。

## 策略方案空白状态与默认流量去向

- “从空白开始”创建的方案 `groups` 和 `rules` 都为空；策略方案页按已有名称自动建议不重复的新名称。
- `policy.rs` 在没有自定义策略组时会生成全部节点入口，在没有分流规则时会生成 `MATCH,DIRECT`。策略编辑页明确展示当前默认去向，并可添加或更新一条 `MATCH` 规则；更新时将兜底规则放到列表末尾。
- 网站快速分流、单条规则目标和默认去向选择器必须提供本方案策略组及内置 `DIRECT`（直连）与 `REJECT`（拦截）。
- 若没有明确选中的自定义策略组，快速添加网站规则的目标默认值必须为 `DIRECT`。新建规则目标只能选择本方案策略组、`DIRECT` 或 `REJECT`；历史规则若仍指向自动线路组，必须保留原值并标记为既有配置，用户改选前不得静默重写。
- 按来源/地区生成的线路组展开后展示全部节点名称，不截断、不分页。

## 策略方案可视化编辑器

规则顺序弹窗左右列表必须各自独立拖动与滚动；宽屏按三列、较窄窗口按两列显示紧凑策略组卡片；每列从上到下填充，卡片只显示组名。拖动项必须跟随指针显示浮层，原位置保留半透明占位卡，排序变化按前后坐标播放让位动画；网格拖动必须支持首位、末位及跨列放置，指针靠近列表上下边缘时自动滚动。右侧必须按 `ruleGroupOrder` 显示全部组，包括当前没有规则指向的组，并将未被指向的组排在末尾。左侧拖动只改变 `PolicyConfig.groups` 的显示顺序；右侧拖动只改变流量检查组规则的顺序；两边不得同步改变对方顺序。鼠标悬停在策略组卡片内时，两边同 ID 组必须同时高亮；若对应卡片不在另一侧可视区域，另一侧列表必须滚动到该卡片。卡片间隙和边缘空区必须清除高亮；不得保留点击选中状态或绘制连线。拖动开始后，所有指针事件必须由稳定的窗口级监听持续接收。

- `src/PolicyVisualWorkspace.tsx` 是方案内容的独立编辑界面；方案列表继续由 `PolicySchemeManager` 显示。方案摘要必须分别统计普通分流规则、规则集引用与兜底状态，不能把所有规则统称为网站规则或用规则集定义数代替引用数。编辑器不提供回到旧版的试用开关，也不调用已移除的单组编辑页面。
- 所有策略组以折叠卡片显示，新建流程只打开一个单字段名称弹窗；创建后卡片默认折叠。卡片拖柄只调整 `PolicyConfig.groups` 的展示顺序。方案编辑页右上角的“规则顺序”入口打开方案级排序弹窗；弹窗必须左右分栏，左右均用紧凑卡片显示全部策略组，卡片只显示组名并按 ID 对应；宽屏按三列、较窄窗口按两列显示，每列从上到下填充：左栏可独立拖动，只调整 `PolicyConfig.groups` 的展示顺序；右栏可独立拖动，按生成规则中各策略组最早被指向的规则排列并调整实际规则命中顺序。左右拖动必须互不影响。右栏必须包含所有策略组，未被普通规则指向的组仍显示在末尾。鼠标悬停一侧的策略组卡片时，另一侧同 ID 组必须同步高亮；对应卡片不在另一侧可视区域时，该侧列表必须滚动到对应卡片。卡片间隙和边缘空区必须清除高亮；不得保留点击选择或绘制连线。卡片必须整块可拖动；拖动项跟随指针显示浮层，原位置保留半透明占位卡，其他卡片按前后坐标播放让位动画。多列拖动必须支持跨列及首末位置。左右列表必须分别独立滚动，拖动项不得跨列表更改另一侧顺序。拖动开始后，所有指针事件必须由稳定的窗口级监听持续接收。应用后更新当前草稿，仍须点击“保存方案”提交。左栏顺序直接保存在 `PolicyConfig.groups`；右栏顺序保存在 `PolicyConfig.rule_group_order`，单组内部规则顺序保留。旧方案缺少 `ruleGroupOrder` 时必须按空列表读取并保留原生成顺序；右栏未调整时必须反映当前生成规则顺序。右栏有调整时，普通去向规则保持原序，指向策略组的规则按右栏组顺序生成，`MATCH` 仍在末尾。`MATCH` 兜底不得出现在排序弹窗中，仍由工作区底部“未命中规则时”选项控制。测速网址与间隔必须使用下拉预设；对已有非预设值提供仅用于保留旧设置的选项。切换策略组方式时必须保留测速网址和间隔；生成非测速组配置时不得输出这些暂存值，切回测速方式后必须恢复。组设置页不得重复显示分流明细，只提供单条规则和规则集两个管理入口，分别进入独立管理页；规则集页始终显示完整可用目录，并预选当前组已引用项，用户通过勾选状态统一增加或移除，并一次应用选择结果。组设置页还必须直接显示关键词输入框，不得要求跳转到另一个验证页；该输入框必须同时搜索当前组自定义规则的匹配内容和已引用规则集的本地规则文本，并分别显示命中项。
- 策略方案编辑器右侧“自动地区线路”候选按订阅厂商分组，每个分组内排列该订阅生成的全部节点线路；线路卡保留拖入目标策略组和打开线路设置的操作。候选卡片摘要只显示当前节点数量；地区与订阅商保留在名称中，切换方式等其他摘要信息不显示，节点数随订阅刷新动态更新。
- 策略组编辑器必须采用左右两栏：左侧显示用户创建的策略组和独立的自动策略组卡片；自动策略组列表必须可整体折叠，标题、说明和数量在折叠时保持可见，折叠状态按方案在应用内页面切换时保留；每张自动组卡片也可单独折叠。自动组按订阅来源及已识别地区生成，展开可查看当前成员，成员随订阅刷新自动增加、移除或换入新节点。自动组作为真正的 Mihomo `proxy-group` 输出，可单独设置切换方式、测速网址与间隔，设置保存在当前方案。右侧候选 Tab 固定为“内置项”“策略组”“自动地区线路”；“内置项”包含动态“全部可用节点”和 DIRECT、REJECT、REJECT-DROP、PASS、PASS-RULE 五种内置出站；“策略组”只列用户创建的策略组，“自动地区线路”只列自动组，同一自动组不得同时出现在这两类候选中。内置项共 6 项，按动态“全部可用节点”、DIRECT、REJECT、REJECT-DROP、PASS、PASS-RULE 顺序显示；六张卡必须单列全宽、等高并分别使用低饱和语义色，策略组和自动地区线路候选使用白色样式。“全部可用节点”与左侧动态节点范围必须使用同一种琥珀色；DIRECT、REJECT、REJECT-DROP、PASS、PASS-RULE 必须各用一种易区分的克制配色。COMPATIBLE 是 Mihomo 自动兼容回退，等效 DIRECT，不单独列为候选。候选项必须使用 Pointer Events 拖动到左侧目标组；不得提供逐项单击加入或批量加入控件。不得提供单个节点候选；动态项只提供“全部可用节点”范围。策略组卡片摘要、组内成员卡片和右侧候选必须区分直接节点数与下级策略组/线路数，分别标为“个节点”“个成员”；同一策略组在左侧和右侧显示相同成员数。自动地区线路候选与组内成员卡片使用对应国旗；台湾、香港显示中国国旗。组内成员卡片采用紧凑两行布局，保持两列等宽；嵌套策略组成员卡片第一行必须显示加粗成员名称和浅灰蓝类别标签，第二行直接使用浅色文字显示策略摘要，不添加左边线或额外缩进，以建立清晰且克制的信息层次；摘要或名称过长时必须省略，并在悬停时显示完整内容。展开成员框与标题分隔线之间必须留出清晰间距，边框不得相贴或重叠。候选名称必须完整换行显示，不得使用省略号截断。内置出站、策略组或自动地区线路成员写入 `PolicyGroup.group_names`，配置生成器将其作为 Mihomo `proxy-groups[].proxies` 项输出。
- 策略组、线路规则和规则集的操作必须分层：组设置放在设置弹窗；单条网站/IP/应用规则和规则集必须由两个独立入口分别打开独立管理页，各页只管理对应内容。策略组引用必须阻止自引用、有向循环和重复加入。组卡摘要不得重复显示策略组引用数；多个已引用成员必须在可用宽度内按两列等宽排列，奇数项的最后一张卡仍保持单列宽度，不得跨列铺满；窄窗口时再切为单列。组卡展开箭头必须使用居中绘制的 CSS 图形，成员移除按钮必须清零默认内边距并居中，避免字符基线造成错位。
- 主窗口顶部必须显示订阅来源、策略方案、导入配置、流量分析四步导航。四个主模块隐藏“Clash 管家 / 页面名”面包屑小标题；订阅来源、方案列表、配置地址和流量范围等操作必须放在各自内容区对应的操作行，不得挤入全局导航栏。顶部栏必须将面包屑、页面计数等信息放在左侧，将功能操作放在右侧。设置页“保存设置”仅在设置草稿与当前设置不同时启用。进入策略编辑后隐藏流程导航；返回方案列表操作放在顶部栏最左侧，方案名称和状态紧随其后，新建、放弃和保存操作靠右对齐。运行状态必须统一放在左下角侧栏。策略编辑页面不得再重复显示大块方案摘要和成员编排标题栏。
- 策略组引用必须阻止自引用和有向循环。删除策略组时必须同时删除目标为该组的规则和其他组中引用该组名称的线路项；确认提示必须显示受影响的其他策略组数和分流规则数。组重命名时必须同步更新规则目标及其他组的同名引用。普通删除动作显示确认；Shift 点击跳过确认，不能跳过业务校验。编辑器保存、放弃和返回由方案级操作控制；离开工作区不得自动保存或启用方案。
- “全部可用节点”范围必须由 `PolicyGroup.all_nodes` 表示，并由 Mihomo `include-all: true` 输出，确保订阅刷新后当前全部解析成功的节点动态进入该组，包含地区无法识别的节点。来源级全部节点线路同样包含该来源的全部有效节点；国家/地区线路仅包含已识别地区节点。`includeNodeIds` 和 `excludeNodeIds` 保留用于读取与编辑旧方案；两个字段必须使用 serde 默认值兼容旧 `policy-library.json`。已保存的单节点包含/排除继续按节点 ID 映射到配置，当前界面不提供新增单节点候选。
- 内置出站、策略组、自动地区线路候选及策略组拖柄必须使用 Pointer Events 和 pointer capture 完成按住、移动、松开；不得依赖 WebView HTML5 DataTransfer。移动达到拖动阈值后，必须显示随指针移动的卡片提示，并高亮唯一的目标策略组。松开“全部可用节点”动态项时只设置目标组的 `all_nodes`，不得解包成静态节点清单或自动展开节点明细；松开内置出站/策略组/地区线路卡片时写入 `groupNames`；松开组拖柄时调整组顺序。
- 策略组卡片左侧必须只放组顺序拖柄和组名；摘要、状态、成员/规则计数、折叠、设置和删除位于卡片右侧区域。组名与摘要所在的主区域必须是折叠/展开点击区；拖拽柄、折叠箭头、设置和删除按钮只执行各自动作。摘要统计必须紧接组名排列并使用剩余宽度，不能在名称与摘要之间留下明显空档而截断摘要；摘要保持单行，小窗口下才允许换行。新建策略组默认不包含节点；右侧“内置项”必须包含可拖动的“全部可用节点”动态项。只有将该项拖入指定组时才设置当前 `PolicyGroup.all_nodes`；不得创建名为“全部节点”的策略组。配置生成器必须输出 Mihomo `include-all: true`，使订阅刷新后的节点自动进入该组；编辑器内将此动态范围显示为一个聚合项，且必须与自动地区线路的动态范围卡片使用相同的紧凑两行成员卡格式和琥珀色配色：第一行显示名称与类型，第二行显示节点数和订阅同步摘要。节点明细必须由用户点击卡片展开控件后单独查看，默认收起；拖入动态范围时不得自动展开节点列表。
- 新增网站、IP 或应用规则及多选规则集，都在策略组对应的规则管理页绑定当前组；规则集 ID 同时对应写入 `ruleProviders`。已支持的域名、IPv4 CIDR、IPv6 CIDR 及进程规则必须按类型校验；前端添加和后端保存都必须拒绝空内容、错误域名/CIDR，以及可破坏生成规则格式的逗号或换行。策略组设置必须提供“网站 / IP / 应用规则”和“规则集”两个管理入口；两者打开各自管理页并只显示对应类型。关键词输入框必须直接位于策略组设置页中，并在同一次搜索中匹配当前组自定义规则的 `rule.value` 与已引用规则集的本地有效规则文本。单条规则行必须依次排列序号、规则类型、匹配内容和移除按钮；移除按钮必须保持在末列，不得继承成员行的跨列定位样式。规则集管理页不得重复展示“已加入当前组”列表；目录中的当前组既有规则集必须默认勾选，取消勾选标记待移除，未加入项勾选标记待加入；勾选变化必须暂存到当前方案草稿；弹窗底部只能有一个操作按钮，有待应用变化时显示“应用并返回设置”，点击后必须应用增删和顺序并返回，无变化时显示“返回设置”；新勾选项按勾选顺序加入匹配顺序。规则集目录必须始终显示本地规则集库的完整可用目录，不得因当前组的引用状态隐藏候选；当前组已引用项必须默认勾选，取消勾选标记待移除，未引用项勾选标记待加入。目录搜索必须同时匹配规则集名称（卡片标题）和本地有效规则文本，均按大小写不敏感的字面子串匹配；不得搜索规则集说明或发起网络请求。标题和内容搜索必须与来源及用途分类组合；标题命中或规则内容命中的规则集均须显示，内容预览最多展示三条命中规则并注明剩余数量。策略组设置页的关键词输入框必须同时检查当前组自定义规则和当前组已引用的规则集 ID；自定义规则只比较其匹配内容，规则集只搜索本地可读规则文本，不得把未引用候选加入检查。MRS 或尚未完整同步的规则集必须标注结果覆盖不完整，不得把无法读取的规则内容显示为无命中。目录还必须按 AI 服务、搜索与开发、社交与通信、影音与音乐、游戏平台、云服务与支付、国内服务、网络与广告、其他用途分类浏览。目录待应用状态必须在候选卡片滚动时保持可见；唯一的应用/返回按钮由弹窗底部提供。规则集明细行必须限制在弹窗宽度内，弹窗内容不得产生横向滚动条；仅一类分流内容有数据时，该类必须使用完整可用宽度。添加规则插在目标组现有规则之前；同一类型内拖动排序时，另一类型条目在全局列表中的位置必须保持。方案级最终 `MATCH` 去向仍在工作区底部编辑；没有 MATCH 时选择去向会创建一条。
- 网站、IP 和应用单条规则管理必须提供“单条”和“批量”两种录入方式，规则类型选择对两种方式共用。批量输入按换行拆分，每个非空行独立执行现有类型校验；空行必须忽略，重复项按当前组、规则类型和值（大小写不敏感）跳过。有效项必须按原始行序一次性插入当前组已有规则之前；无效项不得写入，必须保留在输入框中并显示原始行号及校验原因。批量完成后必须显示新增、重复跳过和无效行数。
- 策略组设置页不得展示“分流内容”概况、规则明细列表或空状态占位；只保留“网站 / IP / 应用规则”和“规则集”两个独立入口，并在入口上显示当前数量。关键说明文字不得小于 12px。

- 策略组规则集管理页必须提供来源筛选行，选项为“全部来源”、blackmatrix7、ACL4SSR、MetaCubeX、Loyalsoldier 和 Sukka；必须根据规则集 URL 识别这五个社区来源，未匹配来源的条目仍须在“全部来源”中显示。来源筛选必须与用途分类、规则集标题和规则内容搜索组合，筛选不得改变当前组的勾选状态或规则顺序。
- 删除策略组时必须同时删除目标为该组的规则和其他组中引用该组名称的线路项。普通删除动作显示确认；Shift 点击跳过确认，不能跳过业务校验。编辑器保存、放弃和返回由方案级操作控制；离开工作区不得自动保存或启用方案。
- `PolicyGroup.exclude_node_ids` 只记录用户在可视化编辑器明确移出的地区节点。旧版 JSON 缺少该字段时按空列表迁移；字段不得加入规则集库或订阅来源模型。
- 手动选择策略组通过组内成员卡片悬停出现的图钉设置或取消默认成员；选中项图钉始终显示。默认值使用 `options["default-selected"]` 保存并写入 Mihomo `default-selected`；候选必须来自组内节点、嵌套策略组或内置出站。自动地区线路通过 `AutoGroupSettings.default_selected` 保存可选默认节点，并仅在切换方式为 `select` 时输出。非手动选择组不得输出 `default-selected`；缺失成员的回退行为由 Mihomo 处理，不得在订阅刷新时静默清除用户配置。
- 规则集管理页的候选项仅显示规则集名称、规则条数、用途类别和来源主体；当前选择必须由勾选图标及卡片状态表达，不得额外显示“选择”“已加入”等状态文字。规则条数与用途类别同一行，来源主体另起一行，不得把名称、用途、数量和来源挤在同一行。来源主体必须显示 GitHub/Gitee/GitLab 所有者、自定义来源域名或“本地自建”。说明和完整来源地址必须通过独立“详情”入口在详情弹窗中查看，详情操作不得改变选择状态。详情弹窗必须提供全部已保存的远端规则、本地追加和屏蔽规则，支持搜索与分页；MRS 二进制规则必须明确说明不支持逐条查看。候选卡片按可用宽度自适应为紧凑多列布局，把更多可选项留在可视区域内。
