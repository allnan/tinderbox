# Codex 用量预测：使用说明

本文介绍安装、图表含义、刷新与常见状态。以下命令必须在项目根目录执行。

## 安装与打开

运行环境需要 Node.js、Codex CLI 与 Codex 桌面端；额度读取需要本机 Codex 中可用的登录状态。

```powershell
codex plugin marketplace add .
codex plugin add codex-usage-panel@codex-local-tools --json
```

从 Codex 侧边栏打开“Codex 用量预测”。页面同时显示 5 小时和周额度；账号没有返回的额度窗口会显示“额度未提供”。

## 阅读额度卡片

每张卡片按当前用量、走势与重置时间排列。用量条表示当前已用比例，右侧显示距重置的倒计时。

| 信息 | 含义 |
| --- | --- |
| 绿色已用曲线 | 当前重置周期内的历史额度快照，经轻度平滑后显示走势；样本不足时回退为当前窗口均速回推。 |
| 橙色预测线 | 按当前窗口平均使用速度估算到重置时的用量。超过 100% 时端点向上取整显示预测值，卡片标出预计超额；图表仍保持 0–100% 尺度。 |
| 5 小时图的合理消耗区间 | 结合历史活跃时段、活动频率与剩余周额度，估算一个完整 5 小时窗口可分配的总预算。 |

5 小时图两端显示开始时间与重置时间；周额度图两端显示开始日期时间与结束日期时间。

卡片标签使用以下文案：

- **重置时余量 N%**：按当前窗口均速外推，重置时预计剩余的比例。
- **重置前预计用尽**：当前均速预测达到额度上限。
- **预计超额 N%**：当前均速预测超过额度上限，超额量向上取整显示；例如预测为 100.2% 时，标签显示“预计超额 1%”。
- **重置时余量估算中**：当前窗口时间或样本还不足以生成估算；窗口前 5 分钟暂不产生数字预测。

合理消耗区间按完整 5 小时窗口计算，当前已用量可以高于区间；周额度先重置时，只分配本周剩余额度。这个区间仍需真实使用数据回测，具体数据、公式及限制见[额度预算算法](./额度预算算法.md)。

## 数据与刷新

插件通过本机 `codex app-server --stdio` 的只读接口 `account/rateLimits/read` 读取当前额度。历史快照从 `CODEX_HOME` 指定的根目录下 `sessions/**/rollout-*.jsonl` 读取；未设置 `CODEX_HOME` 时，默认根目录为 `~/.codex`。历史最多回看 14 天。

历史样本来自已有记录，面板打开频率不决定样本数量。计算只使用限额字段和事件时间，不保存对话正文或令牌，也不上传数据。页面可刷新额度；历史扫描结果在服务进程中缓存 5 分钟。

## 常见状态

- **读取失败**：确认 Node.js 与 Codex 命令可用，且本机 Codex 已登录，再重试刷新。
- **额度未提供**：本次账号接口没有返回对应窗口，页面按实际返回内容显示。
- **合理消耗区间暂不可用**：额度换算至少需要 4 个独立有效 5 小时窗口和合计 100 个百分点的 5 小时额度变化；活动时段估算还需要近 14 天至少 4 个有效活跃窗口。任一门槛未满足或额度换算不稳定时，服务暂不生成区间。
- **历史曲线样本不足**：当前周期没有足够的额度快照，页面回退为均速回推；不能据此判断历史数据已丢失。

## 更新与版本核对

更新源码后，使用相同的插件安装命令更新本地版本。必须在项目源码中修改，不得直接编辑已安装缓存；更新过程必须保持 Codex 主进程运行。

可使用以下命令检查本地市场源、安装版本及启用状态：

```powershell
codex plugin marketplace list --json
codex plugin list --json
```

安装版本、服务返回的页面资源、已经打开的面板必须分别核对。服务启动时会将页面读入内存，刷新用量不能单独证明页面资源版本已更新；具体更新验证见[开发说明](./开发说明.md)。
