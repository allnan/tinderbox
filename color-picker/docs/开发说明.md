# 开发说明

> 面向后续维护。功能与操作见 [使用说明](./使用说明.md)，设计细节见 [设计方案](./设计方案.md) 与 [全彩取色算法](./全彩取色算法.md)。
> 本文记录已确认的技术约束、当前实现、构建与验证方式、已知问题；计划项会明确标注「计划」。

## 1. 项目定位与状态

把「配色工坊」里的取色器独立出来的设计存档 + React 参考实现：

- 保留原取色器的全部视觉与交互（面板 / OKLCH 全彩 / 色块、透明度、中文色名、颜色小窗、pin、立即/确认后）；
- 颜色数学、中文色名、全彩算法拆成纯函数，可单独复用与测试；
- 提供可运行的演示页与 12 项自动化测试；
- 当前版本 0.1.0（2026-11）。

状态：构建、类型检查、测试、演示页构建均已通过；真实浏览器/Electron 截图在本会话受限环境中未能执行（见第 8 节）。

## 2. 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| UI | React 19.2 + TypeScript 5.9 | 只使用函数组件与 Hooks；无第三方 UI 库 |
| 色彩引擎 | 自研 OKLab / OKLCH | 零第三方色彩依赖 |
| 构建 | TypeScript 编译器 API + Rollup 4 | 纯 JS 工具链，不引入 Vite/esbuild/webpack |
| 测试 | node:test + jsdom | 纯函数测试 + 组件 DOM 测试，无浏览器 |
| 产物 | ESM + CommonJS + d.ts + CSS | `dist/index.mjs`、`dist/index.cjs`、`dist/core.mjs`、`dist/core.cjs`、`dist/color-picker.css` |

运行时依赖只有 React / React DOM（peer），其余全部为 devDependencies。

## 3. 目录与源码入口

demo/demo.css                   演示页样式

## 4. 环境硬性约束

1. **安装依赖用**：`npm install --ignore-scripts --cache .npm-cache`。
   - `--ignore-scripts`：受限环境会拦截 npm 的 postinstall 子进程；
   - `--cache .npm-cache`：默认缓存目录可能不可写。
2. **构建链保持纯 JS**：TypeScript 用编程 API（`ts.createProgram` / `ts.parseJsonConfigFileContent`），Rollup + 两个官方插件；不要引入需要原生二进制或 postinstall 的工具。
3. **库包保持 `private: true`**：避免误发布；对外分发用 `file:` 依赖或 `npm pack`。真发布时改包名 / 去 private / 配 license，并重新评估 peer 版本。
4. **核心代码不依赖 DOM**：`src/core/**` 只允许纯函数；canvas、portal、localStorage 只能出现在 `src/components/**` 或 `src/spectrum-image.ts`。
5. **构建产物不入库**：`dist/`、`.build/`、`demo/dist/`、`node_modules/`、`.npm-cache/`、`.shots/` 均在 `.gitignore` 中。
6. **测试不能依赖浏览器**：jsdom 没有 canvas，`buildSpectrumImage()` 必须优雅返回空字符串；这一点有专门的 DOM 测试覆盖。
7. **中文文档与注释**：与配色工坊保持一致。

以下命令都在 `color-picker/` 目录执行：

| 命令 | 说明 |

## 6. 构建与测试

### 6.1 库构建（`scripts/build.mjs`）

1. 清理 `.build/js` 与 `dist/`；
2. TypeScript 编译到 `.build/js`（ESM，模块解析 Bundler）；
3. Rollup 打包两个入口（`index`、`core`），各输出 ESM `.mjs` 与 CJS `.cjs`；React / React DOM 作为 external；
4. TypeScript 只输出声明文件到 `dist/`；
5. 复制 `src/components/color-picker.css` → `dist/color-picker.css`。

产物（本机实测，2026-11）：

| 文件 | 大小 |
| --- | --- |
| `dist/index.mjs` | 约 62 KB |
| `dist/index.cjs` | 约 65 KB |
| `dist/core.mjs` | 约 27 KB |
| `dist/core.cjs` | 约 28 KB |
| `dist/color-picker.css` | 约 19 KB |

### 6.2 演示页（`scripts/build-demo.mjs`）

1. 收集 `src/**/*.ts(x)` 与 `demo/**/*.ts(x)`；
2. 用 TypeScript 编译到 `.build/demo`（`rootDir: '.'`，因为源文件跨两个目录）；
3. 构建期把 `process.env.NODE_ENV` 固定为 `"production"`，让 Rollup 摇掉 React 开发分支；
4. Rollup 打成单个 IIFE（React 打进包里），复制两份 CSS 到 `demo/dist/`。

产物约 780 KB（未压缩，生产版 React）。演示页不经过 `dist/`，直接引用 `src/index`，所以改源码后重新 `npm run demo` 即可。

`demo-smoke.mjs` 会在 jsdom 里执行打包后的 `demo.js`，检查页面标题、OKLCH 区块、深色主题切换、打开取色器与 3 个模式 tab；jsdom 没有 canvas，取色器与色域图预览应优雅降级。

### 6.3 测试（`scripts/test.mjs`）

- 不使用 `node --test` 子进程：受限沙箱不允许子进程管道，会报 `spawn EPERM`；改为在当前进程依次 `import` 测试文件，`node:test` 仍负责执行与汇总；
- 测试导入的是 `dist/` 产物，所以必须先 build；
- `tests/core.test.mjs`：解析/规范化、透明度、HEX↔RGB、OKLCH 端点、WCAG、中文色名、最大色度、色域图端点、格式化；
- `tests/picker.test.mjs`：jsdom 挂载 React，覆盖打开浮层、三模式、确认模式不写回、应用写回、RGB 读数跟随预览、颜色小窗、立即模式与最近颜色、主题属性与 `defaultOpen`；
- jsdom 没有 canvas，测试里把 `HTMLCanvasElement.prototype.getContext` 固定返回 `null`，顺带验证降级路径。

### 6.4 已验证结果

node scripts/build.mjs       → 成功
node scripts/test.mjs        → 12 tests / 12 pass / 0 fail
node scripts/build-demo.mjs  → demo.js 779.7 KB
node scripts/demo-smoke.mjs  → 演示页渲染与交互通过

独立时做了这些库化改造，行为上只有第 4 条是修正：

| # | 改动 | 说明 |
| --- | --- | --- |
| 1 | 去掉对 `ui.tsx`、`palette.ts` 的依赖 | 图标与中文色名改为库内实现 |

## 8. 已知问题与限制

- **本会话无法做浏览器截图**：Electron 44 与系统 Chrome 都会在受限会话中因 Mojo 命名管道报 `拒绝访问`（`platform_channel.cc`），`--no-sandbox` / `--single-process` 均无效。因此文档中的界面图来自配色工坊原有截图，色域图由 `computeSpectrumRgba` 直接生成 PNG。需要真实截图时，在完整桌面环境打开 `demo/index.html` 或 `npm run serve`。
- **配色工坊尚未接入**：两处实现暂时并存；本会话对 `palette-studio/` 的写入被 Windows 文件权限与受限令牌拦住，已撤销接入改动。接入步骤见第 7 节。
- **仅 React**：Vue / Svelte / 原生 JS 不能直接使用组件；`./core` 纯函数可以。
- **仅 sRGB**：不支持 Display-P3 / Rec.2020；没有画色域边界。
- **首次全彩生成约 0.35 s**（Node 22 实测），在浏览器主线程上会阻塞一次；已缓存。
- **无键盘方向键取色**：画布交互以指针为主。
- **中文界面**：未做 i18n。
- **`private: true`**：未发布 npm；`npm pack` 可以生成 tgz。
- **包名占位**：`@tinderbox/color-picker` 是本地命名；正式发布前需确认 scope 与 license。
- **主题变量作用域**：浮层 portal 到 body，宿主变量必须在 `:root` / `body`。

## 10. 开发约定

- 颜色统一大写 HEX：不透明 `#RRGGBB`、半透明 `#RRGGBBAA`；输入先用 `normalizeHex` 校验。
- `src/core/**` 保持纯函数：不 import React / DOM / Node；新增算法先写测试。
- 改颜色转换只改 `core/color.ts`，不要在组件里另写一套。
- 组件里不要用 `<input type="color">`，也不要引入第三方取色/颜色库。
- 新增 CSS 颜色必须用 `--cp-*` 令牌，并提供浅色/深色默认值；不要写死主题色。
- 新增 Props 时同步：`ColorPickerProps`、使用说明的 Props 表、必要时测试。
- 改全彩参数时同步：`core/spectrum.ts`、`docs/全彩取色算法.md` 参数表、重新生成 PNG、跑测试。
- 提交前跑 `npm run check`；改文档后检查相对链接。
- 不要把 `node_modules/`、`dist/`、`.build/`、`demo/dist/`、`.shots/`、`.npm-cache/` 提交进仓库。
