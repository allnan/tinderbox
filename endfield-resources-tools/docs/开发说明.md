# 开发说明

## 当前实现

- 版本：`2.7.3+28`；Flutter/Dart，SDK 约束见 `pubspec.yaml`。
- `lib/main.dart` 为应用入口和状态协调；`lib/resource_calculator.dart` 实现资源换算；`lib/resource_history.dart` 实现记录、游戏日和趋势汇总；`lib/resource_store.dart` 实现本地读写、备份、迁移和冲突保护；`lib/lan_sync.dart` 与 `lib/ui/lan_sync_dialog.dart` 实现局域网同步及更新结果提示。
- `android/` 和 `windows/` 保存平台工程源码；`assets/resources/` 保存随应用打包的资源图标。
- Windows 使用 `Platform.resolvedExecutable` 的父目录保存账本；Android 通过原生方法通道使用 `noBackupFilesDir`。两端数据路径不同，源代码迁移不会搬动运行数据。
- Windows 便携包包含 EXE、DLL、Flutter `data/` 和用户文档。打包目录和 ZIP 位于 `release/`，不纳入 Git。

## 构建与测试

以下命令均在项目根目录执行：

```powershell
flutter pub get
flutter analyze
flutter test
flutter build windows --release
./tool/package_portable.ps1
```

Windows 打包需要 Visual Studio x64 VC Runtime 分发文件。脚本可自动查找；无法找到时用 `-RuntimeDirectory` 明确指定该运行库目录。

打包默认在 `release/` 生成 `终末地资源账本-2.7.3/` 目录和同名 `.zip`；输出目录或 ZIP 已存在时会拒绝覆盖，重复打包必须使用 `-OutputDirectory` 指定不存在的新目录，命令示例见[项目首页](../README.md)。只有明确要求部署时才加 `-InstallAfterPackage`，并同时传入 `-InstallDirectory`。例如：

```powershell
./tool/package_portable.ps1 -InstallAfterPackage -InstallDirectory 'D:\Apps\EndfieldLedger'
```

上例 `D:\Apps\EndfieldLedger` 为虚构示例目录，运行时必须替换为用户明确指定的目标。直接调用 `tool/install_portable.ps1` 时也必须同时指定 `-BundleDirectory` 和 `-InstallDirectory`。部署脚本在覆盖程序文件前检查账本格式，保留目标账本，并拒绝覆盖未验证的数据格式。

`tool/generate_icons.ps1` 只用于从 `docs/app_icon_1024.png` 重新生成平台图标，不属于常规构建步骤。不要把 `build/`、`release/`、`.dart_tool/`、`.backups/`、Android 本机 SDK 配置或运行账本纳入版本控制。

## 验证边界

源项目的 `docs/验证记录.md` 记载 2.7.3 的静态分析、44 项测试和 Windows/Android 构建结果。局域网同步测试使用两个模拟账本端点在本机回环地址通信，不等同于真实电脑与手机之间的同步验证。测试覆盖和本次迁入复核结果见[验证记录](./验证记录.md)。

Windows 视觉回归测试使用固定构造的账本夹具，与仓库内 `test/goldens/dashboard_desktop.png` 对照。修改界面后如需更新快照，在 Windows 上运行 `flutter test --update-goldens test/visual_golden_test.dart`，审阅更新结果后再纳入变更。

## 已知限制

- 本机回环同步测试不验证真实局域网发现、防火墙配置或跨设备兼容性。账本格式变更须先用构造副本验证迁移。
- 资源图标来源与游戏规则会随游戏更新变化；更新换算规则前必须重新核验来源和口径。
- 程序不连接项目服务器。Windows 防火墙与局域网设备发现依赖用户设备的网络设置。
