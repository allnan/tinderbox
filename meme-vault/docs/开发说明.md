# 开发说明

> **状态：已暂停（2026-11-19）**。代码和 v0.1.0 构建保留；恢复开发前先阅读本页“已知问题与待验证”。

本文记录表情包仓库的技术实现、数据格式、整理与撤回机制、构建验证方式和已知问题。面向使用者的操作说明见[使用说明](./使用说明.md)。

## 1. 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 桌面外壳 | Tauri 2.12（Rust 2024 edition） | Windows 客户端，窗口由 `WebviewWindowBuilder` 手动创建，便于指定 WebView2 用户数据目录 |
| 前端 | React 19 + TypeScript 5.9 | 双入口：主窗口 `main.tsx` + 快捷窗口 `quick.tsx`，无路由库；主视图状态由 `App.tsx` 管理 |
| 构建 | 自研 `scripts/build-web.mjs` | TypeScript 转译 + Rollup 打包 + 自写 CSS 收集插件；不依赖 esbuild 子进程 |
| 原生能力 | Rust + tauri-plugin-dialog / clipboard-manager / opener / global-shortcut | 文件选择、剪贴板、打开目录、全局热键 |
| 图片处理 | `image` crate | 读取尺寸、生成缩略图、计算 dHash、复制图片时转 RGBA |
| 备份 | `zip` crate | 导出/导入 zip；图片以 Stored 方式写入，元数据 Deflated |
| AI | `reqwest` + OpenAI 兼容 Chat Completions | 视觉模型发送缩略图 data URL，文本模型只发文件名/尺寸 |
| 存储 | 本机 JSON + 文件目录 | 无数据库依赖，便于备份和手工检查 |

选择逐项文件 + JSON 的理由：表情包以原图文件为主，元数据规模小；直接落盘便于用户备份、迁移和排查，也避免引入数据库迁移成本。

## 3. 数据目录与格式

默认目录：exe 同级的 `userdata/`（便携模式），在启动时通过写探针确认可写；若不可写，退回 `%APPDATA%\com.tinderbox.memevault\data`。早期版本把数据直接放在 `%APPDATA%\com.tinderbox.memevault`，启动时会优先识别并继续使用。环境变量 `MEME_VAULT_DATA` 可覆盖（测试与自定义目录使用）。

```text
data/
├─ library.json     素材、分类、分组、待确认/历史提案
├─ library.json.bak 上一次成功写入的副本
├─ settings.json    AI 配置、复制方式、卡片大小、自动备份开关（含明文 API Key）
├─ history.json     整理记录（数组，最多保留 5000 条）
├─ images/          原图，文件名为 <sha256>.<ext>
├─ thumbs/          缩略图，文件名为 <sha256>（PNG 带透明 / JPEG 无透明）
├─ backups/         导出的 zip 与导入的旧记录存档
└─ webview/         WebView2 用户数据（主窗口 + quick/ 快捷窗口，缓存，可删除）
```

关键约束：

- 素材以 `sha256` 做内容寻址，导入去重；缩略图与原图共用同一个哈希。
- 删除为软删除（`deleted=true`），原图不删除，记录可通过历史撤回；暂未实现物理清理。
- 所有写操作在 `Mutex<Store>` 内串行执行，写入使用临时文件 + rename。
- 媒体通过自定义协议提供：Windows 下为 `http://meme.localhost/image/<sha>` 与 `/thumb/<sha>`；协议处理函数只接受 64 位十六进制哈希，避免路径穿越。

## 4. 快捷窗口与相册首页

- **快捷窗口**：启动时创建隐藏的 `quick` 窗口（无边框、跳过任务栏、独立 WebView2 数据目录），加载 `quick.html`。是否置顶读取 `settings.quickAlwaysOnTop`（默认 `false`，不强制置顶）；快捷窗口右上角图钉调用 `set_quick_always_on_top`，同时持久化设置并调用 `set_always_on_top`。Rust 侧用 `global-shortcut` 注册 `Ctrl+Shift+Space`，按下时按鼠标位置显示/隐藏窗口；关闭按钮被拦截为隐藏，避免下次热键失效。Tauri 对初始隐藏窗口的 `show()` 在部分环境只更新状态、不设置 `WS_VISIBLE`，因此显示后再调用 Win32 `ShowWindow` 兜底。主界面“快速使用”按钮调用 `show_quick` 命令，作为热键冲突时的兜底。
- **快捷选择**：`QuickPicker` 默认按最近使用排序，支持收藏/全部/分类筛选、搜索、方向键和 Enter；单击条目调用 `copy_item` 后立即 `hide()`，窗口重新获得焦点时刷新一次素材库。
- **相册首页**：主窗口默认 `view=albums`。相册卡片由系统相册（全部/待整理/收藏）与分类/分组生成，封面取前 4 张缩略图；有内容的相册在上，空白相册收进下方紧凑区。最近使用的 12 张单独成段，便于直接点用。
- **拖动整理**：卡片指针拖动超过 7px 才进入拖拽；松手时用 `elementFromPoint` 找带 `data-drop-target` 的相册卡片或侧栏分类/分组，复用 `batch_update`。相册卡片与侧栏共用同一套拖放逻辑。
- **单击复制**：主界面单击卡片延迟 160ms 复制；双击会在 160ms 内清除定时器并打开大图，避免双击触发两次复制；详情通过卡片右上角眼睛按钮打开，不再抢占单击。
- **构建**：`build-web.mjs` 分别打包 `app.js` 与 `quick.js`（各自自包含），生成 `index.html` / `quick.html`；Tauri 生产构建必须启用 `custom-protocol` 特性。

## 5. 整理流程与可撤回机制

整理分为「生成建议 → 人工确认 → 应用 → 可撤回」四步，AI 与本地规则共用同一套提案模型。

1. **生成**：`propose_rules` / `propose_ai` 只创建 `Proposal`（`status=pending`），不修改素材。同一来源的新提案会移除旧提案中重叠条目的建议，避免重复。
2. **确认**：前端逐条显示建议（分类、分组、标签、改名、置信度、理由），用户可跳过条目或修改分类/分组/标签；`update_proposal` 只写入提案。
3. **应用**：`apply_proposal` 在锁内解析新分类/分组、合并标签、更新素材状态，生成 `organized.apply` 留痕并记录前后快照；只有同时产生变化的条目才计数。
4. **撤回**：`revert_history` / `revert_proposal` 先比较当前素材状态与记录中的 `after` 快照：
   - 全部一致 → 直接还原；
   - 存在差异 → 返回 409 + 冲突素材 ID，前端展示冲突列表；
   - 用户确认“强制撤回”后跳过检查，仍按 `before` 快照还原。

撤回同时会把关联提案状态改为 `reverted`，避免同一条建议被重复应用。目录类操作（新增/改名/删除分类分组）也有对应留痕；删除分类/分组时会记录受影响素材的快照，撤回时恢复目录并还原归属。

素材库写入使用临时文件 + rename，并在每次成功写入前保留 `library.json.bak`。若 `library.json` 损坏，启动时会尝试用 `.bak` 自动恢复，并保留损坏文件为 `library.corrupt-<时间>.json`；没有可用备份时拒绝启动，避免用空库覆盖原始数据。

## 6. AI 接口约定

- 请求：`POST {baseUrl}/chat/completions`，Bearer API Key，`temperature=0.2`，优先 `response_format={"type":"json_object"}`；若服务返回 400 则自动重试一次不带该字段。
- 输入：系统提示词限定“只输出 JSON”，用户消息包含现有分类/分组、素材清单（id、文件名、尺寸、格式），视觉模式下附带缩略图 data URL。
- 输出结构：

```json
{"items":[{"id":"...","category":"已有分类名","newCategory":"","groups":[],"newGroups":[],"tags":[],"name":"","confidence":0.8,"reason":"..."}]}
```

- 解析时会过滤未知 id、重复 id、不存在的分类/分组名称，限制标签数量与长度；未知名称作为“新分类/新分组”进入提案，应用时才真正创建。
- 单批上限 24 张，默认 12；前端提示剩余数量，可再次触发继续整理。

## 7. 备份格式

zip 根目录：

```text
manifest.json       app=meme-vault、格式版本、创建时间、素材数
library.json        分类/分组/素材元数据（不含提案）
settings.json       非敏感设置；apiKey 仅为 [REDACTED_SECRET] 或空
history.json        整理记录存档（导入时不合并进当前时间线）
images/<sha>.<ext>  原图
thumbs/<sha>        缩略图
```

导入只接受上述白名单条目，校验 sha256 与库中记录一致；恢复采用合并语义：相同哈希跳过、分类分组按名称合并、恢复动作写入一条可撤回的 `backup.import` 记录。旧记录会另存为 `backups/imported-history-*.json`。

## 8. 构建与验证

```powershell
npm install
npm run typecheck     # 前端 TypeScript 类型检查
npm run test          # cargo test：规则、AI 解析、存储、提案/撤回、备份
npm run ui-smoke      # jsdom 加载主界面 bundle，用模拟 IPC 跑界面冒烟
npm run quick-smoke   # jsdom 加载快捷窗口 bundle，验证渲染/复制/收起
npm run build:web     # 仅构建前端到 dist/
npm run build         # 前端 + release，输出 release/MemeVault.exe，并尝试投放到本地 .deploy-target 目录
npm run deploy        # 只投放 release/MemeVault.exe 到 .deploy-target 目录（失败会返回非零）
npm run smoke         # 对已启动且开放 9223 调试端口的客户端执行 CDP 冒烟
```

`npm run dev` 会启动 127.0.0.1:7411 的静态服务器与 `cargo run` 窗口。所有构建均使用 Windows GUI 子系统，不显示控制台；启动失败时 panic 信息写入 `%TEMP%\meme-vault-crash.log`。

发布构建必须启用 `custom-protocol` 特性：`npm run build` 已自动附加 `--features custom-protocol`。发布配置 `tauri.conf.json` 已移除 `devUrl`，开发时由 `scripts/dev.mjs` 通过 `TAURI_CONFIG` 注入 `http://127.0.0.1:7411`；release 二进制中不包含该地址。若手动 `cargo build --release` 漏掉 `custom-protocol`，exe 会尝试加载开发地址并显示“拒绝连接”，不会使用内嵌前端。

发布版是单个便携 exe；首次运行在 exe 同级创建 `userdata/`（目录不可写时退回 `%APPDATA%\com.tinderbox.memevault\data`）。`npm run build` 会读取项目根目录的 `.deploy-target`（本地配置，已忽略）尝试投放一份；投放前用 `taskkill` 结束 `MemeVault.exe` / `meme-vault.exe`，只覆盖 exe，保留同级 `userdata/`。可用 `MEME_VAULT_DEPLOY_DIR` 覆盖目录、`MEME_VAULT_SKIP_DEPLOY=1` 跳过；也可运行 `npm run deploy` 或双击 `deploy-to-desktop.cmd`。

冒烟测试依赖 WebView2 远程调试：

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9223"
$env:MEME_VAULT_DATA="...\tmp\tauri-data"
.\release\MemeVault.exe
node scripts/smoke.mjs
```

冒烟覆盖：相册首页、粘贴导入、素材展示与自定义协议、详情抽屉、规则整理提案、应用、撤回、备份导出、设置页、控制台异常检查，并输出 `docs/assets/` 截图。快捷窗口另用桌面截图与剪贴板检查验证。

若当前环境无法创建 WebView2（例如受限沙箱返回 E_UNEXPECTED），可先运行 `npm run selftest` 验证 release 二进制的数据链路。本次已在 full access 下用 release 二进制完成真实窗口冒烟；`npm run dev` 与 `npm run build` 使用同一套前端资源，selftest 不覆盖界面。

## 9. 已知问题与待验证

- **剪贴板两种方式待真机人工验证**：图片复制使用 tauri-plugin-clipboard-manager，文件复制使用 Win32 CF_HDROP；自动化测试未覆盖真实粘贴到微信/QQ。
- **真实 AI 服务未接入验证**：当前验证使用假数据与解析单测；需要用户提供 Key 后验证 401/429、视觉输入和不同兼容服务的 JSON 输出差异。
- **超大素材库性能**：前端一次性加载全部素材元数据；卡片使用懒加载 + `content-visibility`，快捷窗口限制前 180 张，但主网格尚未做真正的虚拟滚动。超过约 5000 张时仍建议分页/虚拟列表。
- **回收站**：目前只有软删除 + 历史撤回，没有独立的清理与恢复入口。
- **多实例**：未实现单实例锁，同时打开两个窗口会并发写同一数据目录（写操作有锁，但跨进程不互斥）。
- **全局热键冲突/全屏遮挡**：`Ctrl+Shift+Space` 可能被其他软件占用；注册失败会写 `%TEMP%\meme-vault-quick.log`，此时仍可从主界面“快速使用”按钮打开。部分全屏独占游戏或提权前台程序会遮挡悬浮窗或屏蔽热键，建议在桌面/窗口化场景使用。
- **备份包大小**：上传解析上限 512 MB，超大素材库需要分批导出（未实现）。
- **单文件导入上限**：`import_bytes` 走 base64 IPC，仅用于剪贴板粘贴，大小受前端内存限制。
