> 面向后续开发与维护。运行与操作见 [使用说明](./使用说明.md)，架构、数据模型与扩展指南见 [项目交接](./项目交接.md)。
> 本文件记录已确认的技术约束、当前实现、开发与构建方式、验证方法及已知问题；待验证事项与建议会明确标注。

## 1. 项目概况与技术栈

「配色工坊」（PaletteStudio）是一个 Windows 桌面端前端配色管理工具：为多个前端项目维护品牌主色、色板、浅色/深色语义主题与控件配色，支持从主色用 8 种方式生成配色、生成 50–950 明暗色阶与 18 个语义 Token，并把结果导出成 7 种前端代码格式。

- 运行时：Electron 44.7.0（Windows 便携运行时位于项目根目录 `runtime/`，不入库）
- 渲染层：React 19.2 + TypeScript 5.9，无第三方 UI 库
- 构建：纯 JavaScript 工具链（TypeScript 编译器 API + Rollup 4 + Terser + 自研 CSS 收集注入，无 Vite/esbuild/webpack）
- 测试：自研极简 testkit（核心单测）+ jsdom（渲染冒烟）
- 色彩计算：自研 OKLab / OKLCH 色彩引擎，零第三方色彩依赖
- 打包：`scripts/package.mjs`（@electron/asar 生成 app.asar）+ PowerShell（rcedit、快捷方式、zip）+ C# 启动器
- 版本：1.0.0（2026-11-06）；`src/` 约 1.9 万行（含测试与样式），`electron/` 主进程约 380 行
- 当前状态：全部功能已实现并通过验证（见第 5 节），无已知阻塞性缺陷

源码入口：

- `electron/main.cjs`：主进程（窗口、IPC、数据读写、验收参数、独立预览窗口）
- `electron/preload.cjs`：contextBridge 暴露 `window.desktop`
- `src/main.tsx` → `src/App.tsx`：渲染入口与外壳路由（projects / workspace / settings）
- `src/shared/types.ts`：数据模型唯一真源

## 2. 环境硬性约束

1. **构建链是纯 JS 的**：TypeScript 以编程方式编译（`ts.createProgram`）+ Rollup + Terser，**不要引入 Vite/esbuild/webpack 等需要原生二进制或子进程的构建工具**。
2. **安装依赖必须用**：`npm install --ignore-scripts --cache .npm-cache`。
   - `--ignore-scripts`：部分受限环境会拦截 npm 的 postinstall 子进程（EPERM）；
   - `--cache .npm-cache`：npm 默认缓存在用户目录，受限环境不可写。
   - 安装后 `node_modules/electron` 里**没有** Electron 二进制是正常的，本项目用项目根目录 `runtime/` 里的运行时。
3. **Electron 运行时来自项目根目录的 `runtime/`**（Electron 44.7.0 win32-x64，`PaletteStudio.exe` + dll + `resources/default_app.asar`）。`node_modules/electron` 只用来读取版本号/路径，不要依赖它的二进制。`runtime/` 不入库，从远程克隆后需自行准备（见 [项目交接](./项目交接.md) 第 2.2 节）。
4. **受限沙箱中 Electron 无法启动**（Chromium 需要命名管道/进程沙箱）。需要真实运行/截图时：优先使用主进程内置的验收参数（见第 4 节）；若环境限制进程启动，请在具有完整桌面权限的环境中运行，或直接双击打包版。启动前务必清除 `ELECTRON_RUN_AS_NODE` 环境变量（某些宿主会注入，会让 Electron 被当成 Node 运行）。
5. **`.ps1` 脚本一律保存为 UTF-8 with BOM**（Windows PowerShell 5.1 需要 BOM 才能正确解析中文）；用工具写完后再用 PowerShell 转一次 BOM。
6. **应用数据目录不可写时会回退到程序目录 `userdata/`**（见启动器说明）。这是刻意设计，不要"修复"成只写 `%APPDATA%`。
7. **运行打包脚本前确认 csc.exe 存在**：启动器编译依赖系统自带 .NET Framework 4.x 的 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`（Windows 10/11 默认具备）。
8. **所有临时文件、诊断输出、演练产物必须放在项目目录内**（如 `.shots/`、`.diagnostics/`、`.tmp-*`），用完清理；禁止在项目目录之外创建临时文件与目录，工作区之外只允许读取。
9. **仓库只提交源码与文档**：`node_modules/`、`runtime/`、`release/`、`dist/`、`.build/`、`build/` 等均为本地忽略产物（见 `.gitignore`），不要提交。

### 2.1 为什么是纯 JS 构建链

- **TypeScript** 以编程方式调用（`ts.createProgram` + emit），输出 CommonJS 到 `.build/app/`
- **Rollup**（纯 JS）+ `@rollup/plugin-node-resolve` + `@rollup/plugin-commonjs` 打包为单文件 IIFE
- CSS 不单独打包：`scripts/build.mjs` 自动收集 `src/**/*.css`，复制到 `dist/` 并注入 `index.html`
- 单元测试：自研极简 testkit（`src/core/_testkit.ts`），`scripts/test.mjs` 编译后逐个 require 执行
- 渲染冒烟：jsdom 中执行 `dist/assets/app.js`，逐页检查 DOM 与运行时错误（不需要 Electron）
- 依赖安装使用 `--ignore-scripts`：Electron 的 postinstall 在受限环境中无法运行，因此 Electron 运行时来自 `runtime/`，安装 `electron` 包仅为获得版本信息

## 4. 真实运行与截图验收

```powershell
# 开发运行（构建 + 启动 Electron，脚本会清掉 ELECTRON_RUN_AS_NODE）
powershell -File scripts/dev.ps1            # 会先 build
powershell -File scripts/dev.ps1 -SkipBuild # 只启动

# 自动化验收参数（主进程 electron/main.cjs 内置）
.\runtime\PaletteStudio.exe . --screenshot=.shots\home.png --smoke-log=.shots\smoke.log --user-data-dir=.electron-userdata
.\runtime\PaletteStudio.exe . --shots-dir=.shots --smoke-log=.shots\smoke.log --user-data-dir=.electron-userdata
```

- `--shots-dir` 会自动点击：项目总览 → 打开项目 → 6 个标签页 → 设置页（含浅色主题、新建项目弹窗），并验收界面预览：停靠预览面板（桌面/手机，含真实鼠标点击校验）→ 独立预览窗口，逐页截图后退出
- `--screenshot=<path>`：等待渲染完成后截图并退出
- `--smoke-log=<path>`：收集渲染进程 console 与 DOM 快照
- 若独立预览窗口未创建，日志会写 `[preview-window] 预览窗口未创建`
- 注意：`.shots/`、`.electron-userdata/` 均在 `.gitignore` 中

运行前先清除宿主可能注入的环境变量（否则 Electron 会被当成 Node 运行）：

```powershell
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
Remove-Item Env:ELECTRON_NO_ASAR -ErrorAction SilentlyContinue
```

## 7. 开发约定

- **TypeScript strict**；`import type` 导入类型；中文注释、中文 UI 文案。
- **核心逻辑必须是纯函数**（`src/core/` 不依赖 React/DOM/Node），所有颜色操作走 `color.ts`，不要另写转换。
- **颜色以大写 HEX 存储**：不透明 `#RRGGBB`、带透明度 `#RRGGBBAA`；输入用 `normalizeHex`（兼容 8 位）校验后再落库。自动生成的主题/色阶仍为不透明色。
- **视图只通过 `useApp().actions` 修改数据**；不要直接改 props/全局对象。
- 优先复用 `src/components/ui.tsx` 与 `src/components/color-ui.tsx`；UI 颜色一律用 CSS 变量（`--bg-panel` `--text-2` `--accent` …），**禁止写死暗色/亮色**。
- 每个视图的 CSS 放 `src/views/<name>.css`，类名加视图前缀（`palette-` `theme-` `controls-` `contrast-` `export-` `history-`），构建会自动收集并注入。
- **不引入第三方 UI/色彩库**；确需新增依赖时必须同时考虑纯 JS 构建链与 `--ignore-scripts`。
- **界面预览三处复用**（主题页内嵌 / 停靠面板 / 独立窗口）都渲染 `ThemePreview`，不要各写一份；预览颜色只来自 `getPreviewColors(theme, mode)`，禁止写死颜色。停靠面板必须保持「让位不遮挡」，不要再加全屏遮罩/覆盖层。
- 修改 `src/shared/types.ts` 时：`AppData.version` +1，并在 `normalizeAppData` 中补默认值/迁移；旧数据不能崩。
- 不要绕过安全设置：渲染层保持 `contextIsolation: true`、`nodeIntegration: false`；`main.cjs` 已禁止外部导航。
- 启动器会强制 `--no-sandbox`（受限会话兼容），这是产品取舍；不要"顺手"加回沙箱导致用户又打不开。
- 设计系统：所有颜色使用 CSS 变量（`--bg-panel`、`--text-2`、`--accent` 等），深浅主题通过 `html[data-app-theme]` 切换；`--accent` 由当前项目主色动态注入（`App.tsx`）。

## 8. 已知坑（踩过的）

| 现象 | 原因 / 处理 |
| --- | --- |
| Electron 启动即崩、错误码 `0xC0000003` | Chromium 沙箱在受限会话无法初始化 → 用启动器/`--no-sandbox`，见 [项目交接](./项目交接.md) 第 9.4 节 |
| 双击 exe 闪退、日志 `Lock file can not be created 0x5` | 默认用户数据目录不可写 → 启动器自动回退程序目录 `userdata/`，不要改成只写 `%APPDATA%` |
| Electron 被当成 Node 运行（`ipcMain.handle` undefined） | 宿主注入 `ELECTRON_RUN_AS_NODE=1` → 启动前清除该环境变量（启动器已处理） |
| `npm install` 报 EPERM / spawn EPERM | 用 `--ignore-scripts` + `--cache .npm-cache`；本构建链不需要 postinstall |
| `.ps1` 中文乱码/解析报错 | 保存为 UTF-8 with BOM（用 PowerShell 转），别用无 BOM 的 UTF-8 |
| `.build` 被并发脚本清空导致构建偶发 ENOENT | 多个构建/测试并行时可能；重跑一次即可，验收时串行执行 |
| Windows PowerShell 5.1 下 `&&` 不可用 | 用 `;` 或分开执行；`npm run check` 内部由 npm 处理 |
| 独立预览窗口空白/不显示内容 | 必须在项目工作台打开项目且已生成主题（无主题时预览显示等待状态）；确认 `dist/` 已构建，主窗口先启动（预览窗口依赖主窗口推送数据） |
| 预览窗口打开后截图脚本挂起 | 截图验收里预览窗口由主进程 `previewWindow.close()` 关闭；若手动结束进程，先清理残留 `PaletteStudio` 进程再重跑 |
| 颜色输入弹出的是 Windows 灰白系统取色器 | 说明又用了 `<input type="color">`；项目统一用 `components/ColorPicker.tsx`（自定义浮层），不要再引入原生 color input |
| 设置了透明度但显示不出来 | 确认 `normalizeHex` 返回的是 8 位 `#RRGGBBAA`；主题 Token 生成本身不透明，透明度只对色板/控件自定义色/取色器生效 |
| 全彩图蓝紫区有折痕/色带 | 属 sRGB 色域凹口（hue 约 250–290°）的正常特征；渲染已用 720×360 + Bayer 抖动 + 最大色度场平滑，若再放大仍见格子可再提高分辨率或加大平滑半径 |

## 11. 构建、测试与打包流水线

构建链（`scripts/build.mjs`）步骤：

1. 清理 `.build/app` 与 `dist/`（只清自己的产物目录，避免与并行测试/类型检查互相干扰）；
2. TypeScript 编译到 `.build/app/`（CommonJS）；
3. Rollup 打包 `src/main.tsx` 为 `dist/assets/app.js`，Terser 压缩；
4. 收集 `src/**/*.css` 复制到 `dist/` 并生成 `index.html` 样式引用。

打包流水线（`scripts/package.ps1`，7 步）：

1. 构建渲染进程（`scripts/build.mjs`）；
2. 生成图标 `build/icon.ico`（缺失时调用 `python scripts/make-icon.py`）；
3. 按需编译启动器 `build/PaletteStudioLauncher.exe`（C#，依赖 .NET Framework 4.x 的 `csc.exe`）；
4. `scripts/package.mjs` 组装 `release/PaletteStudio/`：`dist/` + `electron/` + `build/icon.ico` → app.asar；复制 `runtime/`（主体改名 `PaletteStudioCore.exe`）；放入启动器 `PaletteStudio.exe`；
5. rcedit 写入图标与版本信息；
6. 创建 `release/PaletteStudio/配色工坊.lnk` 快捷方式；
7. `Compress-Archive` 生成 `release/配色工坊-<version>-win64.zip`。

### 关于打包版启动与 Chromium 沙箱

Chromium 的子进程沙箱在部分受限 Windows 会话（远程桌面、企业管控终端、某些自动化运行器）中无法初始化，表现是**双击 exe 直接闪退且没有窗口**（错误码 `0xC0000003`）。命令行加 `--no-sandbox` 可以正常启动。

因此打包版采用「启动器 + 程序主体」结构：

- `PaletteStudio.exe`：`scripts/launcher.cs` 编译出的 C# 启动器（约 90KB，无控制台窗口）。双击后它会：
  1. 清除 `ELECTRON_RUN_AS_NODE` / `ELECTRON_NO_ASAR` 等可能被宿主注入的变量；
  2. 以 `--no-sandbox --disable-gpu-sandbox` 参数启动 `PaletteStudioCore.exe`；
  3. 透传用户传入的命令行参数（如 `--screenshot`）；
  4. 优先使用 `%APPDATA%\PaletteStudio` 作为用户数据目录；若它不可写（受限会话常见），自动回退到程序目录下的 `userdata\` 便携目录，且下次启动会直接沿用便携目录；
  5. 主体 7 秒内异常退出时换数据目录重试，仍失败则弹窗提示错误码，并写入同目录 `启动日志.log`。
- `PaletteStudioCore.exe`：真正的 Electron 程序（原运行时改名）。
- `启动（兼容模式）.cmd`：绕过启动器直接拉起主体，用于排查启动器被安全软件拦截的情况。
- `配色工坊.lnk`：指向启动器。

`--no-sandbox` 只在本地加载打包内容（应用禁止外部导航与远程加载），对离线工具风险可控。启动器编译需要系统自带 .NET Framework 4.x 的 `csc.exe`（Windows 10/11 默认具备）。

## 12. 数据与持久化

- 主进程把 `AppData` 写到 `app.getPath('userData')/data/palette-studio.json`：
  - 正常环境：`%APPDATA%\PaletteStudio\data\palette-studio.json`
  - 受限环境（默认目录不可写时由启动器回退）：`<程序目录>\userdata\data\palette-studio.json`
  - 实际路径可在应用「设置 → 数据与存储」查看
- 保存前把旧文件复制为 `palette-studio.backup.json`，再写临时文件并原子重命名；读取失败时自动尝试备份
- 窗口位置/尺寸/最大化状态保存在 `userData/window-state.json`
- 渲染进程通过 `window.desktop.saveState/loadState` IPC 访问；在浏览器（无 Electron）中回退到 localStorage
- 保存时机：数据变化 500ms 防抖；首次加载完成强制保存一次；窗口关闭前 `beforeunload` 尽力保存
- 数据结构变更：递增 `CURRENT_DATA_VERSION` 并在 `normalizeAppData` 中补默认值/迁移（旧数据不能崩）
