# 核心模块契约（core）

> **实现状态：已完成（v1.0.0，2026-11-06）。** 本文件是最初的功能契约，`src/core/` 已按此实现并通过 131 项单元测试（含透明度扩展）；如需了解当前实际架构、数据模型与扩展方式，请阅读 `docs/项目交接.md`。
> 实现中的少量偏差与取舍（例如 `DEFAULT_EXPORT_OPTIONS.mode='both'`、`_testkit` 无 `.not`、PaletteView 未复用 `ScaleStrip`）记录在 `docs/项目交接.md` 第 12.1 节。
> 后续实现已扩展：颜色支持 `#RRGGBBAA` 透明度（`parseColorAlpha` / `alphaOf` / `normalizeColor` / `setAlphaHex` / `rgbaToHex`），`formatColor` 与 `contrastRatio` 均按透明度处理。

本文件约束 `src/core/` 下纯函数模块的公开 API。UI 视图、导出和测试都依赖这里的签名，**不得擅自改名或改签名**；需要调整时先报告 Lead。

## 通用规则

- 全部为纯函数 / 纯数据模块，不依赖 React、Node、DOM（测试文件除外）。
- TypeScript `strict` 模式；使用 `import type` 导入类型。
- 所有用户可见文案使用简体中文，注释使用中文。
- 不新增任何第三方依赖，不访问网络、文件系统或子进程。
- 颜色一律使用大写 `#RRGGBB`；输入兼容 `#RGB`、`rgb()`、`hsl()`（可复用 `src/core/color.ts` 的 `normalizeHex` / `parseColor`）。
- 已存在的 `color.ts`（Lead 编写，**只读**）提供：`normalizeHex`、`parseColor`、`rgbToHex`、`hexToRgb`、`rgbToHsl`、`hslToRgb`、`hexToHsl`、`hslToHex`、`rgbToOklch`、`oklchToRgb`、`hexToOklch`、`oklchToHex`、`formatColor`、`relativeLuminance`、`contrastRatio`、`getContrastResult`、`bestTextOn`、`isDark`、`mix`、`lighten`、`darken`、`withLightness`、`rotateHue`、`adjustSaturation`、`withAlpha`、`blendOver`、`hueDistance`、`perceptualLightness`、`nearestStep`、`clamp`。
- 数据模型见 `src/shared/types.ts`（只读）。
- 测试使用 `src/core/_testkit.ts` 的 `test/describe/expect`，测试文件命名为 `*.test.ts`，由 `node scripts/test.mjs` 统一执行。
- 提交前必须运行：`node scripts/typecheck.mjs`、`node scripts/test.mjs`（在工作区根目录）。

## 一、`src/core/palette.ts`（负责人：palette-themer）

```ts
import type { GeneratedTheme, PaletteColor, ThemeMethod, ThemeMethodId, ThemeScale } from '../shared/types'

export type HarmonyType =
  | 'complementary'      // 互补色
  | 'analogous'          // 相邻色
  | 'triadic'            // 三角配色
  | 'split-complementary' // 分裂互补
  | 'tetradic'           // 四角配色
  | 'monochromatic'      // 单色明暗
  | 'shades'             // 暗调（加深）
  | 'tints'              // 亮调（减淡）

export interface HarmonyInfo {
  type: HarmonyType
  label: string        // 中文名称，如「互补色」
  description: string  // 一句话说明，如「色轮正对面，视觉冲击最强」
}

export const HARMONIES: HarmonyInfo[]              // 顺序固定，8 个
export const TONAL_STEPS: number[]                 // [50,100,200,300,400,500,600,700,800,900,950]
export const THEME_METHODS: ThemeMethod[]          // 5 个：balanced/vivid/muted/neutral/high-contrast，中文 label
export function nextColorId(): string              // 唯一 id，如 'c-lq3k2-8f1a'
export function createPaletteColor(
  hex: string,
  name?: string,
  source?: PaletteColor['source'],
): PaletteColor                                   // 自动 normalizeHex、生成 id；name 缺省用 nameWithLevel(hex)

export function generateHarmony(baseHex: string, type: HarmonyType): PaletteColor[]
// 数量与顺序：
// complementary 2；analogous 5；triadic 3；split-complementary 3；
// tetradic 4；monochromatic 5；shades 5；tints 5
// 第一个元素是主色（name 固定为「主色」，source 'harmony'），其余 name 用 nameWithLevel()
// 每个元素 hex 为合法 #RRGGBB，且互不重复（除单色系可能出现近似色）

export function generateTonalScale(
  baseHex: string,
  options?: { steps?: number[]; chromaScale?: number; lightnessRange?: [number, number] },
): Record<string, string>
// 基于 OKLCH 生成色阶：key 为档位字符串（'50'...'950'），value 为 #RRGGBB。
// 默认 steps=TONAL_STEPS；50 最亮、950 最暗，明度分布均匀（参考 Tailwind/Material）。
// 色度在两端自然收敛（亮端和暗端降 chroma），保持色相稳定。

export function generateScales(baseHex: string): ThemeScale[]
// 返回 8 个色阶，key/label 固定为：
// primary 主色 / secondary 辅助色 / accent 强调色 / neutral 中性色 /
// success 成功 / warning 警告 / error 错误 / info 信息
// 每个 ThemeScale 包含 light 与 dark 两套 Record<string,string>（键同 TONAL_STEPS）。
// 深色模式色阶允许与浅色模式有轻微差异（chroma +5%~10% 之类），但必须保持同色相。

export function generateSemanticTheme(baseHex: string, method?: ThemeMethodId): GeneratedTheme
// 生成语义 token（light/dark 两套）与色阶。
// tokens 的 key 必须与 src/shared/types.ts 的 THEME_TOKEN_KEYS 完全一致（18 个）：
// primary, primary-hover, primary-active, on-primary, secondary, accent,
// background, surface, surface-raised, border, border-strong,
// text-primary, text-secondary, text-disabled, success, warning, error, info
// 要求：
// - light 模式 background 接近白色但对主色有极轻微色偏；dark 模式为深灰蓝/深色（不要纯黑）。
// - text-primary 与其所在背景对比度 ≥ 7:1（light 与 dark 都要满足，测试会验证）。
// - on-primary 与 primary 对比度 ≥ 4.5:1（测试会验证）。
// - method 影响明度/饱和度基调：vivid 更鲜艳，muted 更柔和，neutral 背景更中性，
//   high-contrast 文字/边框对比更强，balanced 为默认自然方案。
// - createdAt 使用 Date.now()。

export function suggestPalette(baseHex: string): PaletteColor[]
// 一键推荐整套色板，返回 12~18 个 PaletteColor：
// 主色及其关键明暗阶（如 300/500/700）、辅助色、强调色、成功/警告/错误/信息、
// 中性背景/表面/文字/边框。名称使用中文（如「主色 500」「正文字色」「成功」）。

export function colorDisplayName(hex: string): string
// 根据颜色给中文色名（12~16 个色系族），例如：
// #4F7CFF → '靛蓝'；#FF7A00 → '朱橙'；#22C55E → '翠绿'；
// 低饱和（chroma < 0.03）时返回 '深灰' / '中灰' / '浅灰'（按明度）。

export function nameWithLevel(hex: string): string
// 色名 + 最接近的色阶级别，例如 '靛蓝 500'；灰阶返回 '浅灰 100' 这类。

export function mergeGeneratedPalette(
  existing: PaletteColor[],
```

## 三、`src/core/export.ts`（负责人：ui-core）

把项目的主题/色板/控件配色导出为前端可直接使用的代码。

```ts
import type { Project } from '../shared/types'

export type ExportFormat =
  | 'css'        // CSS 变量（含 :root 与 [data-theme="dark"]）
  | 'scss'       // SCSS 变量 + 映射
  | 'tailwind'   // Tailwind v3 配置对象（module.exports）
  | 'tailwind4'  // Tailwind v4 @theme 指令
  | 'tokens'     // W3C Design Tokens JSON
  | 'js'         // ES Module 常量对象
  | 'figma'      // 便于粘贴到 Figma 变量插件的 JSON（简单 key-value 颜色表）

export interface ExportOption {
  id: ExportFormat
  label: string        // 中文名称，如「CSS 变量」
  language: string     // 代码高亮语言：'css'|'scss'|'json'|'js'
  extension: string    // 建议文件名后缀：'css'|'scss'|'js'|'json'
  description: string  // 一句话说明
}

export const EXPORT_OPTIONS: ExportOption[]

export interface ExportOptions {
  mode: 'light' | 'dark' | 'both'   // 导出哪一套明暗
  includeScales: boolean            // 是否包含 50-950 色阶（默认 true）
  includePalette: boolean           // 是否包含项目色板（默认 false）
  includeControls: boolean          // 是否包含控件配色变量（默认 false）
  prefix: string                    // CSS 变量前缀，默认 'color'，例如 --color-primary
}

export const DEFAULT_EXPORT_OPTIONS: ExportOptions

export function exportProject(project: Project, format: ExportFormat, options?: Partial<ExportOptions>): string
```

输出要求：

- `css`：语义 token 输出为 `--{prefix}-{key}: ...;`；色阶输出为 `--{prefix}-primary-500: ...;`；
  浅色放 `:root { }`，深色放 `:root[data-theme="dark"] { }`（mode=both 时两者都输出，
  mode=light 只输出 :root，mode=dark 只输出深色块且选择器用 `:root`）。
  顶部加中文注释说明由「配色工坊」生成、项目名、主色。
- `scss`：`$color-primary: #...;`（前缀用 `$`）+ `$color-primary-500: ...;` + `$palette` / `$controls` 映射（如包含）。
- `tailwind`：`/** @type {import('tailwindcss').Config} */\nmodule.exports = { theme: { extend: { colors: { primary: { 50: '#...', ... }, ... } } } }`；
  语义 token 放在 `colors` 顶层键（如 `background: '#...'`）。
- `tailwind4`：`@import "tailwindcss";\n\n@theme {\n  --color-primary-500: #...;\n ... }`。
- `tokens`：W3C 格式，形如 `{ "color": { "primary": { "500": { "$value": "#...", "$type": "color" } } } }`，
  JSON.stringify(data, null, 2)。
- `js`：`export const colors = { primary: { 500: '#...' }, ... } as const`（含注释）。
- `figma`：`{ "颜色/主色/500": "#..." }` 简单 JSON。
- 控件配色包含时：`--{prefix}-control-button-bg: #...;`，需要根据 project.controlStyles 解析
  （用 `src/core/resolve.ts` 的 `resolveColorRef`，传入 project.palette / project.theme / mode），
  控件/属性中文名作为注释。
- 项目没有 theme 时（project.theme === null）：只导出项目色板（palette），并在头部注释说明未生成主题。
