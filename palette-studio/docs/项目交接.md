## 1. 项目概述与当前状态

### 1.1 产品定位

「配色工坊」是一个 Windows 桌面端的前端配色管理工具，面向做前端页面/设计系统的开发者。核心流程：

```
选择项目 → 输入品牌主色 → 8 种方式生成配色 / 生成明暗色阶 / 生成语义主题
        → 管理色板（锁定/改名/删除）→ 给 24 种控件逐个属性绑定颜色
        → 对比度检查 → 导出 7 种前端代码格式 → 保存快照随时回滚
```

### 1.2 功能清单（均已实现）

| 模块 | 能力 |
| --- | --- |
| 多项目管理 | 项目总览/搜索/新建/编辑/复制/删除；每项目独立主色、色板、主题、控件配色、快照 |
| 色板生成 | 8 种和谐配色（互补/相邻/三角/分裂互补/四角/单色明暗/暗调/亮调）、一键推荐 17 色色板、中文色名、颜色锁定/改名/删除/添加、50–950 明暗色阶 |
| 语义主题 | 主色 → 18 个语义 Token（浅色/深色两套）+ 8 组色阶；5 种生成方式（均衡/鲜艳/柔和/中性/高对比）；自动保证对比度；**界面预览**（桌面端/手机端双形态，内嵌 + 右侧停靠放大 + 独立窗口实时同步） |
| 控件配色 | 24 种控件、77 个属性，绑定主题 Token / 项目色板 / 自定义色；24 套真实控件实时预览；单控件/全部重置 |
| 对比度检查 | WCAG 2.1 AA/AAA 判定、文本三档字号示例、项目常用组合体检、不达标时沿 OKLCH 明度搜索建议色 |
| 导出 | 7 种格式：CSS 变量 / SCSS / Tailwind v3 / Tailwind v4 / W3C Design Tokens / ES Module / Figma 变量；明暗/色阶/色板/控件/前缀可选；复制或保存文件 |
| 记录 | 快照保存/恢复/重命名/删除（最多 60 条），重新生成主题前可自动快照 |
| 应用体验 | 深/浅主题、强调色随项目主色变化、无边框窗口、窗口尺寸记忆、自动保存、Toast、错误边界、键盘快捷键 |
| 颜色输入 | 自研紧凑取色器：面板/全彩/色块三模式（面板 = SV + 色相条微调；全彩 = OKLCH 全色域图（横向色相 × 纵向感知明度，逐像素取 sRGB 最高色度）；色块 = 12×5 色相明度网格 + 灰阶，单击即选）、tab 上方 pin 设默认取色方式（被 pin 的 tab 未选中时常显淡化 pin；首次使用默认全彩、应用方式默认确认后）、「当前颜色 → 初始颜色（色块+色值）→ 恢复按钮 → 吸管」标题区顺序（两处色块均 24px、色值均 11.5px；恢复按钮紧挨初始颜色右侧，未改动置灰、改动后点亮；固定占位不改变面板尺寸）、强调色锁定（取色器控件不随编辑颜色变色）、应用方式（立即同步 / 确认后同步，面板内记忆；首次默认确认后）、透明度滑条、HEX/RGBA 输入、OKLCH 读数、常用/中性/最近单行色板、屏幕吸管；颜色支持 `#RRGGBBAA` 透明度。完整设计与实现见 [取色器说明](./取色器说明.md) |

## 2. 快速开始

### 2.1 环境要求

- Windows 10/11 x64
- Node.js 22+（验证于 v22.22.0）、npm 11+
- PowerShell 5.1 或 pwsh 7
- .NET Framework 4.x（系统自带 `csc.exe`，用于编译启动器）
- Python 3 + Pillow + numpy（仅重新生成图标时需要）

### 2.2 从零构建（开发目录通常已带 `node_modules/` 与 `runtime/`；仓库不提交这两者）

```powershell
# 1) 安装依赖（受限环境必须加这两个参数，见 docs/开发说明.md 第 2 节）
npm install --ignore-scripts --cache .npm-cache

# 2) 类型检查 → 单测 → 构建 → 渲染冒烟
npm run check

# 3) 开发运行（构建 + 启动 Electron）
powershell -File scripts/dev.ps1
```

> 本仓库只提交源码与文档：`node_modules/`、`runtime/`、`release/`、`dist/`、`.build/` 等均为本地忽略产物，从远程克隆后需按本节自行准备。
> `runtime/` 是 Electron 运行时目录；如果缺失，需要放入 Electron 44.x win32-x64 发行包，并将 `electron.exe` 改名为 `runtime/PaletteStudio.exe`（保留 `resources/default_app.asar`）。
> `node_modules/electron` 只用于读取版本号；没有二进制不影响构建。

### 2.3 打包交付

```powershell
# 完整打包（构建 + 图标 + 启动器 + app.asar + rcedit + 快捷方式 + zip）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package.ps1

# 跳过渲染构建（渲染代码没变时）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package.ps1 -SkipBuild

# 只打包不压缩
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package.ps1 -SkipBuild -NoZip
```

产物：

```
release/
├─ PaletteStudio/                     ← 便携版程序目录
│  ├─ PaletteStudio.exe               ← 启动器（双击这个，约 95KB）
│  ├─ PaletteStudioCore.exe           ← Electron 主体（约 246MB）
│  ├─ resources/app.asar              ← 应用代码（dist + electron 主进程）
│  ├─ locales/ *.dll *.pak *.dat …    ← Electron 运行时文件
│  ├─ 配色工坊.lnk                    ← 指向启动器的快捷方式
│  ├─ 启动（兼容模式）.cmd            ← 直接用主体 + 兼容参数启动（排查用）
│  ├─ 创建桌面快捷方式.cmd / .ps1     ← 一键创建桌面快捷方式
│  └─ 使用说明.txt
└─ 配色工坊-1.0.0-win64.zip           ← 便携压缩包（约 156MB）
```

### 3.2 数据流

- **读**：`AppProvider` 启动 → `window.desktop.loadState()`（无 Electron 时 localStorage）→ `normalizeAppData()` 容错补齐 → reducer 初始化。
- **改**：视图调用 `useApp().actions.xxx` → dispatch action → reducer 不可变更新 → 组件重渲染 → 防抖 500ms 自动保存（`saveState` IPC）。
- **写**：主进程先备份旧文件为 `palette-studio.backup.json`，再写临时文件并原子 rename。读取失败时自动尝试备份。
- **主题色注入**：`App.tsx` 监听当前项目 `baseColor`，写入 CSS 变量 `--accent` 与 `--accent-text`（配合 `color-mix` 生成 hover/soft 变体），整个界面强调色随项目变化。
- **应用明暗主题**：`html[data-app-theme]` 切换 `global.css` 中的 CSS 变量组。

### 3.3 设计原则

1. `core/` 全部为纯函数，不依赖 React/DOM/Node，便于单测与复用。
2. 颜色统一用大写 `#RRGGBB` 字符串；解析/校验用 `core/color.ts`。
3. 语义主题与控件配色解耦：控件属性绑定 `ColorRef`（token/色板/自定义），主题重新生成不影响绑定有效性。
4. UI 只消费设计系统 CSS 变量，深/浅主题自动适配。
5. 数据模型向后兼容：`AppData.version` + `normalizeAppData` 迁移。

## 5. 数据模型与持久化

### 5.1 类型定义（`src/shared/types.ts` 摘要）

```ts
ColorFormat = 'hex' | 'rgb' | 'hsl' | 'oklch'
// 颜色字符串：不透明 #RRGGBB，带透明度 #RRGGBBAA（parseColorAlpha / normalizeColor 解析，见 6.1）

PaletteColor {
  id: string; name: string; hex: string;
  note?: string; locked?: boolean;
  source?: 'manual' | 'harmony' | 'scale' | 'theme' | 'imported'
}

ThemeToken { key: string; label: string; light: string; dark: string; description: string }
ThemeScale { key: string; label: string; light: Record<string,string>; dark: Record<string,string> }

GeneratedTheme {
  baseColor: string; method: ThemeMethodId;   // balanced|vivid|muted|neutral|high-contrast
  tokens: ThemeToken[];                        // 18 个，key 见 THEME_TOKEN_KEYS
  scales: ThemeScale[];                        // 8 个：primary/secondary/accent/neutral/success/warning/error/info
  createdAt: number
}

ColorRef =
  | { kind: 'hex'; value: string }              // 自定义颜色
  | { kind: 'palette'; id: string }             // 引用项目色板
  | { kind: 'token'; key: string }              // 引用主题 token（自动取当前 mode 的 light/dark）

ControlStyles = Record<controlId, Record<partId, ColorRef | undefined>>

Snapshot {
  id; label; createdAt; baseColor; palette; theme; controlStyles
}

Project {
  id; name; description; baseColor;      // baseColor 为品牌主色
  palette: PaletteColor[];
  theme: GeneratedTheme | null;
  controlStyles: ControlStyles;
  snapshots: Snapshot[];
  createdAt; updatedAt
}

AppSettings {
  theme: 'dark' | 'light';       // 应用界面主题
  colorFormat: ColorFormat;      // 复制颜色的格式
  previewMode: 'light' | 'dark'; // 工作台预览的明暗模式
  previewDevice: 'desktop' | 'mobile'; // 界面预览的设备形态
  autoSnapshot: boolean;         // 重新生成主题前自动快照
  sidebarCollapsed: boolean
}

// 主窗口 → 独立预览窗口的同步载荷（不做持久化）
PreviewPayload {
  project: Project | null;
  mode: 'light' | 'dark';
  device: 'desktop' | 'mobile';
  appTheme: 'dark' | 'light'
}

AppData { version: number; projects: Project[]; activeProjectId: string | null; settings: AppSettings }
```

> 数据版本 `CURRENT_DATA_VERSION = 2`：由颜色字符串扩展支持 `#RRGGBBAA` 引入；旧数据（仅 6 位 HEX）无需迁移，`normalizeAppData` 直接兼容。

### 5.2 持久化

- 位置：`app.getPath('userData')/data/palette-studio.json`
  - 正常环境：`%APPDATA%\PaletteStudio\data\palette-studio.json`
  - 受限环境（`%APPDATA%` 不可写时由启动器回退）：`<程序目录>\userdata\data\palette-studio.json`
  - 实际路径可在「设置 → 数据与存储」查看
- 备份：每次保存前把旧文件复制为 `palette-studio.backup.json`；读取失败时自动尝试备份。
- 原子写：先写 `palette-studio.json.tmp`，再 `rename`。
- 窗口状态：`userData/window-state.json`（位置/尺寸/最大化，多显示器下校验有效性）。
- 浏览器/无 Electron 环境：自动回退 `localStorage['palette-studio:data']`（便于纯前端调试）。
- 保存时机：数据变化后 500ms 防抖；首次加载完成强制保存一次（保证数据目录创建）；窗口关闭前 `beforeunload` 尽力保存。

### 5.3 迁移与容错

- 数据版本：`CURRENT_DATA_VERSION = 1`。
- `normalizeAppData(raw)`：项目数组缺失/字段缺失时补齐默认值，`activeProjectId` 失效时回退第一个项目，settings 合并默认值。
- 修改数据结构时：先改 `types.ts` → 修改 `defaults.ts`（默认值/迁移）→ 视需要递增 version → 在 store 的 action/reducer 中消费新字段 → 补 `normalizeAppData` 兼容逻辑（旧数据不能崩）。

### 5.4 项目生命周期

- 新建：`actions.createProject({name, description, baseColor})` → `createProject()` 自动 `suggestPalette(baseColor)` + `generateSemanticTheme(baseColor)` + `defaultControlStyles(theme)`。
- 复制：深拷贝项目，`name + ' 副本'`，快照重新生成 id。
- 删除：从列表移除；若删除的是当前项目，`activeProjectId` 回退第一个项目。
- 主题重新生成：`generateSemanticTheme(baseColor, method)` → `actions.setTheme`；若控件绑定为空会自动补默认绑定，已有绑定保持不变（token key 稳定）。
- 色板删除：会同步清理控件配色中指向该色板颜色的引用（`removePaletteRefs`）。

### 8.4 界面预览的三种形态与同步

| 形态 | 入口 | 说明 |
| --- | --- | --- |
| 内嵌面板 | 主题页「界面预览」面板 | `ThemePreview` 直接渲染，设备/明暗切换与设置联动 |
| 右侧停靠面板 | 主题页「放大预览」按钮、工作台顶部「界面预览」按钮（仅主题页显示） | `App.tsx` 渲染 `PreviewDrawer`：从标题栏下方展开（默认 760px、可拖拽调宽），`.app-body` 增加右侧 padding 让出空间（无遮罩、不遮挡），侧栏临时收起；Esc/关闭按钮收起 |
| 独立窗口 | 主题页或停靠面板里的「独立窗口」按钮 | 主进程 `createPreviewWindow()` 以 `?view=preview` 加载同一份 `dist/index.html`，渲染 `PreviewWindowPage` |

同步链路：
1. 主窗口 `App.tsx` 在 `activeProject / previewMode / previewDevice / theme` 变化时调用 `window.desktop.preview.update(payload)`；
2. 主进程缓存 `previewState` 并转发 `preview:state` 给预览窗口（窗口尚未打开则等 `did-finish-load` 后补发）；
3. 预览窗口切换明暗/设备 → `preview:set-mode` / `preview:set-device` → 主窗口 `updateSettings` → 新状态再推回预览窗口，形成双向同步；
4. 设备形态持久化在 `settings.previewDevice`，所以重新打开应用/独立窗口后保持一致；预览窗口的窗口尺寸不单独持久化（每次 1280×900）。

新增设备形态（如平板）时：`PreviewDevice` 联合类型 + `theme-preview.css` 增加对应预览布局 + `ThemePreview` 的 `device` 分支 + 两处 `DEVICE_OPTIONS`（ThemeView / PreviewDrawer / PreviewWindowPage 共用应抽取，当前为三处重复常量）。

## 9. Electron 主进程与启动器

### 9.1 窗口

- 无边框（`frame: false`），默认 1500×950，最小 1180×760；背景色 `#0b0d12`。
- 自定义标题栏（`TitleBar.tsx`，`-webkit-app-region: drag`；窗口按钮 `no-drag`）。
- 窗口尺寸/位置/最大化持久化到 `userData/window-state.json`（恢复前校验是否在可见显示器内）。
- 单实例锁：二次启动会聚焦已有窗口。
- 独立预览窗口：标准系统边框，默认 1280×900（最小 900×620），标题「配色工坊 · 界面预览」；与主窗口共享 preload 但加载 `?view=preview` 路由；主窗口关闭时自动关闭，避免应用残留。
- 阻止外部导航：`setWindowOpenHandler` + `will-navigate` 只允许本地 `file://`；`http(s)` 用系统浏览器打开。
- 渲染层安全：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`、preload 仅通过 `contextBridge` 暴露白名单 API。

| `--shots-dir=<dir>` | 自动点击遍历所有页面并逐页截图后退出（用于 UI 验收）；当前覆盖：项目总览 → 工作台 → 6 个标签页 → 设置页（浅/深）→ 新建项目弹窗 → 深色预览 → **停靠预览面板（桌面/手机）→ 独立预览窗口** |
| `--smoke-log=<file>` | 收集渲染进程 console、DOM 快照、渲染错误到文件 |

示例见 `docs/开发说明.md`「调试 Electron 应用」。

### 9.4 启动器（重要，不要随意改坏）

Windows 受限会话（远程桌面/企业管控/自动化运行器/沙箱宿主）中，Chromium 子进程沙箱可能无法初始化（错误码 `0xC0000003`），且 `%APPDATA%` 可能不可写（`Lock file can not be created 0x5`）。为此打包版采用「启动器 + 程序主体」：

- **`PaletteStudio.exe`**：`scripts/launcher.cs` 编译的 C# GUI 启动器（约 95KB，无控制台）。
  1. 清理 `ELECTRON_RUN_AS_NODE`/`ELECTRON_NO_ASAR`（宿主可能注入）；
  2. 选择用户数据目录：若程序目录已有 `userdata/` → 直接使用（保持一致性）；否则先尝试 `%APPDATA%\PaletteStudio`；若启动失败（7 秒内异常退出）→ 回退 `程序目录\userdata` 重试；
  3. 启动 `PaletteStudioCore.exe` 并附加 `--no-sandbox --disable-gpu-sandbox`（透传用户参数）；
  4. 主体异常退出时弹窗提示错误码，并写 `程序目录\启动日志.log`；
  5. 退出码 0 视为正常（支持 `--screenshot` 等一次性参数）。
- **`PaletteStudioCore.exe`**：真正的 Electron 主体（由运行时 `PaletteStudio.exe` 改名）。
- **`启动（兼容模式）.cmd`**：绕过启动器直接启动主体（排查启动器被安全软件拦截的情况）。
- **`配色工坊.lnk`**：指向启动器。
- 版本/图标：`rcedit` 同时写入启动器与主体（ProductName=配色工坊、FileVersion=package.json version）。

修改启动器流程：编辑 `scripts/launcher.cs` → 运行 `scripts/package.ps1`（会自动检测源码更新并重新编译）→ **必须实测**：无参数双击 `release/PaletteStudio/PaletteStudio.exe` 能打开窗口、数据能落盘。

### 9.5 打包产物结构（app.asar）

```
resources/app.asar
├─ package.json          { name, productName, version, description, main: 'electron/main.cjs' }
├─ electron/main.cjs、preload.cjs
├─ dist/                 index.html + assets/app.js + 各 CSS
└─ build/icon.ico        窗口图标
```

## 10. 构建 / 测试 / 打包流水线

### 10.1 为什么是纯 JS 构建链

项目初始环境（DSH Agent 沙箱）禁止 Node 子进程管道，`npm install` 的 postinstall 与 Vite/esbuild 的原生二进制/子进程都会失败。因此构建链刻意选择：

- **TypeScript 编译**：`ts.createProgram()` + `emit()`，输出 CommonJS 到 `.build/app/`（无 `tsc` 子进程）；
- **打包**：Rollup（纯 JS）+ node-resolve + commonjs 插件，输出单文件 IIFE；
- **压缩**：Terser（纯 JS）；
- **CSS**：不需要打包——`build.mjs` 自动收集 `src/**/*.css`，按相对路径复制到 `dist/` 并注入 `index.html`；
- **测试**：自研 testkit + 直接 `require` 编译后的测试文件；
- **渲染冒烟**：jsdom 里 `eval` 打包产物，不启动 Electron。

### 10.2 `scripts/build.mjs` 步骤

1. 清理 `.build/app` 与 `dist/`；
2. 编程式 TypeScript 编译（类型错误会导致构建失败）；
3. Rollup 打包 `.build/app/main.js` → `dist/assets/app.js`（IIFE）；
4. Terser 压缩（当前约 846KB，压缩前约 2.4MB）；
5. 收集 `src/**/*.css` → 复制到 `dist/<相对路径>`；`global.css` 排最前；
6. 读取 `src/index.html`，替换 `<!-- STYLES -->`（注入所有 `<link>`）与 `<!-- APP -->`（注入 `<script src="./assets/app.js">`）→ 写 `dist/index.html`。

### 10.3 `src/index.html` 注意事项

- CSP 未启用（`file://` 本地应用，且渲染层无 Node 权限）；请勿加载远程资源。
- 含 `window.process` / `window.global` 垫片（React CJS 依赖需要）。
- 含 `window.__ERRORS__` 运行时错误收集（供自动截图/冒烟读取）。

### 10.4 测试体系

- `src/core/_testkit.ts`：`test(name, fn)`、`describe(group, fn)`、`expect(actual).toBe/toEqual/toBeCloseTo/toContain/toMatch/toThrow/...`；**没有 `.not`**。
- `scripts/test.mjs`：编译到 `.build/test-app-<pid>/`（避免并发冲突）→ 递归找 `*.test.js` → `require` 注册 → 逐个执行 → 输出 `131/131 通过 ✓`。
- 当前用例分布：`color.test.ts`（30）、`palette.test.ts`（49）、`controls.test.ts`（12）、`export.test.ts`（40）= 131。
- 改核心行为时优先补测试；测试文件与源码同目录、命名 `*.test.ts`。

### 10.5 渲染冒烟（`dom-smoke.mjs`）

- 用 jsdom 执行 `dist/assets/app.js`（需先 build）；
- 依次检查：项目总览 → 打开项目 → 6 个标签页 → 设置页，共 9 个快照；
- 判定：root 内容非空 + 无 `window.__ERRORS__` 错误 + 无 jsdomError；失败退出码 1；
- 输出每页字符数与文本摘要，可加 `--verbose` 查看 console、`--json` 输出机器可读结果。
- 局限：jsdom 不做真实布局/视觉，视觉验收仍要靠 Electron 截图。

### 10.6 打包流水线（`scripts/package.ps1`，7 步）

1. （可选）`node scripts/build.mjs` 构建渲染进程；
2. 若无 `build/icon.ico`，用 `python scripts/make-icon.py` 生成图标；
3. 启动器源码比产物新时用系统 `csc.exe` 编译 `build/PaletteStudioLauncher.exe`；
4. `node scripts/package.mjs`：生成 app.asar（stage `.build/stage-app`）、复制 `runtime/`（主体改名 `PaletteStudioCore.exe`）、放启动器为 `PaletteStudio.exe`、生成使用说明与 cmd 文件；
5. `rcedit` 给启动器与主体写图标 + 版本信息；
6. PowerShell COM（`WScript.Shell`）创建 `配色工坊.lnk`；
7. `Compress-Archive` 生成 `release/配色工坊-<version>-win64.zip`。

注意：
- `package.mjs` 全部用 Node `fs` 完成（不启动子进程）；`package.ps1` 负责调用 `csc.exe`/`rcedit.exe`（PowerShell 直接执行外部程序是允许的）。
- 打包前请确认 `dist/` 是最新的（`-SkipBuild` 时尤其注意）。
- zip 中**不应包含** `userdata/` 与 `启动日志.log`（测试后清理再压缩，脚本自身不会生成它们）。

### 10.7 图标

- `scripts/make-icon.py`（Pillow + numpy）：渐变圆角底 + 白色调色盘 + 四色点，输出 `build/icon.png`（1024）与 `build/icon.ico`（16/24/32/48/64/128/256）。
- 仅当设计变更时需要重跑；`package.ps1` 会自动检测 `build/icon.ico` 是否存在。

## 12. 已知限制、技术债与路线图

### 12.1 已知限制（当前设计取舍）

| 项 | 说明 |
| --- | --- |
| 启动器强制 `--no-sandbox` | 为兼容受限 Windows 会话；应用只加载本地内容、禁止外部导航，风险可控。不要随意改回，否则部分用户无法启动 |
| 受限环境首次启动多一次尝试 | 先试 `%APPDATA%`（约 1–3 秒失败）再回退便携目录；之后启动直接使用便携目录 |
| 数据目录可能有两个 | 正常环境在 `%APPDATA%`，受限环境在程序目录 `userdata/`；迁移时请用「设置 → 导出/导入数据」 |
| 主题 Token 不可单独编辑 | 只能整主题重新生成；需要单 token 微调需扩展 `GeneratedTheme`（见路线图） |
| 快照上限 60 条 | 超出后保留最新 60 条 |
| 无撤销/重做 | 目前依赖快照做版本回退 |
| 透明度支持范围 | 色板、控件自定义色、取色器/输入支持 `#RRGGBBAA`；自动生成的主题 Token 与色阶仍为不透明色（生成算法基于 OKLCH 实色） |
| 仅中文界面 | 无 i18n 框架 |
| 便携版无安装/自动更新 | 通过 zip + 快捷方式分发 |
| 无前端工程导入 | 不能直接解析现有 CSS/Tailwind 配置 |
| UI 自动化覆盖有限 | 核心有单测；视图靠 dom-smoke + 截图人工验收 |
| PaletteView 色阶为自绘 11 档网格 | 契约原本建议复用 `ScaleStrip`，为支持「每档加入色板」改为自绘；ThemeView 仍用 `ScaleStrip` |
| 代码预览固定深色 | ExportView 刻意保持代码编辑器风格，不随应用浅色主题变化 |
| 主进程含验收参数 | `--screenshot/--shots-dir/--smoke-log` 保留在发布版中，便于后续验收；不涉及远程能力 |
| 预览窗口尺寸不持久化 | 独立预览窗口固定 1280×900，不保存位置/最大化；可后续复用 `window-state.json` 的模式 |
| 仅桌面/手机两种预览形态 | 平板/超宽屏等需扩展 `PreviewDevice` 与预览布局 |
| 界面预览只反映主题 token | 不渲染控件配色的真实控件组合；预览内容写死在 `ThemePreview.tsx` |

### 12.2 技术债 / 可改进

- 核心单测覆盖较好，但 store/reducer、视图交互缺少自动化测试（可引入轻量 React 测试或扩展 jsdom 交互断言）。
- `ControlsView.tsx` 约 1500 行、`controls.css` 约 1600 行，后续可拆分控件预览为独立文件（`views/control-previews/*`）。
- 导出代码生成用字符串拼接，格式多时可考虑按格式拆分模块（`core/export/*.ts`）。
- Dialog/弹窗的焦点管理（focus trap）尚未实现。
- 无骨架屏/加载态（本地应用加载很快，影响小）。
- `main.cjs` 中验收参数的日志/截图逻辑可考虑 DEV 开关，但目前保留利大于弊。

### 12.3 路线图（建议顺序）

1. 主题 Token 手动微调（`GeneratedTheme.overrides` + 迁移 + ThemeView 编辑）；
2. 从 CSS 变量 / Tailwind 配置导入色板；
3. 色盲模拟预览（OKLab 变换矩阵）；
4. 撤销/重做；
5. 更多导出格式（UnoCSS、CSS-in-JS、Ant Design/Chakra 主题变量）；
6. 自定义控件定义；
7. NSIS 安装包与自动更新；
8. 国际化。

- [ ] 色名：纯黑显示「黑色」、纯白显示「白色」，不再归到深灰/浅灰。
- [ ] 全彩上下边缘：最底行取色应为 #000000、最顶行应为 #FFFFFF（脚本验收 `bottomAllBlack=true` / `topAllWhite=true`）；不透明色块不应出现透明度棋盘格。
- [ ] 颜色小窗：点取色器左上角当前颜色块，浮层小弹窗展开/收起——外壳背景与取色器弹窗一致（`sameBg=true`，取 `--bg-elevated`，随主题变化）、顶部与取色器对齐（`alignTop=true`）、内部 132×132 方形色块（`swatchSquare=true`）显示中文色名 + HEX；验收 `leftOfPopover=true`、`heightStable=true`、`name` 非空、`hex` 与当前色一致，再点 `visibleAfterClick=false`（左侧空间不足时应回退到右侧）。

- [ ] 全彩光标：真实鼠标从面板底部拖到顶部，圆形光标与指针偏差应接近 0（脚本验收 `maxDevPx=0.0`），且完整可见不被面板裁剪（`allInside=true`）；圆圈露在面板外侧时按住也能拖动（`outsidePanel=true`、偏差≈0）；点「恢复」后光标应回到初始颜色位置（`backToInitial=true`）；
- [ ] 「恢复」按钮：打开时记住带入颜色；标题区顺序为「当前颜色 → 初始颜色（色块+色值）→ 恢复按钮 → 吸管」，恢复按钮紧挨初始颜色右侧、固定占位；未改动置灰、改动后点亮，点击回到最初颜色（立即模式外部同步恢复、确认模式只恢复内部），恢复后再次置灰，面板高度不变；
- [ ] 强调色锁定：编辑颜色（尤其是项目主色，全局 --accent 会变）时，取色器内 pin/当前 tab/初始颜色区域颜色保持不变；

## 15. 交接注意事项

1. **先跑验证再改代码**：确认当前基线全绿，避免把环境问题当成代码问题。
2. **环境差异**：`npm install` 必须 `--ignore-scripts --cache .npm-cache`；Electron 只能用 `runtime/`；受限沙箱下 Electron 需要完全权限或使用打包版。
3. **不要提交/打包**：`node_modules/`、`runtime/`、`dist/`、`.build/`、`release/`、`.npm-cache`、`.shots/`、`.electron-userdata/`（`.gitignore` 已覆盖）。
4. **数据安全**：应用数据在本机；改动数据模型务必保证旧数据可被 `normalizeAppData` 兼容。
5. **不要随手"优化"掉**：纯 JS 构建链、`--ignore-scripts`、启动器方案、`.ps1` 的 BOM、颜色大写 HEX 约定——这些都有明确原因，见 docs/开发说明.md 第 2、8 节。
6. **不要在工作区外创建任何文件/目录**：临时截图、诊断输出、演练数据一律放项目目录内（`.shots/`、`.diagnostics/`、`.tmp-*`）并在完成后清理。用户明确要求过这一点。
7. **新增功能时同步文档**：至少更新 `README.md`（用户能力）、`docs/更新日志.md`（变更），必要时更新本文件对应章节。
8. 有疑问先搜代码与文档中的关键词（`resolveColorRef`、`normalizeHex`、`generateSemanticTheme`、`defaultControlStyles`、`exportProject`、`PreviewPayload`、`preview:update`），架构都围绕这几个入口组织。
