# X 媒体工坊 · 开发说明

## 1. 技术栈

- 桌面壳：Electron 44.x（win32-x64），免安装便携目录；主进程 CommonJS（`electron/*.cjs`）；
- 界面：React 19 + TypeScript 5（严格模式）+ 自研状态管理，Rollup 打包 + Terser 压缩；
- 主进程能力：`electron/lib/` 下的纯 Node 模块（推文接口、MP4/GIF 纯 JS 解析、媒体下载与**原始媒体保存**、GIF 转换流水线、历史与设置）；
- 外部工具：`ffmpeg.exe`（解码/缩放/抽帧/缩略图）、`gifski.exe`（GIF 编码）、`gifsicle.exe`（体积优化），开发态在 `tools/bin/`，打包态在 `<resources>/tools/`。

## 2. 目录与源码入口

| 路径 | 说明 |
| --- | --- |
| `electron/main.cjs` | 窗口、IPC、`xgif://` 本地文件协议、任务进度转发、`--smoke-report`/`--screenshot` 自检 |
| `electron/preload.cjs` | `contextBridge` 暴露 `window.desktop`（类型见 `src/shared/types.ts#DesktopApi`） |
| `electron/lib/tweet.cjs` | X 链接解析、公开接口抓取（fxtwitter → syndication → vxtwitter 回退）、media 归一化；网络请求走 network.fetch |
| `electron/lib/network.cjs` | 统一 fetch：Electron `net.fetch`（走 session 代理）/ 纯 Node 退化全局 fetch |
| `electron/lib/proxy.cjs` | 代理解析、session.setProxy 应用、代理认证凭据、密码加密、X 接口与媒体 CDN 连通性测试 |
| `electron/lib/mp4probe.cjs` | 纯 JS 解析 MP4 `stts` 等 box，得到逐帧时长（GIF 时序还原的依据） |
| `electron/lib/gifprobe.cjs` | 纯 JS 解析 GIF，读/写逐帧延时与循环信息 |
| `electron/lib/media.cjs` | 媒体下载、缓存、探测、缩略图、**保存原始媒体**（mp4/图片，图片按魔数识别格式并解析宽高） |
| `electron/lib/gif.cjs` | GIF 转换流水线（见技术方案文档；`autoSave` 时先自动保存源媒体） |
| `electron/lib/history.cjs` / `settings.cjs` | 本机 JSON 持久化（原子写入 + `.bak`）；history entry 含 `savedMedia`（已保存媒体）与 `results`（GIF 结果） |
| `src/shared/` | 前后端共享契约：类型、预设、桌面 API 声明（**只读契约**） |
| `src/core/` | 纯函数与单元测试（格式化、参数校验、历史过滤） |
| `src/views/`、`src/components/`、`src/state/`、`src/styles/` | 界面 |
| `scripts/` | 构建、类型检查、单元测试、冒烟、工具下载、打包、启动器 |
| `docs/` | 文档 |

## 3. 开发与构建

```powershell
cd x-gif-studio
npm install                     # 安装依赖（受限环境：npm install --ignore-scripts --cache .npm-cache）
npm run fetch-tools             # 下载 ffmpeg/gifski/gifsicle 到 tools/bin
npm run typecheck               # TS 严格模式检查
npm run test                    # src/core 单元测试 + tests/ 主进程引擎测试
npm run build                   # 渲染进程产物 dist/
npm run smoke                   # jsdom 渲染冒烟
npm run check                   # 以上全部
npm start                       # 构建并启动 Electron
```

Electron 运行时准备（不入库）：把 Electron win32-x64 发行版的运行时文件放到 `runtime/`（可来自同仓库 palette-studio 的 `runtime/` 目录，或自行从 Electron 官方发行版解压后放入，保证目录内有 `*.exe`、`resources/`、`*.pak`、`*.dll` 等文件）。

## 4. 打包

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package.ps1 [-SkipBuild] [-NoZip] [-SkipSmoke]
```

输出 `release/XMediaStudio/`：`XMediaStudio.exe`（小启动器，处理受限会话参数与数据目录回退）→ `XMediaStudioCore.exe`（Electron 主体）→ `resources/app.asar`（`dist/` + `electron/`）→ `resources/tools/`（三个 exe）。同时生成 `THIRD-PARTY-LICENSES.txt`、`使用说明.txt`、兼容模式启动脚本、桌面快捷方式脚本和 zip。

## 5. 验证方法

- 静态：`npm run typecheck`；
- 单元/集成：`npm run test`（主进程测试使用 `XGIF_DATA_DIR` 指向临时目录，不污染用户数据；内部用 ffmpeg 现场生成 VFR 夹具，网络用例自动跳过）；
- 渲染冒烟：`npm run smoke`（jsdom + 假 `window.desktop`，覆盖主界面、导航切换、无桥接降级）；
- 主进程冒烟（需网络与 tools）：`runtime/*.exe . --no-sandbox --smoke-report <json> [--smoke-url <推文链接>]`，报告内含工具状态、推文解析、媒体下载探测、**媒体保存（media:save / save 步骤）**、GIF 转换结果；
- 截图验证：`runtime/*.exe . --no-sandbox --screenshot <png> [--screenshot-view parse|history|settings] [--screenshot-eval <js文件>]`；
- 打包后验证：`release/XMediaStudio/XMediaStudioCore.exe --no-sandbox --smoke-report <json> --xgif-user-data=<临时目录>`，以及 `XMediaStudio.exe` 双击启动；
- 人工验收：真实推文 → 勾选媒体 → **保存所选** → 查看已保存媒体 → 右键/转换所选导出 GIF → 查看尺寸/体积 → 改参数重新导出 → 历史按推文链接统计 → 打开/定位/另存为。

## 6. 已确认的技术约束

- 渲染进程无 Node 权限，所有文件/网络操作走 IPC；本地文件预览统一使用 `xgif://display/?path=...` 协议，主进程校验路径必须位于应用数据目录内；
- 主进程不依赖 `ffprobe`：MP4 探测由纯 JS 实现，打包只带 `ffmpeg.exe`；
- 主进程所有出站请求必须走 `electron/lib/network.cjs`（Electron 下为 `net.fetch`），严禁直接用全局 fetch，否则不会经过 Chromium 的代理；
- 代理配置由 `electron/lib/proxy.cjs` 应用到 `session.defaultSession`：主进程请求与渲染进程加载的远程图片/缩略图共用同一代理；渲染进程请求的代理认证由 `app.on('login')`（`authInfo.isProxy`）回填凭据；**主进程 `net.fetch` 不会触发该事件**（Electron issue #44249），因此 `network.cjs` 在配置了代理凭据时自动改用 `net.request`（ClientRequest，其 `login` 事件可回填凭据），未配置认证时仍用 `net.fetch`；
- 代理密码不落盘明文：保存时用 `safeStorage` 加密为 `passwordEnc`；不可用时退化为 `plain:<base64>`（已在文档说明风险），换机器/换用户后需重新填写；
- 代理保存前先 `buildProxyConfig` 校验，非法地址返回 `PROXY_INVALID`；代理测试（`proxy:test`）内部「临时应用候选配置 → 测 X 接口与媒体 CDN → 恢复已保存配置」；
- 冒烟/联调可用 CLI 覆盖代理：`--proxy-mode=custom --proxy-url=http://127.0.0.1:7890 --proxy-auth-user=<user> --proxy-auth-pass=<pass>`（建议用等号形式；配合 `--xgif-user-data=<目录>` 指定数据目录）；不带认证时 `--proxy-mode=custom --proxy-url=<url>` 即可；
- GIF 的逐帧延时必须以源 MP4 的 `stts` 为准（`fps='source'` 模式），否则会出现「重复帧/丢帧/体积虚高」；
- gifsicle 的 `--colors` 会触发全局量化，是体积下降的主要手段，但会损失少量颜色精度，只在用户开启优化时使用；
- 历史与设置采用「旧文件备份 .bak + 临时文件 + rename」的原子写入；
- **媒体保存**：视频/GIF 复用 `media.prepare` 得到 mp4 缓存后复制到输出目录；图片（pbs 原图）经 `network.fetch` 下载（60s 超时、单张 50MB 上限），按魔数识别 JPEG/PNG/GIF/WebP 并解析宽高；保存采用临时文件 + 原子 rename；
- **保存 id 与去重**：`SavedMedia.id = tweetId:mediaId:format`；history 中已有记录且文件存在时直接返回（幂等），`force=true` 才覆盖；文件名 `<作者>_<推文id>_<媒体序号>_<宽>x<高>.<ext>` 由推文/媒体决定，重复保存不会误覆盖其他媒体；
- **自动保存**：`gif:convert` 的 `autoSave=true` 时，若源媒体未保存则先执行保存流水线，再转 GIF，结果带 `sourceSaved`；
- **数据目录改名**：应用存储名 `XMediaStudio`；启动时若旧 `%APPDATA%\XGifStudio` 存在且新目录无 `settings.json`/`history.json`，自动复制迁移（不迁移大缓存；历史中的绝对文件路径仍指向旧目录，文件保留可访问）；
- **主题**：`settings.theme`（dark/light/system）→ 渲染进程写 `document.documentElement.dataset.theme`；主进程按保存的主题设置窗口初始背景色，减少启动闪烁。

## 7. 已知问题与待办

- 大体积 GIF（>20MB）在界面内预览可能卡顿，暂未做缩略预览；
- X 接口为公开第三方服务（fxtwitter / syndication），稳定性依赖其可用性；`vxtwitter` 回退因 Cloudflare 403 未能真实验证（代码已实现）；
- `mp4probe` 的 ffprobe/ffmpeg 文本回退路径未在真实损坏文件上触发验证（主路径已充分测试）；
- 缩略图取视频首帧，首帧全黑的素材会偏暗（后续可优先使用接口返回的 poster 图）；
- 打包产物体积较大（Electron 运行时 + ffmpeg 约 400MB 解压后），后续可评估更小的 ffmpeg 构建或可选系统 ffmpeg；
- 开发态用「改名后的 runtime exe + 项目目录」启动时 `app.isPackaged` 可能为 true，`paths.toolsDir()` 已按目录存在性兜底；打包态行为不受影响；
- 旧版数据目录迁移只复制 `settings.json`/`history.json`；旧输出目录（`%APPDATA%\XGifStudio\gifs`）中的文件不会被搬移，历史里的绝对路径仍可打开；
- 图片保存支持 JPEG/PNG/GIF/WebP；X 的 pbs 原图通常是 jpg，其他格式按魔数识别后保存；
- 轻量体积预设下 gifski 可能合并重复帧，已实现「编码后按实际帧数归一延时」自动回退（详见 `GIF转换技术方案.md` §5.9），严格逐帧请用最高画质预设。
