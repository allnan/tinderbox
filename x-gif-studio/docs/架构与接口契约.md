# X 媒体工坊 · 架构与接口契约

本文档是主进程（`electron/`）与渲染进程（`src/`）共同的开发契约。**先改契约、再改实现**；两侧字段、IPC 名称、阶段枚举必须与本文一致。

## 1. 目标与边界

- 输入一条公开的 X（Twitter）推文链接，不需要登录；
- **主流程：解析并保存原始媒体**（推文 GIF 为 mp4、视频为 mp4、图片为 jpg/png/webp），用户选择要保存的媒体并写入输出目录；
- **可选 GIF 导出**：对已保存（或右键转换时自动保存）的 mp4/动图媒体，使用「专用还原流水线」导出 GIF（详见 `docs/GIF转换技术方案.md`），并显示尺寸、大小、帧数、时长；
- 生成后可快速改参数重新导出；保存的媒体与 GIF 文件可直接打开、定位、另存为；
- 以 X 链接为分组维护历史（推文条数 / 媒体数 / GIF 数分别统计）；
- 交付 Windows 免安装 exe（Electron 便携目录），不启动任何本地 Web 服务。

非目标：批量时间线抓取、需要登录/受保护内容、上传回 X、网页版部署。

## 3. 技术栈与运行

- Electron（运行时 `runtime/`，由打包模板提供，44.x win32-x64）+ React 19 + TypeScript 5 + Rollup；
- 主进程为 CommonJS（`.cjs`），渲染进程由 `scripts/build.mjs` 编译打包为 `dist/`；
- 网络：主进程统一使用 `electron/lib/network.cjs` 的 fetch（Electron 下为 `net.fetch`，走默认 session 的代理配置；纯 Node 测试退化为全局 fetch）；代理由 `electron/lib/proxy.cjs` 解析并应用到 `session.defaultSession`，同时覆盖主进程请求与渲染进程加载的远程图片/缩略图；
- 外部工具：`ffmpeg.exe`（解码/缩放/抽帧/缩略图）、`gifski.exe`（GIF 编码）、`gifsicle.exe`（GIF 体积优化）；
- 开发时工具位于 `tools/bin/`，打包后位于 `<resources>/tools/`；两者都找不到时回退系统 PATH；仍缺失则 `ToolStatus.ready=false`，界面必须给出明确提示；
- 打包：`pwsh -File scripts/package.ps1`，产物 `release/XMediaStudio/`，双击 `XMediaStudio.exe` 启动（启动器拉起 `XMediaStudioCore.exe`）。

## 4. 存储（全部在本机）

- 用户数据根：`app.getPath('userData')`，应用存储名为 `XMediaStudio`（旧版 `XGifStudio` 的 `settings.json`/`history.json` 在首次启动时自动迁移）；受限环境下由启动器回退到程序目录 `userdata/`；
- `history.json`：历史记录（按推文 id 分组），每条 entry 含 `savedMedia: SavedMedia[]`（已保存原始媒体）与 `results: GifResult[]`（GIF 导出结果），原子写入 + `.bak` 备份；旧版无 `savedMedia` 的 entry 读取时补空数组；
- `settings.json`：设置；
- `cache/media/<mediaId>.mp4`：原始媒体缓存；
- `cache/thumbs/<mediaId>.jpg`：缩略图；
- `cache/frames/<mediaId>-<hash>/`：抽帧临时目录（可随时清理）；
- `media/<screenName>/<tweetId>/`：默认输出目录（保存的 mp4/图片与导出的 GIF 同目录组织），用户可在设置中改；
- `logs/main.log`：主进程日志。

## 4.1 设置数据（AppSettings，新增 proxy）

```ts
type ProxyMode = 'system' | 'custom' | 'direct'
interface ThemeSettings {
  theme: 'dark' | 'light' | 'system'
}

interface ProxySettings {
  mode: ProxyMode          // 系统代理（默认）/ 自定义 / 直连
  url: string              // 自定义代理地址：http(s)://host:port、socks5://host:port，裸 host:port 按 http
  bypass: string           // 不走代理的主机，分号/逗号/空白分隔；始终追加 localhost;127.0.0.1;<local>
  username: string         // 可选，代理认证用户名
  password: string         // 可选，运行时明文；落盘时用 safeStorage 加密为 passwordEnc
}
```

- 新增 `theme: 'dark' | 'light' | 'system'`（默认 `dark`）：渲染进程据此设置 `document.documentElement.dataset.theme` 并适配浅色变量；`system` 模式跟随 `prefers-color-scheme`；保存后立即生效；
- 主进程创建窗口时读取已保存主题（system 用 `nativeTheme.shouldUseDarkColors`）设置窗口初始背景色，减少启动闪烁；
- `settings.json` 持久化格式中的 proxy 为 `{mode,url,bypass,username,passwordEnc}`，**不落盘明文密码**；
- `safeStorage` 不可用时退化为 `plain:<base64>`（文档说明风险）；
- 保存设置前用 `buildProxyConfig` 校验地址，非法时返回 `code='PROXY_INVALID'`；
- `outputDir`：保存的原始媒体与 GIF 的统一输出根目录，默认 `<userData>/media`；
- 应用时机：应用启动（读取设置）、settings:save 成功后、代理测试前（临时应用，测试结束恢复已保存配置）；
- 代理认证：主进程监听 `app.on('login')`，`authInfo.isProxy` 时使用缓存的用户名/密码回调；
- 冒烟/联调可用 CLI 覆盖（建议全部用等号形式，避免附加位置参数干扰 Electron 启动）：`--proxy-mode=custom --proxy-url=http://127.0.0.1:7890 --proxy-auth-user=demo --proxy-auth-pass=secret`。

### 5.1 任务进度

- 渲染进程生成 `jobId`（`crypto.randomUUID()`）并随请求传给主进程；主进程所有进度事件都带同一个 `jobId`；
- 阶段：`queued → download → probe → thumbnail → extract → encode → optimize → finalize → done`，失败为 `error`，取消为 `cancelled`；
- 任务 scope：`gif`（导出 GIF）/`media`（媒体准备）/`save`（保存原始媒体）；
- 同一时间最多允许 2 个并发转换任务；`jobs.cancel` 需要杀掉对应子进程（保存/下载使用 AbortController 取消）。

## 6.0 媒体保存流水线（新增主流程）

1. **保存视频/动图（kind=gif|video）**：复用 `media.prepare`（下载 mp4 + 纯 JS 探测），把 mp4 复制到输出目录；输出路径 `<outputDir>/<screenName>/<tweetId>/<screenName>_<tweetId>_<mediaIndex>_<宽>x<高>.mp4`；
2. **保存图片（kind=photo）**：`network.fetch` 下载原图（走代理，60s 超时、50MB 上限、content-length 进度），按魔数识别 JPEG/PNG/GIF/WebP 并解析宽高，写入 `.jpg/.png/.webp/.gif`（临时文件 + 原子 rename）；
3. **幂等与去重**：以 `tweetId + mediaId + format` 为稳定 id；`history.json` 已有记录且文件存在时直接返回（`newFile=false`），`force=true` 才重新覆盖；
4. **历史写入**：成功后 `history.recordSaved` 更新/新增 entry 的 `savedMedia`；
5. **自动保存**：`gif:convert` 传 `autoSave:true` 时，若源媒体尚无保存记录则先走保存流水线，再转 GIF，结果带 `sourceSaved`；
6. **命名冲突**：媒体文件按上述确定性命名；不同 `mediaIndex` 不会冲突；同一媒体重复保存覆盖自身，不误覆盖其他媒体。

## 6. 转换流水线（关键实现约束）

1. **媒体探测**：`mp4probe.cjs` 直接解析 MP4（`moov/trak/mdia/minf/stbl/stts、stsz、stsd、tkhd、mvhd`），得到宽高、帧数、逐帧时长毫秒；只在解析失败时才回退 `ffprobe`（若系统存在）或 `ffmpeg -i` 文本解析；
2. **专用还原模式（fps='source'，默认）**：抽取源视频**每一帧**（不做帧率重采样；ffmpeg 9 起用 `-fps_mode passthrough`，旧版本可用等价的 `-vsync 0`），编码完成后按 `stts` 还原每帧 GIF 延时（厘秒，最小 2cs），保证「不抽帧、不重复帧、播放节奏与源一致」；
3. **帧率模式（fps=数字）**：按目标帧率重采样后使用统一 1/fps 延时；
4. **gifski 编码**：PNG 帧目录 → `gifski -o out.gif --fps <nominal> --quality <Q> [--width W] [--fast] frames/*.png`；`nominal` 只影响初始时长，最终延时由第 2/3 步覆盖；数字帧率时延时按累计时间分配（如 15fps 用 6/7cs 交替），避免固定取整导致总时长漂移；
5. **ffmpeg 编码（备选）**：两遍法 `palettegen(stats_mode=diff,max_colors)\ paletteuse(dither,diff_mode=rectangle)`，输出后同样按时间戳校正延时；
6. **gifsicle 优化**：`optimize=true` 时执行 `gifsicle -O3 --lossy=<N> [--colors C] in.gif -o out.gif`；`lossy=0` 时不加该参数；`--colors` 仅在 `colors<256` 时添加；
7. **速度调整**：`speed` 作用于延时（`delay/speed`），不改变帧数与画面；
8. **循环**：`loopCount=0` 写 NETSCAPE2.0 无限循环；`>0` 写对应次数；`-1` 表示不循环（`gifski --repeat` 处理）；
9. 输出文件名：`<screenName>_<tweetId>_<media序号>_<宽>x<高>_<preset或custom>_<时间戳>.gif`，写入默认输出目录，同时写入历史。

## 6.1 代理与网络约束

1. 所有主进程出站请求必须使用 `network.fetch`，禁止直接使用全局 fetch（否则不会经过 Chromium 代理）；
2. 渲染进程加载远程缩略图/头像走默认 session，因此 session 上应用代理后自动生效，无需额外代码；
3. 代理解析只接受 http/https/socks5（裸 host:port 按 http）；白名单始终包含本机回环；
4. 代理测试使用 `proxy:test`，内部执行「临时应用候选配置 → 请求 X 解析接口与媒体 CDN → 恢复已保存配置」，渲染层只会看到逐项检查结果；
5. **主进程代理认证限制**：Electron 的 `net.fetch` 在主进程发请求时不会触发 `app.on('login')`（Electron issue #44249），因此配置了代理用户名/密码时，`network.cjs` 自动改用 `net.request`（ClientRequest）发请求——它支持 `login` 事件回填凭据；未配置认证时仍走 `net.fetch`。渲染进程请求（远程头像/缩略图）有 webContents，由 `app.on('login')` 正常处理；
6. 代理 `url` 中内嵌账号密码（`http://user:pass@host:port`）会被解析并作为认证凭据使用，也可在设置里分开填写。

## 7. 错误约定

- 网络/接口失败返回可直接展示的中文提示，例如「推文不存在或已被删除」「该推文没有可转换的媒体」；
- 工具缺失：`code='TOOLS_MISSING'`，message 里列出缺失工具与解决方式；
- 保存失败：`code='MEDIA_SAVE'`，message 为可展示中文提示（网络失败/图片过大/格式不支持等）；
- 转换失败：`code='CONVERT_FAILED'`，message 包含失败阶段与工具原始错误尾部（截断）；
- 取消：`code='CANCELLED'`；
- 代理配置非法/应用失败：`code='PROXY_INVALID'`，message 为可展示中文提示；
- 主进程不得把未捕获异常抛给渲染进程，统一 try/catch 包装。

## 8. 开发与验收

- `npm run typecheck`：渲染进程 TS 严格模式通过；
- `npm run test`：`src/core` 单元测试 + `tests/` 下 Node 测试全部通过；
- `npm run build`：生成 `dist/`；
- `npm run smoke`：渲染进程 DOM 冒烟（jsdom）；
- `powershell -File scripts/package.ps1`：生成 `release/XMediaStudio/` 并做打包后冒烟（`XMediaStudioCore.exe --smoke-report <json>`，需要网络与工具可用）；
- 关键人工验收：真实推文 → 媒体列表 → 保存原媒体 → 预览/尺寸/大小 → 右键转换为 GIF → 改参数再导出 → 历史分组（按推文链接统计）。

## 9. 并行开发约定

- 渲染进程只依赖 `src/shared/` 中的类型与 `window.desktop`，不得 require Electron / Node API；
- 主进程不 import 渲染进程代码；`electron/lib/` 中各模块导出纯函数/类，`main.cjs` 只做 IPC 适配；
- 修改共享契约必须同步更新本文件与 `src/shared/types.ts`，并通知另一侧；
- 每个任务的写入范围见团队任务板，禁止跨范围改文件。
